# 第 5 阶段：智能审批

目标：复用现有审批服务，支持常规 LLM、Jev 两种智能审核，在设置页全局切换。每次独立调用，不维护审核会话。

实施与验证事实统一见 `STATUS.md`。剩余验收：用户运行 `make run` 检查设置页和真实审批；继续用实际任务评估 Jev 门槛。后端初始门槛 0.8，仅用于保守转人工，不视为安全正确率保证。

## 设置与密钥

- 设置页选择审核方式；常规 LLM 复用已有模型清单与选择器，选择模型和思考档位。
- 审批服务持久化全局 `Engine / Model / ReasoningEffort`，每次审批开始取快照；切换不影响已开始的审核。
- **Jev 与 LLM 密钥共用 `~/.harness/config.yaml`**，Jev 使用独立配置项，不混入聊天模型目录；通过现有 persist 读取，密钥不返回前端。
- Jev 页面只显示是否配置；审批设置增加读取、保存接口，同步 Go / TS 契约。

## 给模型看什么

- 当前任务的真实用户要求、后续补充和限制；不使用执行模型自述代替用户授权。
- 完整命令或补丁、工作目录。
- 当前权限、本次额外申请及理由；理由明确标记为 Agent 的解释。
- 固定审核规则：是否符合用户意图、权限是否合理、是否有破坏或泄露风险。
- 后端按当前会话分支收集用户要求；子 Agent 保留来源用户授权，模型派发任务不能冒充用户原话。

## 流程

```text
设置页 → 后端保存全局审核设置
                    ↓
工具申请 → 审批服务 + 真实用户要求
             ├─ 人审批 → 等待用户
             └─ 智能审批
                  ├─ 常规 LLM → 现有 llm.Client
                  └─ Jev      → HTTP API
                            ↓
                  批准 / 拒绝 / 转人工
                            ↓
               批准 → 本次权限 → Linux / Mac 沙箱
```

## 实现方向

- 一套审批服务、两个模型适配；先在审批包内分文件，不增加插件或登记处。
- 常规 LLM 复用现有服务；Jev 使用 Go HTTP 调用。首版不增加调查工具、会话复用或增量历史。
- 两种适配统一为 `decision + reason`：批准、拒绝或转人工；审批服务完成转人工后，仍通过现有 Reviewer 契约返回最终批准或拒绝。
- 常规 LLM 生成理由；Jev 根据分类生成简短说明，不伪装成模型推理。Jev 仅对自动批准增加置信度门槛，低于门槛转人工；拒绝照常生效。阈值用补充案例确定，先放后端，不增加界面滑块。
- 调用失败、结果无法解析或必要上下文放不下时转人工；不能静默截掉授权限制。
- 用户停止直接取消，沿用现有等待、重连机制；待审批状态不写入对话账本。
- 批准只覆盖本次申请，仍由沙箱执行限制；配置可用后开放前端“智能审批”。

## 极简伪代码

```text
审核(ctx, 申请):
    设置 = 当前全局设置快照()
    结果, 错误 = 所选适配审核(ctx, 设置, 用户要求, 申请, 固定规则)
    如果用户已停止: 返回取消
    如果失败或结果要求转人工: 返回人工审核(ctx, 申请)
    如果 Jev 批准但置信度不足: 返回人工审核(ctx, 申请)
    返回批准或拒绝及理由
```

顺序：补齐用户授权上下文 → 两种审核适配与转人工 → 全局设置和页面。

核心测试：两种适配的批准/拒绝、失败与低置信度转人工、停止取消、设置快照与持久化、来源用户授权不被模型消息替代。MCP 执行边界另行核查；UI 由用户截图验收。
