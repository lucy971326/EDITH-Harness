# 架构精简方向书

## 目标

保持功能、稳定性和现有 UI，借鉴 Codex 的明确入口、显式依赖和状态归属，移除 Host 服务装配机制与 Product 层。

代码以简洁、清晰、容易顺着读为先；不照搬 Codex 的额外复杂度。

## 目标主干

```text
启动入口：创建依赖 → 接线 → 启动 → 关闭

UI → app-server → 会话操作 → Runner → Loop → Tools
          |
          +→ 模型 / Skills / MCP / 审批 / Hooks

状态归属：
进程 → 共享服务
会话 → 对话与运行配置
本轮 → 执行、取消与等待
步骤 → 本次使用的设置、工具与环境
```

app-server 负责协议与分发，核心负责业务协调。保留真正需要的扩展登记处，Go / TS 契约继续手写。

## 实现原则

- **依赖直接可见**：构造时传入，运行时直接调用；不再查询 Host，也不传万能服务容器。
- **字段尽可能少**：删除重复保存、无必要缓存和可低成本推导的状态；保留必要快照与恢复信息。
- **锁各有职责**：说明保护什么、作用范围多大；能随重复状态一起删除就删除，不能为了少字段合并无关锁或削弱并发保障。
- **不隐藏复杂度**：不用地图、嵌套结构或细碎对象把字段搬走来冒充精简。只有职责和生命周期确实独立时才拆分。
- **流程顺着读**：检查、执行、错误返回和收尾直接可见；仅为消除实质重复或分离完整职责提取方法。
- **资源归属明确**：创建者负责取消、关闭和等待；初始化失败清理已取得的资源，关闭失败继续清理其余资源并汇总错误。

## 改动顺序

1. **归拢会话操作，移除 Product**：保留创建、发送、插话、停止、分叉和设置规则；改为会话内协调，不让一个会话的准备过程挡住其他会话。Stop 独立执行。
2. **显式组装，移除 Host**：入口直接构造服务和登记扩展，接住原有启动失败清理与关闭责任；不保留兼容转发层。
3. **收敛运行与存储**：合并真正相同的收尾逻辑；普通运行取消保留未完成内容，压缩失败不提交半截摘要。领域负责自己的数据格式，保留可靠文件读写。
4. **整理前端内部状态**：统一订阅生命周期和草稿归属，整理文件保存与监听职责；UI 和交互保持原样。

## 验证与交付

每批保持可运行、可验证、可回退。开发阶段不做旧数据迁移或兼容；保留对外协议；同步更新架构规则与数据归属文档。

重点验证：

- 同会话操作有序，跨会话并行；准备期和子任务可以停止。
- 工具调用与结果配对，取消后不启动剩余工具。
- 结束事实先保存，再通知；资源收尾完成后才能开始下一轮。
- 初始化失败、关闭失败、写入失败及重启恢复。
- 订阅重连不漏事件；切换会话不丢草稿，迟到确认不清除新输入；文件冲突不覆盖修改。

优先复用现有测试，只补真实回归风险的最小用例。每批完成运行 `make agent-check`，发布前运行 `make test`；界面由用户运行验收。

交付说明实际减少的重复代码、状态和维护入口，以及未验证项；不把行数或字段数当硬指标。

## 收口

本方向的主干与存储、编辑器整理已执行；完成事实及验证见 `STATUS.md`。后续只处理实际使用中暴露的问题，不继续为拆分而拆分。旧数据不迁移，Agent 引用保护、取消收尾与文件冲突保护继续保留。
