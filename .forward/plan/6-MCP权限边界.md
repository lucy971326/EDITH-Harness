# 第 6 阶段：MCP 权限边界

目标：借鉴 Codex，把 **Server 的启用信任** 与 **Agent 的逐次工具审批** 分开。MCP Server 在宿主侧运行；批准工具调用不代表 Server 进入 Linux / macOS 沙箱。

```text
全局 MCP 配置 ──────────────────────┐
项目 MCP 配置 → 用户确认配置版本 ───┤→ 连接 Server → 发现 Tool
                                    ↓
                              Agent 发起调用
                                    ↓
                     只读：禁用 MCP Tool
                     请求批准：逐次人审
                     智能审批：逐次模型审，不确定转人工
                     完全访问：直接调用
                                    ↓
                              MCP Server 执行
```

## 实现方向

- **连接前**：全局配置视为用户主动安装。项目的 `.mcp.json` 与 `.harness/mcp.json` 先解析、显示将启动的命令或连接的地址；本轮在确认处等待，用户批准后才 `Connect` 并继续发现。按项目真实路径和解析后的有效配置摘要持久记住确认；配置或引用的环境变量变化后旧连接拒绝工具调用，重启读取新配置时重新确认。拒绝时本轮不启用项目 MCP；断线可重连回答，停止则取消等待。
- **准备阶段**：把本轮 `permissionMode` 传给 Agent 的 Tool 准备和 `tools.Call`。只读模式先过滤 MCP，再调用动态 Provider 的 `Snapshot`；不启动项目 MCP，也不给模型 MCP 定义或说明。调用入口再校验一次，不能只靠隐藏 Tool。已启动的全局 Server 仍是用户自己的宿主进程。
- **调用前**：在 MCP Provider 将参数转发给 Server 前，请求独立审批。沿用现有人审、LLM、Jev 的等待、取消、重连和真实用户授权追溯；审批内容为 Server、Tool、实际参数及工作区，不伪装为 `writeRoots` / `network` 申请。每次调用独立裁决，不缓存批准，不信任 Server 自报的“只读”标记。拒绝或停止时不调用 Server。
- **界面与契约**：项目 MCP 信任确认展示配置来源与摘要；MCP 调用复用底部审批框，明确展示 Server、Tool 和参数。审批服务增加 MCP 操作类型，不改变现有命令/补丁的单次权限合并。

## 极简伪代码

```text
准备(项目, 模式):
    如果 模式 == 只读: 返回无 MCP Tool
    配置 = 读取项目 MCP 配置()
    如果 配置未获用户确认: 等待用户确认；拒绝则返回无项目 MCP Tool
    返回 已确认 Server 的 Tool 快照

调用MCP(ctx, call):
    如果 模式 == 只读: 拒绝
    如果 项目配置未获确认: 拒绝
    如果 模式 == 请求批准: 决定 = 人审(ctx, call)
    如果 模式 == 智能审批: 决定 = 模型审或转人工(ctx, call)
    如果 决定不是批准: 不转发
    返回 Server.CallTool(ctx, 原参数)
```

## 验收

- 未确认的项目配置不会启动本地进程或连接远端；确认后可用，修改配置后再次禁用；全局与项目同名覆盖关系仍按现有规则处理。
- 四档模式分别验证工具可见性与调用结果；人/模型批准只放行该次调用，拒绝、故障、停止、断线重连均不误放行。
- 用户在 Linux、Mac 实测本地 stdio 和 HTTP Server。MCP Server 的自主行为与远端服务不受命令沙箱限制，界面说明须如实表达。
