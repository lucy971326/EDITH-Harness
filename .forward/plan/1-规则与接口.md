# 1－规则与接口

目标文档：`.forward/plan/1-规则与接口.md`

## 1. 实现方向与难度

**这一步难度偏低：主要是 Go 数据结构、规则计算与设置保存。** 真正复杂的进程隔离、文件访问和审批等待放在后续步骤。

参考 Codex 可以减少设计试错。本步借鉴三个已经核实的做法：

| Codex 做法 | Harness 如何采用 |
|---|---|
| 实际权限与配置名称分开 | 用户选择 Mode，程序计算 Policy |
| 基础权限与额外授权分开 | 一次批准只生成本次权限，不修改默认值 |
| 用户与自动审核汇入同一审批流程 | 定义统一 Reviewer 接口 |

源码依据：[权限类型](/home/lucy/Documents/Projects/EDITH-Harness/reference/codex/codex-rs/protocol/src/models.rs:421)、[权限合并](/home/lucy/Documents/Projects/EDITH-Harness/reference/codex/codex-rs/sandboxing/src/policy_transforms.rs:630)、[审批入口](/home/lucy/Documents/Projects/EDITH-Harness/reference/codex/codex-rs/core/src/tools/approvals.rs:474)。

先取这些核心关系。Codex 的企业约束、自定义配置继承、持久命令规则和多种授权期限暂不引入。

## 2. 数据与代码放哪里？

```text
SessionSettings
└─ PermissionMode              持久保存用户选择
             │
             ▼
kernel/permissions             本步新增
├─ 类型与 Reviewer 接口
├─ 模式 → 基础权限
├─ 判断额外申请
└─ 批准后 → 本次有效权限
             │
             ▼
审批服务                       后续实现
├─ 人审核
└─ 模型审核
             │
             ▼
Agent 执行层                   后续实现
└─ Linux / macOS 沙箱
```

### 新增内核包，不新增插件

`kernel/permissions` 只有数据和计算函数，没有后台任务或活对象，暂时不登记到 Host。

代码组织：

```text
kernel/permissions/
├─ types.go       数据、枚举、审核接口
├─ rules.go       默认规则、申请判断、权限合并
└─ rules_test.go  核心规则验证
```

它不弹窗、不调用模型、不等待审批、不执行工具，也不启动沙箱。

### SessionSettings 记住模式

新增 `PermissionMode`，沿用现有 `settings.json` 保存机制。

- 新会话默认 `ask_for_approval`。
- 旧文件缺失字段时，读取为默认值；不批量重写旧文件。
- 非空但不认识的模式报错。
- 更新其他设置时，未提供模式就保留原值，避免切换模型时重置权限。
- 分叉复制模式；新建子会话继承父 Run 设置快照中的模式。
- 沿用现有规则：会话空闲时才能修改设置。
- Go 与 TS 契约同步增加字段；设置更新参数中的模式可省略。

**只保存模式，不保存审批决定或临时额外权限。** 本步不显示模式选择菜单，也不宣称执行已经受沙箱限制。

## 3. 四档模式怎样翻译？

| 模式 | 默认写入范围 | 默认联网 | 审核者 |
|---|---|---|---|
| `read_only` | 无 | 禁止 | 人 |
| `ask_for_approval` | 工作区、运行时临时目录 | 禁止 | 人 |
| `approve_for_me` | 同上 | 禁止 | 模型 |
| `full_access` | 不添加 Agent 文件限制 | 允许 | 无 |

前三档允许读取宿主当前用户可读的文件。这是已经确认的产品选择，不提供秘密文件读取隔离。

其他规则：

- 工作区由会话提供，命令的 `workdir` 不扩大可写范围。
- 临时目录由运行时提供，参考 Codex 的 `/tmp`、有效 `TMPDIR`；规则包不自行读取环境变量。
- 借鉴 Codex 的项目保护方式，Harness 保护可写根下的 `.git`、`.agents`、`.harness`；明确申请其中的具体路径才能解除对应限制。
- 宽泛批准一个可写根，不顺带解除其中的受保护目录。
- Full Access 仍受宿主操作系统权限约束。

**工具可用性仍由现有 Tool `Allow` 控制。** 本包判断的是执行权限，不把一次批准变成开放一个原本禁用的工具。

不增加 Bash 危险程度分类器：命令副作用由后续沙箱限制，不能靠猜测命令文本代替隔离。

## 4. 极简伪代码

### 数据形状

```go
type Mode string

// 用户模式翻译后的结果。
type Policy struct {
    Unrestricted bool
    WriteRoots   []string
    Network      bool
}

// 申请，不是授权。
type ExtraPermissions struct {
    WriteRoots []string
    Network    bool
}

type ApprovalRequest struct {
    ToolName, Workdir, Reason   string
    Arguments                  json.RawMessage

    Current   Policy
    Requested ExtraPermissions
}

type Decision struct {
    Approved bool
    Reason   string
}

type Reviewer interface {
    Review(context.Context, ApprovalRequest) (Decision, error)
}
```

读取宿主可读文件是固定规则，不保存 ReadHost 字段；受保护目录从可写根推导，不另存 Protected。请求身份与等待归属由后续审批服务管理，不放进审核者的输入。

审核者只能批准或拒绝这份申请，不能返回额外扩大后的权限。取消、超时与审核故障返回错误。

### 本步实现三个函数

```go
// 第一遍翻译；同时得出人审核、模型审核或无需审核。
BuildPolicy(mode, workspace, tempDirs) (policy, reviewerKind, error)

// 已有权限足够 → Allow；需要额外权限 → Ask。
// 非法或不支持的申请 → 拒绝并返回原因。
Evaluate(policy, requested) (requirement, error)

// 拒绝就返回错误；批准则合并申请，生成新值。
ApplyDecision(request, decision) (effectivePolicy, error)
```

路径要求为规范化绝对路径，按路径段判断归属，不能把 `/project-other` 当作 `/project` 的子目录。权限合并复制切片，不修改共享基础权限。

文件链接与路径替换竞态由后续执行层处理；规则计算不是文件访问的安全边界。

### 后续接线示意，本步不执行

```go
base, reviewerKind := permissions.BuildPolicy(mode, workspace, tempDirs)

switch permissions.Evaluate(base, requested) {
case Allow:
    effective = base

case Ask:
    decision, err := approvals.Review(ctx, reviewerKind, request)
    if err != nil {
        return err
    }

    effective, err = permissions.ApplyDecision(request, decision)
    if err != nil {
        return err
    }

case Deny:
    return rejected
}

return executor.Execute(ctx, operation, effective)
```

审批服务绑定请求身份、管理等待与取消；执行层接收最终权限。已有进程不会因后续批准自动获得新权限。

## 5. 交付与验证

本步交付：

- 权限规则包与统一审核接口。
- SessionSettings 模式保存、默认值与校验。
- 设置接口的 Go / TS 契约同步。
- 尚未接入执行限制的边界说明。

核心验证：

- 四档翻译正确，项目外写入与联网需要申请。
- 受保护目录只有明确批准才能放开。
- 拒绝不产生授权，批准不改变基础权限。
- 相似路径前缀不能误判。
- 模式保存后能重新读取；旧设置得到默认值，更新其他设置不丢模式。
- 分叉与子会话继承模式。

规则用一组表驱动测试；设置行为补进已有相关测试，不新增 UI 自动化测试。完成后执行一次 `make agent-check`。

**验收结果：模式能记住、权限能算对、审核接口已统一。Linux/macOS 沙箱、人审批与模型审批仍由后续步骤接通。**
