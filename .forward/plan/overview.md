# Agent 权限系统实施顺序

目标：Linux、macOS 支持 Read Only、Ask for approval、Approve for me、Full Access 四档权限；Windows 暂缓。

核心流程：`Tool 可用性 → 权限判断（允许 / 禁止 / 需审批）→ 审批（需要时）→ 按本次有效权限执行`。明确禁止的操作直接拒绝。

审批系统独立运行，统一管理请求、等待与取消。人审批和模型审批实现同一个审核接口，接收操作、当前位置、当前权限与申请的额外权限，返回批准或拒绝及理由。批准只覆盖本次申请的权限；失败或取消不能视为批准。Hook 是可选扩展。

两次翻译：`所选模式 + 运行时位置 + 本次获批权限 → 本次有效权限 → Linux bwrap/seccomp 或 macOS Seatbelt`。批准默认只对本次操作有效。

实施顺序：

1. 定义有效权限模型、统一 Tool 决策和审批请求 / 决定 / 审核接口；Tool `Allow` 仍只表示工具是否开放。先明确四档模式的行为，再实现权限判断。
2. 建立 `machine-local` 的 Agent 专用通道，先落实 Linux 命令与文件修改的沙箱限制；已有进程沿用启动时权限。
3. 实现独立审批系统，先接入人审批，打通“申请额外权限 → 用户批准 → 按本次权限执行”；处理等待、停止与断线重连，待审批状态不写入对话账本。
4. 用同一份有效权限接入 macOS Seatbelt，并在 Mac 上验收。
5. 通过同一个审核接口接入模型审批；检查 MCP 的执行边界和子 Agent 的权限继承，未覆盖的入口不能绕过限制。
6. 如需自定义检查，再加入 PreToolUse、PermissionRequest、PostToolUse Hook 及其信任管理。审批 Hook 可以对当前请求提供决定；没有 Hook 时内置审批照常工作。

用户终端和编辑器继续使用原有机器通道。
