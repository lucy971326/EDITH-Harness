# 架构整理方向书

## 目标与原则

保持功能、协议、数据格式、UI 和资源生命周期不变，只整理源码归属。
按职责找代码，按生命周期放状态，入口显式装配；不增加服务容器、转发层或旧路径兼容。

```text
cmd/harness       构造 → 登记 → 启动 → 逆序关闭
      ↓
internal/
  appserver       协议与连接
  conversations   会话操作 → runner → loops / tools
  session / agents / subagents / llm / approvals / ...
  tools/{exec,applypatch,mcp,subagents}
  loops/react、skills/{builtin,filesystem}、commands/compact
  machine/local   具体本机实现

clients/          契约与界面
  web/src/{chat,settings,workspace,editor,terminal,review,subagent}
tests/integration 跨层网络验收
```

## 边界

- `kernel/*` 迁到 `internal/*`；`plugins` 的实际实现归回相应领域子目录；不再保留这两个顶层分类。
- 子包实现依赖父包契约，父包不反向导入具体实现；由 `cmd/harness` 接线。目录嵌套不增加运行层级。
- `appserver` 迁入 `internal`，保留自己的 `internal` 子目录，协议私有实现不向其他领域开放。
- 单测跟源码；自包含的跨层网络测试归 `tests/integration`，补丁登记测试归 applypatch。
- 前端按聊天、设置、工作区归位；共享组件、通信和状态保持原边界。保留单一 Go module、手写 Go/TS 契约。

## 执行顺序

1. 迁移后台目录，更新 import、构建命令和跨层测试位置。
2. 归拢前端文件，更新静态与动态导入、测试加载路径。
3. 同步源码导读、架构规范和有效链接，删除失效的目录说明。
4. 审查纯迁移差异，执行一次 `make agent-check`；额外核对资源嵌入、旧路径与依赖方向。

独立审核未发现方案阻碍。注意：网络测试迁移后深度仍为两级；Web 的 dist 嵌入位置不动；模型目录、内置 Skill 资源随包迁移。前端 SSR 字符串和动态 import 同步更新。

不新增测试；复用已有核心与网络验收。界面由用户运行验收，不自动操作浏览器。完成事实写入 `STATUS.md`，本文件完成后收口。

## 收口

本次目录迁移已执行，完成事实与验证见 `STATUS.md`。本方向不再扩展架构；后续按领域归属维护，保留显式依赖与资源收尾边界。
