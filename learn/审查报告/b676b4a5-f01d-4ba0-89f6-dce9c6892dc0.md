### 发现 1：模型与思考档位首次选定后无法更改——STATUS.md 声称的功能不存在

- 位置：`plugins/products/chat/handler.go:572-596`、`plugins/products/chat/page.templ:50-56`

### 发现 5：`if err := f(); err != nil` 合并写法违反两行分离规则

- 位置：`kernel/runner/run.go:88,92,101,105`、`kernel/tools/registry.go:97`、`kernel/agents/service.go:73,76`、`kernel/persist/agent_settings.go:32,44,56,63,76,79,86`、`kernel/llm/config.go:37`、`kernel/session/session.go:71`、`plugins/tools/*/`、`plugins/products/chat/handler.go` 等约 30 处
- 维度：3（风格统一）
- 严重度：P2
- 归类：A 违规

**问题描述与证据：**

AGENTS.md 规定「生产与测试代码一律把 `err := f()` 和 `if err != nil` 分成两行」。代码中大量使用 `if err := f(); err != nil {` 合并写法，例如：

```go
// kernel/runner/run.go:88
if err := ctx.Err(); err != nil {

// kernel/agents/service.go:73
if err := s.validate(agent); err != nil {
```

**建议与代价：** 机械拆分为两行。波及面为零，可批量 `gofmt` 级重构。

### 发现 6：Chat 插槽登记处缺少并发保护——与 kernel 登记处风格不统一

- 位置：`plugins/products/chat/panels.go`、`plugins/products/chat/docks.go`、`plugins/products/chat/message_actions.go`
- 维度：3（风格统一）
- 严重度：P2
- 归类：B 空白

**问题描述与证据：**

kernel 的三个 B 登记处（`tools.Registry`、`loops.Registry`、`skills.Registry`）均持有 `sync.RWMutex` 保护并发读写。Chat 的三个登记处（`PanelRegistry`、`DockRegistry`、`messageActionRegistry`）均无 mutex，直接操作 `map[string]T`。

当前安全：启动期间 `Install` 顺序调用 `Register`，之后只读。但若将来有运行时动态注册（如 MCP 工具热登记进 message.actions），则产生 data race。

**建议与代价：** 为三个 Chat 登记处补 `sync.RWMutex`，与 kernel 风格对齐。改动限于各自文件，零逻辑波及。

### 发现 9：`escapeHTML` 不转义引号——当前安全但函数不完整

- 位置：`surface/web/static/chat.js:2-4`
- 维度：5（闭门造车）
- 严重度：P2
- 归类：B 空白

**问题描述与证据：**

```js
function escapeHTML(value) {
    return String(value || "").replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
}
```

只转义 `& < >`，不转义 `"` 和 `'`。函数用于 HTML 属性值（`data-*="..."`），若值含双引号可截断属性。当前所有被转义的值均为服务端控制的十六进制 ID 或枚举字符串，不存在注入向量，故实际安全。

**建议与代价：** 补 `.replace(/"/g, "&quot;")` 或改用 `textarea.textContent` + `innerHTML` 惯用法。改动限于 chat.js 一处。

## 总评

- **维度 1（架构清晰）**：分层干净，kernel → surface → plugins 依赖方向正确，Host 服务表模型一致，无循环依赖。
- **维度 2（职责清晰）**：每个包职责单一，A/B 形态使用正确，plugin.go 只做 Start/Close。Chat 登记处合理聚合了三个子插槽。
- **维度 3（风格统一）**：命名基本一致，但 type 标注和 err 两行分离有系统性偏差（发现 4、5）；Chat 登记处缺 mutex 是风格不一致（发现 6）。
- **维度 4（文档双向核对）**：模型/档位不可改是最大的文档-代码矛盾（发现 1）；STATUS 声称的功能不存在；启动顺序文档漏写 events（发现 8）；enable 配置未落地（发现 7）；页面硬编码阶段号（发现 3）。
- **维度 5（闭门造车）**：escapeHTML 自造但不完整（发现 9）；其余轮子（goai、jsonschema 校验、templ+htmx）均为生态现成方案，使用合理。
- **维度 6（过度设计）**：未发现过度设计。接口均在「现在就有两种实现」或「别人来填槽」时才建；未建无用抽象。
- **维度 7（测试缺口）**：四个工具插件零测试是最严重缺口（发现 11）；kernel/agents/config、kernel/session/settings 也缺测试但不直接影响安全。
- **维度 8（演进阻力）**：模型/档位不可改将阻塞分叉场景（发现 13）；enable 缺失将阻塞 tui/acp 接入（发现 14）。
