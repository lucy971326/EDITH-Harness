# 阶段 3：真实聊天

## 摘要

把已存在的 Runner 内核接到 Chat：HTTP 发命令，SSE 收实时事件，一份 JS `paint()` 统一画历史与流式消息。

## 核心改动

- 入口按既定顺序组装完整链路：`persist → session → llm → machine → tools → events → loops/react → skills → agents → runner → web → chat`；不新增聊天专用内核服务。
- Runner 将 Loop 内部事件转换为稳定公开的 `RunEvent`：`run-started`、文本/推理 Delta、工具开始/结束、耐久 `message`、`run-ended(success/cancelled/failed + error)`；不再向表面暴露 `loops.Event`。
- `llm` 提供“已配置 Provider 可用模型及其支持的思考档位”列表；Chat 不读取或硬编码 `models.json`。模型与思考档位是两个独立选择框，用户可先后选择；两项都选好才能首次发送。换模型时清空思考档位，二者共同写入 SessionSettings。
- Chat 增加：
  - `GET /chat/{id}/history`：返回从 Session 转换出的消息 JSON。
  - `GET /chat/{id}/events`：一条持续 SSE，按会话投递 JSON。
  - `POST /chat/{id}/messages`：普通新 Run、显式 FollowUp、显式 Steer。
  - `POST /chat/{id}/stop`：只停止当前 Run。
- Chat 启动时订阅一次 `runner.RunEvent`；回调只写入按 Session 分组的内存队列，绝不等待浏览器。慢客户端或队列满则断开该 SSE；重连重新读 History，未落账的半截 Delta 可丢失。
- Chat 通过 `Runner.Start` 启动普通 Run；断开页面不取消任务。Chat 关闭时只注销订阅、关闭自己的 SSE 连接与队列；Runner.Close 负责取消并等待全部仍在运行的 Run。
- 运行中：
  - 主按钮为“停止当前 Run”。
  - 输入框保留，用户显式选择 **Steer** 或 **FollowUp**。
  - Steer 交给 `Runner.Steer`，仅在下个 Checkpoint 落账。
  - FollowUp 交给 `Runner.FollowUp(sessionID, message)`；Runner 按会话顺序保存，当前 Run 结束后自动发起新的 `Runner.Run`。
  - 点停止只取消当前 Run，已提交 FollowUp 保留并继续。
- 页面初始化、刷新、重连均用 History JSON；流式 SSE 同样更新 `messages` 后调用同一个 `paint()`。工具按调用 ID 累积为多张卡片；推理完成后折叠；取消或失败保留已输出内容并显示在当前助手气泡内。
- 耐久 `message` 表示完整消息已落账：当前助手气泡据此结束流式状态并重画，不 GET、不替换 HTML；`run-ended` 只表示整轮 Run 成功、取消或失败，且不关闭 SSE。

## 测试

- Runner：稳定事件顺序、耐久消息先落账再发布、成功/取消/失败结束状态。
- Chat：History JSON、SSE 过滤会话、慢客户端不阻塞 Run、重连语义、首次模型选择。
- 交互：普通发送、Stop、Steer 在 Checkpoint 才出现、FollowUp 顺序执行且 Stop 后保留。
- 完整 Go 测试、race、vet；配置本机 API Key 后做一次真实浏览器流式验证。

## 已锁定的决定

- 模型与思考档位均由用户选择；两项必须选好才能发送。
- 推理内容完成后折叠展示。
- Stop 不清空等待中的 FollowUp。
- 复制、分叉、附件、模型/档位的后续修改入口仍属于阶段 4/5。

## 本次修正

- 模型和思考档位改为两个独立选择框；两项必选，模型切换会清空档位。
- FollowUp 不归 Chat 保存；由 Runner 的 `FollowUp` 入口按会话顺序管理。
- Runner 是 Run 的主人：Runner.Close 取消并等待 Run；Chat.Close 只清理 SSE 和订阅。
- 删除重复的 `message-complete` 事件；完整耐久 `message` 就表示该助手消息完成。
