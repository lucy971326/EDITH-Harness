# 计划 2：项目分组与会话列表

## 摘要

```text
SessionMeta（会话存在依据）
  + SessionSettings.Workspace
  → Chat 按工作区路径分组
  → 项目 / 会话侧栏
```

项目不是独立数据，只是按 `Workspace` 对会话分组。

## 核心改动

- 在 `session` 定义 `SessionMeta { ID, Title, CreatedAt }`。
- `Store.Create(id)` 先持久化元数据，默认标题“新对话”；即使还没有消息账本，也是一场有效会话。
- `Store.Get` 与 `Store.List` 都以元数据文件为准：
  - `Get` 先确认元数据存在；没有 `.jsonl` 时返回空账本 Session。
  - `List` 扫描元数据文件，不从 `.jsonl` 推断会话存在。
- `Store.List()` 返回 `[]session.SessionMeta`；新增 `Rename(id, title)`，本阶段不做改名 UI。
- JSONL 后端为每个会话保存独立目录：`sessions/<session-id>/meta.json` 是存在依据；`messages.jsonl` 只记录消息节点，`settings.json` 单独保存运行设置。

## Chat 与目录选择

- Chat 读取 SessionMeta 与 SessionSettings，按 `Workspace` 分组；项目名为工作区目录 basename，会话按 `CreatedAt` 倒序。
- `GET /chat` 显示侧栏与空状态；`GET /chat/{sessionID}` 显示选中会话。
- 新建项目按钮发起 `POST`：
  - 成功：创建随机 ID 的 Session，并写入 Settings：
    `AgentID: agents.DefaultID`、选中的 `Workspace`，模型与思考档位均为空；随后 303 到新会话。
  - 取消：选择器返回明确的 `ErrCanceled`，不写数据，303 回 `/chat`。
  - 失败：显示 Chat 页面内的错误，不写任何 Session / Settings 文件。
- 原生选择器留在 Chat 插件：
  macOS 用 `osascript`，Windows 用 `IFileOpenDialog`，Linux 依次尝试 `zenity`、`kdialog`；统一返回绝对且存在的目录。

## 入口与测试

- `cmd/harness` 组装 `persist → session → web → chat`，配置明确的数据目录；本阶段不启动 LLM、Runner 或真实发送。
- 覆盖空会话重启后仍可 List/Get、按 Workspace 分组和排序、成功创建、取消零写入、失败零写入、未知会话 404，以及各平台选择器的命令与取消语义。

## 边界

不做独立 Project 数据、目录手输、模型选择、消息发送、SSE、会话删除或改名 UI。阶段 3 的模型候选必须从已登记的 `llm` 服务读取，不能由 Chat 硬编码。
