# 有序时间线：JSON Reducer

## 目标

修正 Chat 的消息渲染次序：工具结果原位回填，历史恢复与实时流式进入同一份前端状态机；为轨迹图和 Subagent 留下稳定数据。

```text
HTMX：页面壳、侧栏、普通表单、SSE 建连
JSON ：History 快照、SSE 事件、Chat 时间线状态
JS   ：apply() + paint()
```

不用服务端 HTML / HTMX OOB 更新消息卡。它需要 Chat 保存流式 HTML 投影、反复替换整张卡，工具回填和重连都更复杂，也不能直接复用给轨迹图。

## 排序与身份

```text
耐久时间线：Entry.Seq
实时 Run 内容：AfterEntrySeq → StepSeq → BlockSeq
工具回填：ToolCallID → StepSeq / BlockSeq
```

- `Entry.Seq`：Session 每次成功落账递增的持久序号。分叉仍由 `ParentID` 表示；另一分叉的编号不在当前路径出现是正常的。
- `RunID`：一场 Run 的稳定身份。
- `AfterEntrySeq`：Run 的实时内容显示在这条已落账 Entry 后。普通 Run 的锚点是本轮用户消息；`run-started` 必须在该消息落账后发布。
- `StepSeq`：同一 Run 内第几次模型回应。
- `BlockSeq`：同一步回应里的 reasoning / text / tool-call 原始块位置。
- `ToolCallID`：工具调用的稳定身份；工具结果不新增视觉卡，只更新这个调用的位置。

## 账本与 Runner

- `persist.Node` 增加持久 `Seq uint64`。
- `session.Entry` 是 Chat 可读取的账本投影：`ID / ParentID / Seq / Message`。
  - `Session.History()` 保持 `[]Message`，只给 LLM。
  - 新增按当前分叉有序返回的 `Session.Entries()`。
  - `Session.Append()` 成功后返回新 Entry；加载现有节点时恢复下一条 Seq。
- `RunEvent` 携带耐久 Entry，以及 `AfterEntrySeq / StepSeq / BlockSeq` 等运行事实；不携带卡片样式或页面布局。
- React Loop 产生每个 Step 与 Block 的序号。
- Runner 看到 assistant 的 tool-call 块时，记录：

```text
ToolCallID → (RunID, StepSeq, BlockSeq)
```

  后续 tool-start、tool-finish、tool-result 都带同一定位。

## Chat 状态机

Chat 定义自己的 `TimelineItem`：稳定 `ID`、可选 `ParentID`、位置、Kind 和内容。`ParentID` 用于未来把子 Agent 挂到 spawn 工具卡；v1 不实现 Subagent。

```js
state = { itemsByID, orderedIDs, lastDurableSeq }

apply(snapshotOrEvent) {
  // 创建或更新同一个 TimelineItem
  // tool-result 仅更新 ToolCallID 对应项
  // 按耐久 Seq 或实时锚点 / Step / Block 排列
}

paint(state) {
  // 唯一消息区画面出口
}
```

- `GET /chat/{id}/history` 返回有序 `TimelineSnapshot`，由当前分叉的 Entries 构建。
- `GET /chat/{id}/events` 返回 `TimelineEvent` JSON。HTMX SSE 只负责连接；`chat.js` 阻止默认 HTML swap 后交给 `apply()`。
- Snapshot 和 SSE 不要求字节形状相同，但都只能通过同一 `apply()` 修改 `TimelineState`。
- 一个 Run 是一个逻辑组；没有插入用户消息时可连续呈现。Steer 夹在 Step 之间时，按 Step 在时间线上展开，不能把后续 Step 画到 Steer 前。
  每个 Step 内仍按 BlockSeq 严格画：

```text
思考 → 正文 → 工具 → 思考 → 正文 → 工具
```

- 工具卡默认折叠，只显示名称和状态；结果原位更新后展开才显示输出。
- Steer / FollowUp 只在 Runner 实际注入、成功落账时进入耐久时间线；提交后可以临时显示“已排队”。

## 恢复与断线

```text
Run 已结束：History == SSE 的最终耐久状态
Run 进行中：History 是耐久快照，SSE 补实时半截 Delta
```

- SSE 断线时，未落账的 Delta 允许丢失。
- 重连后先用 History Snapshot 重建耐久画面；再处理新 SSE 事件。
- 重复的耐久 Entry 按 `Entry.ID / Seq` 去重；同一工具按 `ToolCallID` 更新。

## 测试与验收

- Session：Seq 从 1 递增；分叉后新节点不复用旧 Seq；Entries 正确给出当前分叉的 ID / ParentID / Seq。
- Runner / React：用户消息落账后才发布带 `AfterEntrySeq` 的 RunStarted；Step / Block 单调；工具事件带原块定位；耐久 Entry 先落账后发布。
- Chat reducer：History Snapshot 与完整 SSE 最终得到相同状态；重复事件不重复卡；工具结果不移动；Delta 更新同一块。
- 浏览器：多工具、Steer、FollowUp、停止、失败、SSE 重连、慢客户端；顺序与账本一致。

## 已锁定

- 选 JSON reducer，不选 HTML / OOB 消息渲染。
- 旧历史直接删除，不迁移、不兼容。
- 一场 Run 一个逻辑组；Step 可被耐久用户消息分开呈现。
- 耐久排序使用 `Entry.Seq`；运行中内容使用 `AfterEntrySeq → StepSeq → BlockSeq`。
