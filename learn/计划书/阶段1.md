# 阶段 1：可启动的 Web 产品壳

## 总结

只验证 Web 本身，不提前组装 Session、LLM、Runner。

```text
cmd/harness 读 harness.yaml
  → Host 安装 web
  → web 提供 products + routes 登记处、启动本地 HTTP
  → Host 安装 chat 产品插件，登记 Chat 产品和路由
  → cmd 在全部 Start 成功后打开浏览器
  → Chat 产品壳显示在完整页面中
```

## 核心实现

- 删除 `kernel/http`：HTTP、路由和产品登记处全部归 `surface/web`。
- 新增 Web 服务契约：

  ```go
  type Service interface {
      RegisterProduct(Product) error
      RegisterRoute(pattern string, handler http.Handler) error
      Products() []Product
  }

  type Product struct {
      ID, Name, Icon, BasePath string
      Order                       int
  }
  ```

  - `Product` 只描述左侧产品入口；重复 ID / BasePath 拒绝。
  - 路由只允许启动时登记；冲突转为 error。
  - 本阶段**不**定义 `RegisterPage`、Slot、Provider；页面插槽留到阶段 4，避免空抽象。

- 新增最小 `plugins/products/chat` 静态产品插件：它 Resolve `web`，登记 Chat 产品和 `/chat` 路由。
  - 普通 `GET /chat` 返回完整 templ 页面壳。
  - HTMX 请求返回带 `id="main"` 的完整主区域片段，`outerHTML` 替换 main。
  - 阶段 1 没有电影、狼人杀等假产品；产品切换能力由登记处测试验证。

- Web 插件：
  - `Config{Host, Port}` 是配置；`net/http.Server` 与退出等待是它的长期资源能力。
  - 使用标准 `ServeMux`；Handler 都是实现 `ServeHTTP` 的结构体。
  - `Close` 关闭服务器并等待 `Serve` goroutine 退出；普通包不打印日志。
  - 静态资源由 `go:embed` 提供；不依赖浏览器联网。

- 新增根目录 `harness.yaml`：

  ```yaml
  web:
    host: 127.0.0.1
    port: 0
  ```

  `port: 0` 自动找空闲端口。`cmd/harness` 读取它，全部插件成功后用系统默认浏览器打开实际 URL；打不开时只在命令行打印 URL，服务继续运行。Mac / Windows / Linux 分别调用系统浏览器入口，不用 PowerShell。

## 前端组织

```text
surface/web/
  *.templ              通用页面壳
  assets/
    tokens.css         公共颜色、间距、圆角等 Token
    input.css          Tailwind 入口
  static/
    site.css           编译产物，Go embed
    htmx.min.js        固定版本
    htmx-ext-sse.js    固定版本
plugins/products/chat/
  plugin.go            填入 Chat 产品与路由
  *.templ              Chat 产品壳与主区域
```

- 固定 HTMX `2.0.10` 与 SSE 扩展 `2.2.4`；以后聊天沿用已验证的 SSE API。
- Tailwind 用本地 CLI 编译；Node 只在开发构建时存在，`node_modules` 不提交。
- 公共 CSS Token 是产品间的样式契约；不在阶段 1 预造 Go 组件库。
- 加入 templ Go 依赖与项目级 `go tool templ`；`.templ` 生成的 Go 文件提交，普通开发者无需先安装 templ 才能测试。

## 参考代码与测试

