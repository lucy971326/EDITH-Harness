# 阶段计划书

原则：一次只实现一个阶段，用真实页面验证后再继续；开发暴露新问题时，允许调整后续设计。

```text
Web 基础 → 项目与会话 → 真实聊天 → 页面插槽 → 完整验收
```

## 阶段 1：Web 基础（已完成）

- 建立 `surface/web`，接管 HTTP Server、路由和产品登记处。
- 建立最小 `plugins/products/chat`：登记 Chat 产品和 Chat 页面路由；Web 不内置 Chat。
- 引入 templ、HTMX、SSE 扩展和 Tailwind。
- 建立最小 `cmd/harness`，真正启动、关闭并打开页面。
- 验证产品路由能够整体替换 `main`。

## 阶段 2：项目与会话

- 增加独立 `SessionMeta`：`ID / Title / CreatedAt`。
- 会话创建时显示「新对话」，首条用户消息落账后自动命名。
- Chat 读取 Session 和 SessionSettings，按 Workspace 组成项目列表。
- 实现 Win / Mac / Linux 原生目录选择器。

## 阶段 3：真实聊天

- History HTTP 返回消息 JSON；聊天消息区用一份 JS/TS `paint()` 渲染历史。
- POST 发话，Chat 使用独立 Context 启动 `Runner.Run`。
- Runner 发布稳定的对外事件；Chat 订阅后放入内存队列。
- HTMX SSE 保持会话页长连接；JSON Delta、工具和完成事件都更新 JS 的 `messages`，再调用同一个 `paint()`。
- `message-complete` 只标记完成，不 GET、不替换 HTML；Run 结束不关闭 SSE。
- 跑通发送、停止、Steer 和 FollowUp。

## 阶段 4：页面插槽

- `message.actions`：已实现登记处与内置复制；助手只复制同一 Run 段最后一条有正文的助手消息。分叉和其他插件动作留后续。
- `dock`：可独立折叠的持续状态。
- `composer.actions`：附件等输入动作。
- `sidepanel`：先实现 keyed 登记处与独立 demo 面板，文件面板留给后续插件。
- `settings.section`：插件设置二级列表。

## 阶段 5：完整验收

- 补齐轨迹页、Session 分叉、模型和思考档位修改。
- 验证产品切换、SSE 重连、慢客户端、取消和关闭。
- 运行 Go 测试、race、vet 和浏览器交互测试。
- 同步《插件设计书》和 `STATUS.md`。

Subagent、电影、狼人杀和更多面板不进 v1；它们只用来验证当前架构没有锁死未来。
