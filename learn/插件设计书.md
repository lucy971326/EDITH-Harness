## 1. 根是宿主，不是聊天

进程是一张服务表。聊天只是表上的一摊。

```
Host（宿主）                        桌子，不是插件
  ├─ HTTP                登记处 B      谁都能占路径
  ├─ 页面洞              登记处 B      布局 8 个洞。侧栏/浮层给桌上另一摊；其余给当前对话
  ├─ sessionPersistence  整份 A        最先挂。只负责字节。jsonl 或 sqlite，组装时选一个
  ├─ Session             整份 A        对话账。从 Persistence Load / Save
  ├─ llm                 登记处 B      一份契约。Completions / Responses / Messages 来填
  ├─ world               整份 A        文件和进程在哪。本地或 E2B，组装时选一个
  ├─ tools               登记处 B      工具来填。Get world，不自己当电脑
  ├─ prompts             登记处 B      提示词文本段。系统提示词插件来填；不代收 schema
  ├─ kinds               登记处 B      LLMAgent / GraphAgent 来填
  ├─ Runner              整份 A        外壳；还没跑完的 Run 也在它手里
  ├─ 狼人杀              整份 A        验架构用，v1 不实现。可 Get Runner，棋盘不进账本
  ├─ 多机器人讨论        整份 A        验架构用，v1 不实现。自己的房间；每个机器人一本 session
  └─ 电影播放器          整份 A        验架构用，v1 不实现。零依赖上面那些。自己的路径
```

`RegisterService` / `Resolve`。定义者出契约，提供者装上，消费者 import 定义者。彼此不 import。

没有两份 Agent。Kind 是怎么想；正在跑的是 Runner 还没返回的 `Run`。

## 2. 宿主 Host

不是插件，是插件挂上去的地方。类型叫 `Host`，不叫 `App`（`App` 像整程序就是聊天）。

```go
type Host struct {
    services map[string]any
}

func (h *Host) RegisterService(name string, v any) { h.services[name] = v }
func (h *Host) Resolve(name string) (any, error)   { /* 没有就 error */ }
```

插件 `Start` 时往上挂；`Close` 倒序拆。没有这张表，后面谁都没处放。

`main` 里谁先 `Start` 谁先挂。`sessionPersistence` 在 `sessions` 前面；`world` 在 `tools` 前面；`prompts` 在填段的插件前面。不要给 Host 加优先级，不要 inject 等待。

### 组装：配置选启不启动，顺序写在代码里

插件必须先编译进去。配置只决定这次 `Start` 哪些已经有的实现，不按包名热加载，不让用户改启动顺序。

```yaml
persist: jsonl      # 或 sqlite。A，二选一
world: local        # 或 e2b。A，二选一

enable:
  - web        # templ + htmx；GUI 是这套外面套 webview，不要再画一遍
  - tui        # bubbletea，可选
  - acp        # 协议桥，不是画面
```

```go
h := NewHost()
startKernel(h, cfg)          // 顺序写死
if cfg.On("movie") {
    movie.Start(h)
}
if cfg.On("werewolf") {
    werewolf.Start(h)
}
```

内核（Host、persist、session、world、llm、tools、prompts、kinds、Runner、HTTP、页面洞）每次都 Start，不出现在 `enable` 里。卸的是表面（web / tui / acp）、系统提示词段、和桌上可选的一摊。

| 配置能做 | 配置不能做 |
|---|---|
| web / tui / acp 上场或不上场 | 发明一份还没写的插件 |
| world 本地或 E2B；persist jsonl 或 sqlite | 两个同时挂；改 Start 顺序 |

「卸」= 这次不 `Start`（v1 改配置后重启）。代码还在二进制里。再装回来 = 写回 `enable`、再 Start。不要做成 DSH 的 `cordis.yml`：那是按包名拼插件树，顺序和清单都在 YAML 里。

新写一种世界或一种游戏，仍要编译。配置不能凭空变出一份没有的 Go 程序。另做一个产品（只看电影）= 另写一个 `cmd` 的 `main`，少 Start 几样，不是用户 YAML 把内核拆掉。

## 3. sessionPersistence

整份服务（A）。只负责字节。jsonl 或 sqlite，组装时选一个。

最先挂。`sessions` 在它后面。

```go
type Persistence interface {
    Load(id string) (*Tree, error)
    Save(id string, tree *Tree) error
    List() ([]Meta, error)
}
```

两个插件都 `RegisterService("sessionPersistence", …)`。表上永远一份 A，不要同时装两个。

不认识 `Append` / `History` / `Branch`。不广播。不是喇叭。Session 去 **调用** 它，不是它去 **听** 账本。

热路径不 `Save`。一回合结束 / Runner 返回，Session 自己 `Save`。

不要 DSH 那套 coordinator、flush 事件、投影、标题服务。Host 上就多这一个键。

## 4. Session

整份服务（A）。对话账。表上挂的是 Store。`Start` 时 `Resolve("sessionPersistence")`。

```go
type Session interface {
    Append(...)          // 在「现在站的地方」下面记一行
    History() []Message  // 从这里往回走到开头，问模型
    Branch(id string)    // 只挪指针。历史不改
}
```

只记人 / 模型 / 工具结果，加上压缩后的摘要。模型那一行是一列有序块（`reasoning` / `text` / `tool-call`），形状见 llm。todo、审批、游戏棋盘，**放插件自己的结构体**。

形状学 pi：可以分叉。不是 DSH 那种只能往下接、什么都往里扔的流水账。

```
用户: 帮我改登录
  └─ 模型: 用方案 A
        ├─ 用户: 就用 A     ← 指针在这
        └─ 用户: 改用 B     ← 旧路还在，没删
```

只有一份。树在 Store 手里；磁盘是 Persistence 的事。不要两份长期分开养（pi：内存一列消息 + 文件一棵树，来回抄）。`History()` 现算，不是第二本活数组。

热路径（字一个个出来）不写盘。一回合结束 / Runner 返回，Store 调 `Persistence.Save`。

**屏幕不听账本。** Session 是听众（一句说完了 `Append`），不是喇叭。

| 要干什么 | 听谁 |
|---|---|
| 现在这句正在往外蹦 | 这一轮 `Runner.Run` |
| 打开旧对话、画分叉、画轨迹 | 读 Session |

喇叭就这一个。标题、压缩、计数：听同一轮 Run。todo：屏幕在「工具结束」时去读它的服务。别每个插件各喊各的。

`Run` 开头把 `Assemble` 的系统提示词存进这轮事实（轨迹要画「当时的 SYSTEM」）。时长 / token 跟在 `Chunk.Done` 上，回合结束写进账本。不是新总线。

## 5. llm

登记处（B）。不是入口。学 pi：对内一种流，对上三种线上协议。

```
Host
  └─ llm  登记处 B          ← 只有这一份契约
        ├─ completions      Chat Completions（DeepSeek / OpenAI 兼容）
        ├─ responses        Responses API
        └─ messages         Anthropic Messages
```

不要 `llmCompletions` / `llmResponses` / `llmMessages` 三个键。Agent 不认线上协议。

```go
type LLM interface {
    Stream(ctx context.Context, req Request) (<-chan Chunk, error)
}

host.Resolve("llm").Register("deepseek", completionsAdapter)
host.Resolve("llm").Register("openai-completions", completionsAdapter)
host.Resolve("llm").Register("openai-responses", responsesAdapter)
host.Resolve("llm").Register("anthropic", messagesAdapter)
```

`LLMAgent` 要流时 `Get`。`GraphAgent` 可以完全不碰。人从不直接调 llm，只调 `Runner.Run`。换模型 = 换适配器。不换 Runner，不换 Agent 接口。

### 请求

档位在请求里。不要再做一个 `Thinking bool`，`off` 就是关。

```go
type Request struct {
    Model           string
    System          string       // prompts.Assemble(spec)。纯文本，不代收工具 schema
    Messages        []Message    // Session.History()。助手消息是有序块
    Tools           []ToolSchema // LLMAgent 现取 Get("tools")
    ReasoningEffort string       // 可空。off | low | high | max
}
```

部署锁在适配器配置上，不进每次请求：`thinking: enabled|disabled`，`defaultEffort`。空档位用默认；部署锁了还选 low/high/max，发请求前拒绝。名单和默认值是适配器公布的，Host 不另挂模型目录。

### 流：有序块

思考、正文、工具会交错。没有下标，前端和轨迹画不对。这是契约，不是 DSH 那种 assembler 服务。

```go
type Kind string // "reasoning" | "text" | "tool-call"

type Chunk struct {
    Index int    // 第几块。前端按这个排
    Kind  Kind
    Delta string // 这一片
    Tool  *ToolCall
    Done  bool
    Err   error
}
```

```
[0 reasoning] 想一下登录……
[1 text]      我改 Auth.go
[2 tool-call] 读文件
[3 text]      改完了
```

`Notify` 原样转 Chunk。页面、Agent、轨迹听同一串：`blocks[Index] += Delta`，按 Index 画。一句说完，Session `Append` 的也是这列块。

不要抄 DSH 的 `block-start` / `block-end` / assembler 包 / `usage` 分片。有 Index + Kind + Delta 就够排。

助手消息同一列块。块上可带 `Replay []byte`：适配器私货（Responses 的 item / 加密思考、Anthropic 的 signature、Completions 的 `reasoning_content` 回传）。前端不画。下一轮 `History()` 交回同一份适配器。

### 三份适配器

线上差很大，拆实现，不拆表。

| 适配器 | 线上 | 思考怎么走 |
|---|---|---|
| completions | `messages[]`，`delta.content` / `reasoning_content` | 思考字段回传 |
| responses | `input` items，`previous_response_id` | 短总结折进 `reasoning`；完整 item 进 `Replay` |
| messages | `content_block_*` | `thinking` + `signature` 进 `Replay` |

Responses 的 `reasoning.summary`（工作中短总结）不单开一种 Kind。跟 pi：summary 和全文都进 `reasoning`；以后产品要两栏再加 Kind，不加 Host 键。

密钥、BaseURL、部署锁、Responses 的 summary 档，都是适配器自己的配置。

先写 completions（DeepSeek / OpenAI 兼容）。responses、messages 后来填同一个 `llm`。契约现在就要能装下它们。

## 6. world

整份服务（A）。文件和进程实际待在哪。本地或 E2B，组装时选一个。

先于 tools 挂。bash / 读文件 `Get("world")`，不自己当电脑。

```go
type World interface {
    ReadFile(path string) ([]byte, error)
    WriteFile(path string, data []byte) error
    Spawn(ctx context.Context, cmd Cmd) (Proc, error)
}
```

两个插件都 `RegisterService("world", …)`。表上永远一份 A，不要同时装两个。

不要拆成 `shell` + `fs` + `subprocess` + `e2b` 四把键。DSH 把世界切成「文件一份、进程一份」，再挂 `e2b` 把两半钉到同一台远程机。我们世界是一个主人；E2B 的箱子寿命藏在那份实现里。

本机沙箱（bwrap 那种）是本地世界的一种实现，不是第四个键。工作区文件夹是 Spec 里「在这个世界的哪个目录」，不是另一种世界。

电影不碰它。

## 7. tools

登记处（B）。一条工具不是一份 Host 服务。

表上挂的是空名单。bash、读文件、spawn，都是来填插槽的。没有 `Create` 出来的活 Tool。

```go
type Tool interface {
    Name() string
    Schema() ToolSchema
    Call(ctx context.Context, args Args) Result
}

host.Resolve("tools").Register(bash)   // Call 里 Get("world").Spawn
host.Resolve("tools").Register(read)   // Call 里 Get("world").ReadFile
host.Resolve("tools").Register(spawn)  // 子任务：碰 Runner，不碰 world
```

`Register` 是填槽。`Call` 是使用。`LLMAgent` 调登记处，不自己翻 map。

问模型那一轮：

```
Spec.工具名单  →  Get("tools") 现取 schema  →  塞进 Request.Tools
prompts.Assemble(spec) →  Request.System     ← 只拼文本，不代收 schema
模型要调工具   →  tools.Call  →  里面 Get world
               →  Notify 工具起止
               →  Session.Append 工具结果
```

某个 Agent 可以名单更窄，也可以一个都没有。`GraphAgent` 可以完全不碰这张表。

异步子任务也只是这里的三个工具，去碰 Runner。孩子的寿命不绑在 spawn 这次 `Call` 的 `ctx` 上。spawn 不是入口，入口还是 `Runner.Run`。

不要为 bash 再挂一个 `shell` 键。bash 就是一条 Tool，跑命令走 world。bash 要教模型怎么用，往 `prompts` 填一段文本，不把 schema 写进人设。

## 8. prompts

登记处（B）。只拼文本段。不代收工具 schema。

```
prompts（B）
  ├─ harness / kind:llm    系统提示词插件（或 LLMAgent Start 时 Register）
  ├─ persona               Assemble 时现取 Spec.人设（每个 session 不同）
  ├─ workspace             当前目录
  ├─ agents.md             读仓库说明书
  ├─ tool:bash             工具怎么用（说明，不是 JSON）
  ├─ acp                   「你在编辑器里」
  └─ 以后：skills / todo
```

```go
type Section struct {
    Name  string
    Order int
    Text  func(AssembleCtx) string // 空串 = 本轮没有
}

func Assemble(spec Spec) string {
    // Spec.人设 + 按 Order 拼各段
}
```

`LLMAgent` 只调 `Assemble`，自己不写死长文。`Request.System = Assemble(spec)`，`Request.Tools` 另取。`GraphAgent` 可以整表不碰。

默认系统提示词是来填插槽的一份插件，不是焊在 Kind 里。配置不 enable，这段就不上场，只剩人设和别人填的段。人设是 Spec，每次现取，不要做成进程里写死的一段。

不要抄 DSH 的 `{{变量}}`、拼装瀑布、在这张表上 `tools()` 代收 schema、`complete` 整段替换。棋盘、审批，别写进人设。

## 9. Agent（Kind）

一种程序怎么想。往 `kinds` 上登记，是登记处（B），不是一场活着的对话。多种 Kind 同时登记；不是每种再挂一把 Host 键。没有「正在跑的 Agent」这份服务——那是 `Runner.live`。

```
kinds（B）
  ├─ "llm"    LLMAgent
  ├─ "graph"  工作流 / GraphAgent
  └─ 以后再 Register 一种
```

```go
type Agent interface {
    Run(ctx context.Context, inv Invocation) error
}

kinds.Register("llm", LLMAgent{})
kinds.Register("graph", GraphAgent{})
```

换范式换这个，不换 Runner。session 在 `Run` 的参数上。同一份 Kind 可以跑很多 session。`LLMAgent` 会 `Get("llm")`、`Get("tools")`、`Get("prompts")`。`GraphAgent` 可以都不碰。

**配置是 Spec，不是插件。** Kind 要编译。用户填数据：哪种 Kind、人设、模型、工具名单、工作区。不要 CustomAgent，用户不热加载 Go。没编译的 Kind，Spec 写了名字也 `Build` 不出来。

```yaml
kind: llm
system: 你是后端助手
model: deepseek-v4
tools: [bash, read]
workspace: /path/to/repo
```

换工作流：`kind: graph`。session 事先就有，Spec 绑在这个 session 上。

```
人说话 → Runner.Run(sessionID, 话)
           Spec = 这个 session 的配置
           a    = kinds.Build(Spec)     // "llm" → LLMAgent
           a.Run(Invocation{账本, 这句话, Notify})
```

用户改配置 = 改 Spec，不是往 `kinds` 上再 Register。子任务可以是另一种 Kind：那是下一份 Spec，再进一次 Runner。

### Invocation

`Agent.Run` 吃的就是这个。钉死三样：

```go
type Invocation struct {
    Session Session
    Message UserMessage
    Notify  func(Event) // Runner 填：Chunk（有序块）和工具起止从这里出去
}
```

`Session`：`History()` 给模型，说完了 `Append`。  
`Message`：人这轮新说的。  
`Notify`：不进账本；Runner 拿去给屏幕。llm 的 Chunk 原样转出去，前端按 `Index` 排。没有它，字出不去。

Spec 不在这里。Runner 先 `Build(spec)` 再 `Run`。取消用外面那个 `ctx`。

DeepSeek 把转圈焊进活 Agent。我们不学。换 loop = 换 Kind，不是换 Runner。入口是 `runner.Run`，不是 DSH 的 `Followup`。

## 10. Runner

整份服务（A）。一场调用的外壳。一般只装一个。

不管怎么想。找账本、按 Spec 把 Agent 建出来、把话交出去、一句说完再记。屏幕听的是它这一次 `Run`。

还没跑完的那些 `Run` 也在它手里。不是第二份 Agent 插件。

```go
type Runner struct {
    kinds    Kinds
    sessions Sessions
    specs    Specs         // 每个 session 一份 Spec（数据，不是插件）

    mu   sync.Mutex
    live map[string]*run
}

type run struct {
    sessionID string
    cancel    context.CancelFunc
    done      chan error
}

func (r *Runner) Run(ctx context.Context, sessionID string, msg UserMessage) error {
    spec := r.specs.For(sessionID)
    a, err := r.kinds.Build(spec)
    sess := r.sessions.Get(sessionID)
    return a.Run(ctx, Invocation{
        Session: sess,
        Message: msg,
        Notify:  r.forwardToScreen,
    })
}

func (r *Runner) Spawn(sessionID string, msg UserMessage) (string, error)
func (r *Runner) Wait(sessionID string) error
func (r *Runner) Stop(sessionID string) error
```

`Run(ctx, sessionID, 话)`：塞进 `live`，卡住直到这轮完。人 / HTTP 走这条。不要加 `appName` / `user_id`。对话隔的是 session；用户隔的是 HTTP 先查再调；产品隔的是 Host 上不同的一摊。

```
人 / HTTP     →  Runner.Run      卡住直到这轮完
点停止        →  Runner.Stop     取消这场 live
模型调工具    →  spawn / wait / stop → Runner.Spawn / Wait / Stop
```

`Spawn` / `Wait` 给子任务工具。`Stop` 两边都用。实现必须在 Runner 上（`live` 是它的）；工具是薄封装。不要把 Spawn 做人入口。

session 和 Spec 事先就有。Runner 不建账本。

多机器人讨论（验架构，v1 不实现）是桌上新的一摊，不是给 `Run` 加路径。房间（谁发言、轮次）在讨论服务自己的结构体里；每个机器人一本 session、一份 Spec；要谁说话就 `Runner.Run(那本 sessionID, 话)`。

| 层 | 干什么 | 谁换 |
|---|---|---|
| Runner | 一场调用的外壳。不管怎么想 | 很少换 |
| Agent | 这种程序怎么干活 | **换范式换这个实现** |
| llm | 被 `LLMAgent` 去调 | 换适配器 |

## 11. 对话怎么跑

```
人发一句话
  runner.Run(sessionID, 话)
       │
       ├─ 正在发生（字蹦出来、工具开始/结束、这轮完了）
       │     → 屏幕听这个（同一进程：回调；浏览器：SSE）
       │
       ▼
  agent.Run(Invocation)
       │
       ▼
  llm.Stream(...)               只有 LLM 类 Agent 才 Get("llm")
```

llm 不是第三入口。

## 12. 异步子任务

平台功能。不是某种 Agent 自己会的本事。

不要的：工具里面把子 Agent 跑完再返回。  
要的：工具只下令，马上返回。孩子在宿主里自己跑。

```
宿主 / Runner
  父 Run(session 父)     还在转
  子 Run(session 子)     另开一条

三个工具（挂在 tools 上，Get Runner）：
  spawn  再调一次 Runner.Spawn，立刻给 id
  wait   Runner.Wait
  stop   Runner.Stop
```

分叉处是再进一次 **Runner**。Agent 里不分叉。子任务有自己的 session，按那一份 Spec `Build`，可以是另一种 Kind。

孩子的寿命不能绑在 spawn 这次工具的 `ctx` 上。工具返回了孩子还得在；只有 `stop` 才杀掉。

父账本只记 spawn / wait / stop 的工具结果。子账本是子自己的。屏幕要看子任务：听子那一轮 `Run`。

不抄 DSH 那一套 subagent 插槽（六个后端、jobs、Activation）。v1：进程内 goroutine、三个工具、深度限制是 Runner 的策略。

## 13. HTTP

登记处（B）。宿主挖好路径洞，谁都能来占。

```go
type HTTP interface {
    Register(path string, h Handler)
}

http.Register("/chat", chatHandler)     // 里面调 Runner.Run
http.Register("/movies", moviePage)     // 零依赖对话
```

请求 POST；字往外蹦 SSE。都走这份登记处。v1 不用 WebSocket。

同一进程（CLI）：Run 调一下听的人。完了。浏览器过不去进程，才需要管子：

```
点按钮 / 发话       → POST
字蹦出来 / 工具在跑 → SSE（还是 HTTP，只下行）
```

SSE 就是把回调送到页面。DSH：请求 HTTP，通知两条只下行 WebSocket，而且是账本转给浏览器。我们不学后半。

## 14. 页面洞

登记处（B）。布局挖洞，别人填 templ 片段。聊天中间 Web 自己画，不当插槽。

两种形态：整列（再占换掉）、列表（往旁边加）。v1 **8 个洞**。不够用再加名字，不抄 DSH 的类型链和 chain 槽。

桌上另一摊（电影、狼人杀：验架构，v1 不实现）入口在侧栏，打开走浮层。也可以再占一条 HTTP 路径当整页。不要挤进 `aside`。

| 洞 | 形态 | 扩展目的 |
|---|---|---|
| `sidebar` | 列表 | 产品入口。Web 占「会话」；电影 / 狼人杀再占一项 |
| `overlay` | 列表 | 悬浮窗。审批、命令；电影播放器、棋盘也走这里。多 id 可并存 |
| `dock` | 列表 | 输入条附近：goal、todo、子任务条。属于当前对话 |
| `header.actions` | 列表 | 标题旁：停止、分叉、轨迹 |
| `composer.actions` | 列表 | 输入条上的钮：附件、模型 |
| `message.actions` | 列表 | 气泡上：复制、反馈。不换整条消息渲染 |
| `aside` | 整列，可空 | 右边工具详情。空着就没有右栏 |
| `settings.section` | 列表 | 设置页加一块：密钥、档位、插件自己的选项 |

```go
type Pages interface {
    Register(slot string, fragment templ.Component)
}

pages.Register("dock", GoalBar)
pages.Register("sidebar", MovieNav)     // 点开进 overlay
http.Register("/movies", MoviePage)     // 可选整页
```

和 HTTP 分工：洞是壳上的位置；路径是整页。不在浏览器再跑一棵插件树。洞在服务端填好，htmx 换片段。

不挖：换掉整页聊天、每一种工具一张卡、设置里每一个开关一个槽。

「喇叭就一个」只约束**对话这一摊**。浮层里的游戏自己更新页面，别倒进账本。

页面洞只给 HTML 壳（Web / webview）。TUI 不走这 8 个 templ 洞。

### 对话 / 轨迹

同一份对话的两种画法。Web 自己切 tab，中间不当插槽。不改 Runner。

```
对话页     气泡：可见的字、折叠的思考、工具卡
轨迹页     时间线：SYSTEM → USER → ASSISTANT → 工具，加上时长、轮次
```

正在发生听这一轮 Notify；打开旧的读 Session。DSH 听账本事件再投影——不学。

v1 先做对话气泡。轨迹是换 templ。子任务点进子 session，还是这两个 tab。

## 15. 多端适配

内核一份。表面按端 `enable`。洞不是端。

```
内核     Runner / Session / llm / tools / world
喇叭     这一轮 Run 的 Notify

表面（配置开关）
  web    templ + htmx，占 HTTP；SSE 把 Notify 送过进程
  tui    bubbletea，同进程直接听 Notify
  acp    协议桥：编辑器 ↔ Runner.Run，不画聊天页
```

画面不同就要各自画。**Web 和 GUI（webview）是同一套 templ**，只是窗口不一样，不要画两遍。开 webview = 还是 `enable: web`，外面套窗口（或 web 插件配 `open: browser | webview`）。TUI 另画。ACP 不画；所有 ACP 编辑器共用这一份插件。

不是四种前端四种插件体系。DSH 是同一套 base 换外壳（web-app / headless / ACP 桥）；浏览器里再跑一棵 React/Cordis——不抄。

## 16. 狼人杀

**验架构的例子，v1 不实现。** 用来问：根是不是宿主。

整份服务（A）。一款游戏，不是对话功能。

棋盘是它自己的结构体。不进 Session。

```go
http.Register("/werewolf", w.Page)
runner.Spawn(wolfSpec, "你是狼人，今晚刀谁")
```

`Get` Runner（要 AI）。页面听游戏服务，不听某轮聊天的 `Notify`。

验的是：根是宿主。游戏和聊天并列，不是挂在 Runner 下面的插件。

## 17. 电影播放器

**验架构的例子，v1 不实现。** 用来问：宿主上能不能放零依赖聊天的东西。

整份服务（A）。一款产品。

什么对话都不 `Get`。

```go
func Movie(host *Host) {
    http := host.Resolve("http").(HTTP)
    http.Register("/movies", MoviePage)
}
```

不碰 Session、Runner、Agent、llm、tools、prompts、world。只占一条 HTTP 路径。

验的是：宿主上可以有零依赖聊天的东西。

和 DSH 的差：他们用户能热加载一点 TS。我们加一种新服务要编译进去。这是故意的。

## 18. 明确不抄

| 不抄 | 学 |
|---|---|
| DSH 账本当产品仓库 + 喇叭 | 账本只记对话 |
| DSH 听账本投影轨迹页 | 对话 / 轨迹是同一数据的两种画法 |
| DSH 持久化听 session/event / flush | Session 自己 Save；持久化只是字节 |
| DSH 转圈焊进活 Agent | Runner 在外面 |
| DSH 提示词代收 schema + `{{var}}` + 拼装瀑布 | `prompts` 只拼文本；schema 走 `tools` |
| DSH 七种 StreamChunk + assembler 服务 | 有序块：Index + Kind + Delta |
| DSH / 自造三份 llm 键 | 一份 `llm`；Completions / Responses / Messages 是适配器 |
| DSH `shell`+`fs`+`subprocess`+`e2b` 四把键 | 一份 `world`；E2B 换实现，箱子寿命在实现里 |
| DSH 四十多个可替换面当内核 | 上面这些就够 |
| DSH subagent 六个后端 + jobs | Runner.Spawn / Wait / Stop |
| DSH isolate / `Run(app, user, session)` | `Run(sessionID)`；用户拦在 HTTP；多机器人是桌上另一摊 |
| pi 扩展往同一棵树塞私货 | 插件自己的结构体 |
| pi 内存一列 + 文件一棵，两头抄 | 一份 Session，`History` 现算 |
| pi harness（没启用）三仓状态机 | 太重 |
| 浏览器第二棵 Cordis、双 WebSocket、几十个 chain 槽 | templ 8 个洞 + POST/SSE |
| 每种前端再做一套内核 / 页面 | 内核一份；Web 与 webview 同 templ；TUI 另画；ACP 是桥 |
| 热加载 Go、AI 自改 | 静态编译。Kind vs Spec |
| DSH `cordis.yml` 按包名排插件树 | 顺序在 Go；配置只选已编译的启不启动 |
| 「正在跑的 Agent」再挂一份服务 | 就是 Runner.live |

## 19. 怎么写代码

一个领域一份服务。服务里面按职责拆文件。**真能换的才做插槽**（B）。别把小能力都 `RegisterService`。

```
Plugin    Name + Start + Close。Start 里挂上，Close 里拆
插槽      B 的 Register 口。不是第三种插件
```

没有 `service.go`。Host 上那份对象就是结构体本身。

能力名硬编码字符串。取出时泛型 Resolve。对不上就是组装错误。

```go
host.RegisterService("runner", r)
r, err := host.Resolve[*runner.Runner]("runner")
```

标识符英文。注释中文。commit 双语。

### 仓库怎么摆

两层半。看 `kernel/` 就是 Host 那张表。一个 `go.mod`。

```
cmd/harness/
  main.go            读 yaml，按顺序 Start
  harness.yaml

kernel/
  host/              桌子。Plugin 接口、RegisterService、Resolve、Close 倒序
  persist/           Persistence；jsonl.go / sqlite.go（配置选，不是 enable 插件）
  session/           Session / 块 / Message；Store
  world/             World；local.go / e2b.go（配置选，不是 enable 插件）
  llm/               空登记处 + LLM / Request / Chunk
  tools/             空登记处 + Tool
  prompts/           空登记处 + Section / Assemble
  kinds/             空登记处 + Agent / Invocation / Spec
  runner/            整份 A；live
  http/              路径登记处
  pages/             8 个洞

surface/
  web/               v1。templ + htmx + SSE

plugins/
  bash/              填 tools + prompts
  completions/       填 llm
  prompt-harness/    填系统提示词那段
```

`tui/`、`acp/` 后期真写再加目录，**不要先建空文件夹**。

类型跟定义者走：块在 `session`，Chunk 在 `llm`，Spec 在 `kinds`。

### 一个包里面

默认同包分文件，不先拆子包。

A（Runner）：

```
kernel/runner/
  plugin.go    Start：Resolve 依赖，New，RegisterService("runner", r)
  types.go     跨包才放
  run.go       type Runner struct { live ... } 和 Run
  spawn.go     Spawn / Wait / Stop
```

B 登记处（tools）：

```
kernel/tools/
  plugin.go    挂上空登记处
  types.go     Tool 接口、Schema
  registry.go  Register / 按名 Call
```

填充者：

```
plugins/bash/
  plugin.go    Resolve("tools")、Resolve("world")，Register(bash)
  bash.go      Call 里 world.Spawn
```

看文件名就是菜单。不要 `manager` / `util` / `common`。活着的 `Run` 在 `Runner.live`。

### import 箭头

```
cmd      → kernel / surface / plugins
plugins  → kernel（只定义者）
surface  → kernel
kernel   不得 import plugins、surface
定义者   不得 import 填充者
```

### 启动

```yaml
persist: jsonl
world: local
enable: [web, bash, completions, prompt-harness]
```

```
main:
  host.New()
  必装：persist → world → session → llm → tools → prompts → kinds → runner → http → pages
  再按 enable：plugins/* 、 surface/*
  Close 倒序
```

顺序只出现在 `cmd/harness`。yaml 不能重排。jsonl / local 是 A 包内部选文件，不出现在 enable。

### 什么时候才拆子包

三件都满足才加一层目录：能独立替换；边界稳定；不会绕一圈转发。

```
优先：领域包 → 章节文件 → 函数
```

不因为文件长或「以后也许有用」而拆包。不建空的 `tui/`、`acp/`。

### 装上和拆掉

- B 的 `Register` 返回幂等 `unregister`。
- `Install` 中途失败：已 Start 的倒序拆。
- 谁开长期资源，谁关。
- 一次铺一个领域，测过再下一个。不顺手加功能，不改已经公开的能力名。
- 可选插件用配置 `enable`；内核名单和 Start 顺序留在 Go。v1 改配置后重启。不热加载未编译的包。

### 写法

- 可读性优先，不炫技。
- `err := f()` 和 `if err != nil` 分成两行。
- 每包一个主要公开构造入口；构造只校验依赖和组装。
- 接口只为现在的边界，不为未来预建。
- 不要没有主人的 `utils.go` / `helpers.go` / `common.go`。

### 讲一个插件时四问

一次只讲一个。先说是不是插件，再说已经有了还是计划。

```
【它是什么】     一句话
【提供能力】     别人 Resolve 到什么
【使用能力】     它 Get 哪些已有的
【填充插槽】     填哪个 B；没有就写「不填」
```

不是插件（比如 Spec）：它是什么、干什么、谁产生/谁用。先人话，再代码名。不把没做的说成已经有了。
