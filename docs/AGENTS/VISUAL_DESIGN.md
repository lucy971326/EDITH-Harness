# EDITH 视觉规范

本篇定义应用与官网共用的品牌视觉语言。应用的状态与交互规则见 [WEB_UI](WEB_UI.md)；具体色值、尺寸和组件外观以各自前端的公共 Token 与组件为准。网站与应用可以采用不同布局和密度，不共享一份 CSS。

## 核心语言

```text
暖中性机身 + 克制的信号橙 + 轻微器物质感 + 安静的内容区
```

- 用暖米色、暖灰和深暖灰组织背景与文字；亮暗主题保持同一种层级关系。信号橙只强调主操作、当前选择或真实活动状态，不铺满背景，也不直接用于低对比度的小字。成功、等待、失败可使用各自的状态色，并配文字或图标。
- 状态本身可以形成视觉特点：灯、读数和刻度必须对应真实状态。没有数据时留白，不编造进度、计数或循环动画。
- 保持当代产品的克制感。避免厚重拟物、反复堆叠浮雕、毛玻璃、霓虹和彩色渐变；长时间阅读的聊天、文档与代码区域保持平面和足够的对比度。

## 层次与排版

- 面板轻分层；可按的控件可以微凸，输入与选中项可以微凹，正文与普通列表保持平静。一个区域至多表达面板、控件、内容三层关系，不在凸起控件内继续堆凸起控件。光照、边框与阴影方向一致。
- 间距按 4px 阶梯组织；同类面板、控件和嵌套圆角保持一致。应用的窗口外边距与面板间距使用同一个 Token，窄窗口按内容需要收紧；官网可有更宽松的留白。
- 应用 UI 固定使用已打包的 Ginto 与 MiSans；内容字体、代码字体按现有外观设置独立选择。官网沿用相同的字体角色与品牌气质，字体文件和授权由网站单独核实。等宽小标签只用于有助于辨识的元信息，不要求每处都贴标签；点阵字仅可少量用于真实的英文或数字读数，不进入正文、导航和表单。
- 使用现有 EDITH Logo。相同含义保持同一图标，控件不以 Emoji 代替图标；插图与截图的呈现服从内容，不为装饰添加假仪器零件。

## 状态、组件与动效

- **保留运行仪表条与步骤刻度作为未来组件方向**：只在后端能提供明确状态和有意义的总量时展示相应读数；当前 ReAct 运行不推算步骤总数，不显示完成百分比。状态词与刻度应有可访问的文本等价。
- 同类按钮、输入、菜单、导航和回执使用所在前端的公共组件与语义 Token；页面只组织布局，不复制阴影或色值配方。主要操作醒目，普通操作低调，危险操作有清楚的文字与确认。
- 交互反馈短而稳定；展开与收起可以平滑过渡，正文不持续运动。尊重 `prefers-reduced-motion`，不用声音、视差或自动循环动画制造存在感。
- 文字与控件满足对比度要求，键盘焦点可见；状态不只靠颜色，图标按钮有可访问名称，窄屏和触屏仍能操作。
