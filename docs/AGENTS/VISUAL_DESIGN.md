# EDITH 视觉规范

本篇定义 EDITH 应用的视觉语言。应用的状态与交互规则见 [WEB_UI](WEB_UI.md)；具体色值、尺寸和组件外观以公共 Token 与组件为准。官网有独立样式，不在本次应用改造范围内。

## 核心语言

```text
冷白阅读区 + 淡青玻璃侧栏 + 深色主操作 + 克制的状态色
```

- 亮色主题以白色内容区、默认淡青侧栏和深色文字为主；暗色主题保持相同层级与足够对比度。主要操作用深色实底，运行与选中提示随主题色变化，成功、等待、失败保留各自状态色和文字或图标。
- 状态本身可以形成视觉特点：灯、读数和刻度必须对应真实状态。没有数据时留白，不编造进度、计数或循环动画。
- 玻璃效果仅用于主导航与设置导航侧栏：两处共用色调、透明度、模糊、高光和细边 Token；背后的冷色层次透过玻璃，表面只留一层柔和反光。阅读、编辑器、终端与表单保持不透明。避免厚重拟物、浮雕和霓虹。
- 外观色板统一替换侧栏玻璃色、文件树、聊天代码／气泡、工具底色、悬停／选中、运行提示、边线与编辑器选区；阅读／编辑表面、玻璃透明度、模糊、高光强度，以及成功、警告、失败和代码语法色保持固定。亮暗主题各有对应配色，所选色板属于当前客户端偏好。

## 层次与排版

- 侧栏、正文与辅助工作区贴合，用细分隔线区分；不在宿主窗口内部再套一层带边框的圆角面板。设置导航与内容区同样保持一体。普通列表保持平面，当前项用浅底色与细边线。按钮、输入框与回执不用内凹阴影；浮层和输入框可用一层柔和短阴影。
- 间距按 4px 阶梯组织。圆角只分控件 8px、内容卡片／消息／输入区 16px、浮层 20px、胶囊形；工作区外角交给宿主窗口裁切。正文比导航更舒展。
- 字号按辅助文字 12px、控件与普通正文 13px、聊天阅读与输入正文 14px、小标题 16px、页面标题 22px、欢迎标题 30px 分级；代码字号独立为 13px。Markdown 内相对字号可随正文缩放，不另设全局级别。
- 应用 UI 固定使用已打包的 MiSans；内容字体、代码字体按现有外观设置独立选择。等宽小标签只用于有助于辨识的元信息；点阵字不进入正文、导航和表单。
- 使用现有 EDITH Logo。相同含义保持同一图标，控件不以 Emoji 代替图标；插图与截图的呈现服从内容，不为装饰添加假仪器零件。

## 状态、组件与动效

- 只在后端能提供明确状态和有意义的总量时展示相应读数；当前 ReAct 运行不推算步骤总数，不显示完成百分比。状态词须有可访问的文本等价。
- 同类按钮、输入、菜单、导航和回执使用所在前端的公共组件与语义 Token；页面只组织布局，不复制阴影或色值配方。主要操作醒目，普通操作低调，危险操作有清楚的文字与确认。
- 交互反馈短而稳定；展开与收起可以平滑过渡，正文不持续运动。尊重 `prefers-reduced-motion`，不用声音、视差或自动循环动画制造存在感。
- 文字与控件满足对比度要求，键盘焦点可见；状态不只靠颜色，图标按钮有可访问名称，窄屏和触屏仍能操作。
