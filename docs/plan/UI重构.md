# UI 重构（待拍板）

## 目标

让 Web 下所有产品与页面插槽填充物使用同一套视觉语言：Chat、未来的 Movie、狼人杀，以及 Dock、右侧面板、输入动作、设置栏目，都应一眼看出属于 Harness。

```text
surface/web：拥有视觉语言
    ├─ Web 产品：组合公共规则
    └─ 页面插槽填充物：同样组合公共规则
```

产品决定自己的内容与布局；不得自行定义基础颜色、字体、字号、圆角、按钮或输入框样式。

## 已拍板的方向

| 事项 | 决定 |
| --- | --- |
| 统一边界 | 统一应用外壳与视觉语言；产品拥有独立内容舞台。 |
| 视觉气质 | 克制、温暖的桌面工具感；不模仿某个操作系统，不靠强装饰建立品牌。 |
| 主题 | 正式支持亮色、暗色与跟随系统；只切换 Token。 |
| 字体与阅读 | 使用系统字体；字号固定，不提供用户调节；暂不内置字体。 |
| 图标 | Lucide 为唯一正式图标库；正式 UI 不用 Emoji 充当图标。 |
| 公共 UI 规则 | 第一批保持少而完整：page、panel、card、button、icon-button、input、select、nav-item、notice、empty-state。 |
| Chat 专属内容 | 消息、推理、工具卡、代码块等归 Chat 自己的规则；继承 Token，不升级为所有产品的公共组件。 |
| 可访问性 | 键盘焦点、颜色对比、图标标签、减少动画从第一版就是硬规则。 |
| 桌面窗口 | 只做电脑端；空间不足优先保留主内容，右侧面板进入关闭态。 |
| 偏好保存 | 主题属于浏览器本地偏好；字号固定，不写入 Session 或聊天账本。 |

UI 铁律：

```text
surface/web 统一应用外壳与视觉语言；
产品拥有自己的内容舞台；
填充物继承宿主产品的视觉语言，不得另起一套。
```

## Chat：工作流而非卡片列表

Chat 是 AI 工作台中的连续工作流，不是把用户、推理、工具与回答全部画成同等权重的大卡片。

```text
用户消息
  ↓
工作过程（默认收起）
  ├─ 进展说明
  └─ 事件摘要（可二级展开）
       └─ 单项工具 / 文件 / 搜索事件
  ↓
最终回答（默认直接可读）
```

### 信息层级

```text
默认：工作过程 ›

一级展开：
  进展说明
  已调用 3 个工具 ›

二级展开：
  读取 AGENTS.md
  查看目录
  修改 STATUS.md
```

- 默认只露出最终回答与一行“工作过程”；过程不污染阅读。
- 推理、工具与运行细节属于过程；代码、文件内容、错误详情才使用自己的内容容器。
- 用时不是 v1 的必需信息，不以它作为工作过程的默认标题。
- 默认文案：完成为“已完成 · 工作过程”，运行中为“正在工作”，失败为“未完成 · 查看过程”。
- 不照抄 Codex 的颜色、间距或文案；只参考其“结论优先、过程分级追溯”的信息层级。

### 已拍板的工作流规则

#### 运行中

运行中的工作流保持一行安静状态，不自动展开成长内容：

```text
正在工作 · 正在读取 AGENTS.md ›
```

用户主动展开后才看过程。Agent 忙碌不能让页面重新变成卡片堆。

#### 工具信息

工具事实分两级：

```text
一级：读取 AGENTS.md
二级：工具名、参数、输出、错误
```

日常阅读只看“做了什么”；排错时才展开完整命令、输出或错误详情。

#### 历史与临时状态

```text
耐久保存：最终工具事实、最终正文、失败结果
浏览器临时：展开状态、正在流出的半截文字
```

刷新历史后必须仍能重新投影出同一条工作流；浏览器中的展开状态不写入 Session。

#### 失败与等待

失败、停止和等待用户确认都必须比成功更醒目，但仍只占一行：

```text
已完成 · 工作过程 ›
正在工作 · 正在读取文件 ›
需要处理 · 查看原因 ›
等待你的确认 ›
```

不使用巨大红色错误卡片；只有用户展开后才显示具体原因与可执行的下一步。

#### 最终回答

一次 Run 中的中间说明（如“我先检查一下”）收进工作过程；最后一条有正文的助手消息留在外面，作为默认直接可读的最终回答。

这与复制动作的既有规则一致：只复制同段工作流中最后一条有正文的助手消息。

### 实现边界

```text
Templ + Tailwind：页面外壳、历史结构与视觉规则
原生 <details>：一级 / 二级展开收起
HTMX SSE：接收 Runner 的实时 JSON 事件
Chat JS：仅把实时事实投影为当前工作流
```

- 不为展开收起、普通状态切换或装饰动画新增 JavaScript。
- 保留现有 Chat reducer / `paint()` 处理实时事件与稳定排序，避免运行中内容跳位。
- 现有 `RunID / StepSeq / BlockSeq` 是工作流的顺序事实；本次重构只改变投影画法，不改变账本或 Runner 事实。

## 两层公共体系

```text
Token（视觉原料）
    ↓
公共 UI 规则（标准零件）
    ↓
产品与填充物页面
```

### A. 基础 Token

Token 只保存数值与主题差异，不直接画组件。

- 颜色：页面、面板、内容、边框、主/次文字、主操作、成功、提醒、危险。
- 字体：UI 正文、标题、辅助文字、等宽代码。
- 排版：字号、字重、行高。
- 尺寸：页面留白、区块间距、卡片内边距、控件内边距。
- 外观：小控件、卡片、大容器的圆角；阴影与浮层层级；动画时长。

亮色与暗色只替换这一层 Token；产品和填充物不得各写一套深色样式。

### B. 公共 UI 规则

公共规则只组合 Token，供所有 Web 产品与填充物选择使用。

```text
文字：title / section-title / body / meta / code
容器：page / panel / card
操作：button-primary / button-secondary / button-danger / icon-button
表单：input / select / checkbox / help / field-error
导航：nav-item
状态：notice-success / notice-warning / notice-danger / empty-state / loading
```

产品与填充物使用“文字角色”和“标准零件”，不直接指定字号、颜色、圆角或阴影。

```templ
<section class="ui-card">
  <h2 class="ui-text-section-title">任务</h2>
  <p class="ui-text-body">内容</p>
  <button class="ui-button-primary">确认</button>
</section>
```

### C. 公共图标库

图标属于 `surface/web` 的公共视觉体系，不属于 Chat 或任何单一产品。Chat、未来产品与全部页面插槽填充物使用同一套内置、可分发的开源 SVG 图标库；不依赖外网，也不需要 JavaScript。

```text
surface/web/ui：图标目录与 SVG 输出
       ↑
Chat / Movie / 狼人杀 / Dock / 面板 / 设置填充物
```

图标的**形状**由公共入口 `ui.Icon(ui.IconFolder)` 输出为 Templ 组件；Token 与 Tailwind 只控制图标的**颜色、大小和间距**。

```text
Token / Tailwind：图标多大、什么颜色
ui.Icon(...)     ：图标长什么样
```

使用受控的 Go 常量，而不是随手传字符串：

```go
ui.Icon(ui.IconChat)
ui.Icon(ui.IconFolder)
ui.Icon(ui.IconSettings)
```

未来插件与开发 Skill 应遵守：

- 只能使用公共图标目录里已有的 `ui.IconXxx` 常量。
- 不手写 SVG，不用 Emoji 充当正式 UI 图标，不接入第二套图标库。
- 缺图标时在公共目录新增一项，而不是由某个产品私自保存图标。
- 写错常量名会在 Go / Templ 编译时失败，避免静默画出错误图标。

## 必须统一的视觉规则

1. 字体体系：UI 正文、标题、辅助文字、等宽代码。
2. 间距体系：页面、区块、卡片、控件的留白。
3. 圆角体系：小控件、卡片、大容器；禁止随手选择 `rounded-xl` 等值。
4. 边框与层级：页面底、侧栏、内容卡、浮层、输入控件的关系。
5. 文字层级：页面标题、区块标题、正文、说明、禁用文字。
6. 操作体系：主、次、危险、图标按钮，以及禁用与加载状态。
7. 表单体系：输入框、下拉框、复选框、帮助文字、错误与焦点状态。
8. 状态体系：成功、提醒、危险、运行中、空状态、加载失败。
9. 交互状态：hover、focus、active、disabled；键盘焦点必须清晰。
10. 阴影与浮层：菜单、右侧面板、弹窗使用固定层级。
11. 动画：统一过渡规则，并尊重系统“减少动态效果”设置。
12. 深色模式：只切换 Token。
13. 图标：统一图标库、尺寸、颜色、无障碍标签与使用方式。

## 边界与执行原则

- Tailwind 是实现工具，不是视觉规范本身。
- `surface/web` 定义 Token 与公共 UI 规则；Web 产品和填充物只消费它们。
- 不把每一种特殊产品内容强行抽成公共组件；先统一基础视觉语言。
- 现阶段用公共规则与代码审查约束，不为禁止原始 Tailwind 类预建复杂检查器。
- 字体可随项目分发；中文字体体积大，具体是否内置与字体选型后续拍板。

## 待拍板

- 字体策略：系统字体，或内置可分发字体；中文字体是否内置。
- 阅读字号：固定标准档，或提供“标准 / 大号”两档。
- 亮色与暗色的实际视觉方向。
- 公共 UI 规则的第一批具体外观与命名。
- 重构范围与顺序：先建立体系，再逐页迁移 Chat 与设置页。
