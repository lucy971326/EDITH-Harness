# 3B：让新页面真正能聊天

状态：已拍板，待实施。用户决定压缩会话后，由 Codex 直接实现本步，不再等待转交 Grok；本次只保存计划并提交已有改动，不开始 3B。

先读根目录 `AGENTS.md`、`STATUS.md`、`WEB_UI.md` 和 `DATA_MODEL.md`。总体顺序与唯一功能清单仍在 [Web 迁移计划](Web迁移计划.md)，界面沿用 [产品定义](ProductDefine.md) 和拍板原型；本篇只展开 3B，不另建当前任务文件。

## 1. 目标与边界

接通历史、实时文字、发送、插话、停止和断线恢复，让正式 React 页面能够完成一场真实文字聊天。

```text
历史快照 ──┐
           ├→ 同一份聊天状态 → 同一套页面渲染
实时更新 ──┘
```

- 本步先做纯文本和基础运行状态；三级工作过程、完整工具卡片、Markdown 清洗与复制留第 4 步。
- 接入最小“模型＋思考”菜单，否则新会话无法发送；Agent 管理、独立设置编辑、图片发送、真实用量留第 5 步。
- 分叉、Skill 与命令留第 6 步；Go embed、正式入口切换和旧 Web 清零留第 7 步。不改原型、不为旧页面补兼容层。
- 不新增等待队列、业务防重框架、完整多 Client 协调或反向请求。本步只补已拍板的定向插话保护，停止沿用既有会话级父子停止语义。

## 2. 状态与页面接线

- 复用正式 Web 的 `RPCClient`，补齐运行通知、订阅和解除订阅；不照搬测试 Client 的等待队列，不引入新通信库或通用 Store。
- 普通 TypeScript 管聊天数据、订阅与恢复，React 负责显示和局部交互。连续流程清楚展开，不把所有逻辑继续堆进 `App`，也不制造多层转发。
- Snapshot 与事件进入同一份投影。按 `Entry.ID` 更新消息：增量补正文，完整 Entry 替换同 ID 草稿，不能追加第二份。保留 `blocks` 的种类、顺序和工具关联，不压扁成原型的文字列表。
- 沿用 3A 的 `updateSeq`、`seqEpoch`：忽略已含更新，只接续当前快照之后的事件。App-server 已保证网络通知按序，Client 不再造乱序队列；发现序号缺口或后台换代就重新同步。
- 快照可能省略尚无内容的草稿，首条增量也必须能按 EntryID 和位置建立草稿，不能依赖一定先收到 `message-started`。已落账的消息不能被迟到增量重新变成草稿。
- 展示位置沿用消息 `afterSeq`／草稿 `afterEntrySeq`，块位置沿用 BlockSeq；工具结果继续按 ToolCall.ID 对应。插话前已生成的内容不跳位，消费插话后的新输出排到新位置。
- 旧历史缺少结束状态时显示“状态未记录”；缺新位置字段时按账本顺序显示。不猜成功，不补写旧账本。未完成正文／思考不能冒充最终回答。
- 只订阅当前会话；打开设置页不解除，切会话解除旧订阅。先采用订阅响应中的 Snapshot，再应用后续通知；旧连接、旧选择的迟到响应与通知不能覆盖新会话。
- 切换过程中返回的旧订阅仍须解除；订阅失败不能把空画面当空历史。恢复完成前禁止发送、插话与停止，不能仅因 WebSocket 已连接就开放操作。

## 3. 只新增一个 JSON-RPC 方法

### `model/list`

- 输入 `{}`，结果 `{ models: [...] }`；条目使用 `id`、`contextWindow`、`vision`、`reasoningEfforts`，对应公共 LLM 服务已有的 ModelChoice 数据。不返回密钥或 Provider 配置。
- 能力来自 Host 注册的 `llm` 服务（`*llm.Client`），直接复用 `Models()`，不是模型调用，不发起付费请求。

```text
入口从 Host 取出 llm → 显式交给 appserver
model/list → appserver 的具名 handler → llm.Models()
```

- appserver 不读取 Host，不经过 HarnessProduct 做无意义转发。方法仍在监听前显式登记，按既有规则校验输入输出；Go／TS 契约手工同步。

### 修改现有 `harness/session/send`

- 增加可选、非空的 `expectedRunID`。页面运行中提交时携带当前 RunID，只能插入这一轮；已结束、已关闭插话或换轮均返回既有冲突分类（JSON-RPC `-32009`），不得转成 Start。
- RunID 核对与插话准入、落账在同一临界区内完成，不能先查 State，再调用不带身份的 Steer。保留 3A 的检查点与发布收尾保障。
- 不携带此字段的既有调用保持原来的闲时 Start／忙时 Steer 行为。返回仍为 `{ mode: "started" | "steered" }`；不新增消息编号、RPC 方法或 3A 存储字段。
- 参考已核对的本地 Codex：`TurnSteerParams.expected_turn_id` 与 `turn_steer_inner` 校验预期运行；这里只借鉴身份前提，不照搬请求队列或完整多端机制。

其他会话方法、Snapshot、subscribe、stop 与 unsubscribe 均复用。

## 4. 已拍板交互

- **确认后清空。** 后台确认接受才清除本次提交的草稿；不能清掉期间新编辑的文字或其他会话草稿。等待期间防止同一条输入重复提交，不预先伪造已发送的耐久消息。
- **失败保留。** 失败、超时、断线保留文字。结果不明时提示核对历史，不自动重发，也不按正文相似性猜测是否已接受。
- **插话赶上结束。** 留在输入框，提示本轮已结束或变化；由用户再次确认发送，不自动开下一轮。
- **刷新恢复。** 用本标签页的 `sessionStorage` 记住选中会话，刷新后恢复历史和生成中的内容；首次访问仍不自动选中。输入草稿只留内存，不承诺刷新后恢复。只在明确不存在时清除选择。
- **最小模型菜单。** 模型和思考合用一个菜单；旧会话沿用有效设置，新会话由用户选择，不填假默认值。运行中禁用修改；Agent 沿用当前会话设置。模型目录为空或加载失败时就地提示，不冒充已配置。
- **自动重连。** 断线保留当前画面与草稿，按 1／2／4／8／10 秒间隔重试，之后上限 10 秒；保留手动重连入口。同一时间只允许一个连接尝试，手动重连与卸载应清理旧定时器、连接和回调。重新初始化并恢复当前会话后才开放操作，不重发业务请求。
- **停止状态。** 点击后显示“停止中”；后端确认的结束状态才是事实。请求响应不等于已停止，任务抢先成功也不能强行显示取消；停止继续覆盖子任务。
- **输入与阅读。** Enter 提交、Shift＋Enter 换行，输入法选词不提交；运行中直接插话，无确认条、无等待队列。图片预览保留，但有附件时阻止提交并说明尚未接入，不能偷偷只发文字。向上阅读时不强制滚到底部。
- 首条耐久用户消息后的标题、发送后的会话设置从后台刷新，不在每个文字增量上重新拉列表或猜标题。

## 5. 实施、验证与收口

执行顺序：先补最小接口与失败测试 → 接通统一投影、订阅和恢复 → 接页面操作与模型菜单 → 真实网络、浏览器验收。只做本步，不自动进入第 4 步。

重点回归：

- 同一场运行经实时事件和最终快照恢复，内容、位置及结束状态一致；覆盖中文增量、半句话刷新、空草稿后的首个增量、重复事件、极快完成、插话前后位置、失败与停止保留半截。
- 插话到达时原 Run 已结束或换轮：返回冲突、不追加输入、不启动新轮；正常插话仍被检查点取走。原有无 expectedRunID 的测试 Client 行为不变。
- 快速切会话、切设置、迟到订阅响应、迟到发送确认、提交期间编辑、连续点击、中文输入法与父子任务停止。
- 断线后不杀 Run、不重发请求；重连、刷新、后台重启恢复一致。使用现有真实后端和本机模拟模型，隔离测试数据，不调用付费模型、不用用户真实会话测试。
- 浏览器检查真实发送／插话／停止／恢复、模型菜单、向上阅读，以及亮暗与窄屏；用量、图片、三级过程等未接入能力如实标明。
