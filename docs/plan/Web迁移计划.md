# Web 迁移计划

按已确认的 [产品定义](ProductDefine.md) 和 `prototypes/web` 原型迁移，不重新设计界面。稳定架构看 `../设计书.md`，完成事实只写根目录 `STATUS.md`。

## 协作方式

- Codex 负责拆任务、检查实际 diff 和验收；用户亲自转交会话中的任务与 Grok 回报，不维护当前任务文件。Grok 每次只执行用户转交的本步任务，不得提前做下一步。
- 首次先只读理解项目并在会话中回报；用户将理解文本交给 Codex 审核，通过后才派实现任务。
- 每步交付包含实际改动、执行过的测试与结果、已知问题；Codex 审核通过后才能派下一步。未通过只修本步，不用报告代替源码审查。
- 通过后的完成事实收口到 STATUS，再由用户转交下一步任务；不另建每轮报告或第二份功能清单。提交按用户指令执行。
- 允许中途项目无法完整运行，不为保住旧页面增加兼容层。每步明确哪些入口不可用、原因和计划恢复步骤；可独立验证的部分仍需验证。

## 七步施工顺序

每步按需同时修改后台接口、手写 Go / TS 契约、前端和测试，不先造完整但无人使用的 API。以下是分步边界，不是一次性授权；具体接口与验收命令在派发该步前通过源码核对，写入交给用户转发的任务 Prompt。

| 步骤 | 工作边界 | 审核关口 |
|---|---|---|
| 1. 正式前端基础 | 从拍板原型建立 `clients/web`；保留组件、Token、布局与辅助标签壳；去掉模拟运行和演示入口，未接入业务明确禁用 | 不改设计、不伪造业务成功；类型检查、构建与布局检查 |
| 2. 项目与会话 | 类型化 WS Client、初始化、连接状态；目录选择、列表、创建和切换；按需补 RPC | 真实后台数据、取消目录选择、空会话复用、错误与草稿保留 |
| 3. 文字聊天闭环 | 发送、Snapshot / 事件投影、Steer、停止、历史加载与重连 | 不丢不重不乱；断线不杀 Run、不自动重发；停止包含子任务 |
| 4. 消息呈现 | 三级工作过程、工具回填、Markdown 清洗、复制、最终回答与失败停止状态 | 历史和实时使用同一投影；正常完成收起，失败停止展开；长输出限高 |
| 5. 输入与设置 | 模型／思考、SessionSettings、Agent 管理、图片与真实用量 | 设置影响正确轮次，删除保护、图片限制与持久化正确 |
| 6. 剩余正式操作 | 完成回答分叉、Skill 候选、命令目录与执行；核对下表全部功能 | 真实动作而非原型文本插入；没有遗漏或擅增功能 |
| 7. 切换与清理 | Vite 产物由 Go embed，HTTP 仅静态资源；正式启动接入 React；删除旧 Web、专属依赖和生成链；同步文档 | 从干净工作区构建启动；全部业务走 WS；全链路和关闭验收 |

旧代码可在前面步骤按实际依赖提前删除，第 7 步负责清零，不强留双轨。删除前提取仍需保留的行为及测试；不借迁移重写 Runner、子 Agent、MCP 和工具执行内核。

## 唯一功能验收清单

本表来源于旧源码盘点，不代表新 Client 已验收。新交互以 ProductDefine 为准；原型中的示例和占位不能作为正式完成依据。

| 功能组 | 必须保留／落实 |
|---|---|
| 项目与会话 | 原生目录选择、按工作区分组、新建／复用空会话、切换、首条消息自动命名 |
| 聊天操作 | 发送、实时输出、直接 Steer、停止及子任务停止；无等待队列 |
| 历史与恢复 | 加载历史、刷新／重连恢复、不重复不乱序；结果不明请求不自动重发 |
| 消息展示 | Markdown 清洗、图片、最终回答、三级过程、工具配对、完成／失败／停止状态 |
| 输入区 | Agent、模型与思考合并菜单、图片选取／粘贴／预览／移除、模型看图能力提示、真实上下文用量 |
| 辅助操作 | 复制、从已完成回答分叉、`/` 命令及 Skill 候选、`$` Skill 候选、执行 compact |
| Agent 设置 | 新建、编辑、删除，名称／执行类型／系统提示词／工具；默认与使用中 Agent 的删除保护 |
| 外观与导航 | 亮／暗／跟随系统、侧栏、页面切换、草稿保留、窄屏、键盘焦点与减少动态效果 |
| 辅助工作区 | 与聊天平级、开关／调宽、空态选择及标签创建／切换／关闭；文件／浏览器／终端内容仅未接入提示 |

不迁移旧演示产品、面板 demo、快捷模板 demo、昵称 demo、Dock 计数器或页面插件登记框架。真实编辑器、浏览器、终端和专用子任务面板不在本轮。

## 保留但待确认范围的后续方向

以下来自原计划，未取消，也不自动塞入七步任务：

- Wails 复用 React 与 WS；唯一后台的启动／发现、窗口退出与显式关闭后台。
- 服务端反向请求、待回答恢复、一次有效回答、无人回答时只暂停依赖它的任务；停止后的旧回答不可推进新一轮。
- 业务操作 ID 防重与完整多 Client 协调；两个 Client 不重复推进，旧操作不误伤新一轮。JSON-RPC ID 不作为业务防重 ID。

正式实施范围需用户确认。未确认前不得擅自增加上述能力；现有并发、取消、慢连接与恢复保障不能以缩小范围为由删除。若本轮真实流程暴露必须解决的跨轮次或并发缺陷，先举证并由 Codex 明确本步处理边界。

## 最终验收与收口

- 全量 Go test / vet、相关 race；Go / TS 手写契约逐项对照，TS 类型检查、前端测试及生产构建。
- 隔离数据与本地模拟模型完成真实网络验收：发送、极快完成、Steer、停止、重连、慢连接、后台重启和关闭；不使用用户真实会话代替测试数据。
- 浏览器按功能表检查真实功能，以及亮暗、宽窄屏、键盘、工作过程和长工具输出。记录执行过的检查，不宣称未经验证的结果。
- 确认旧 POST / SSE、Templ、HTMX、页面插槽、演示插件及专属依赖均不再进入启动和构建链。
- 完成事实写 STATUS，稳定边界写设计书／DATA_MODEL／WEB_UI；迁移完成后删除本轮施工文档，未完成的后续方向先转入其实际计划，不遗失承诺。
