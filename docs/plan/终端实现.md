# 浏览器终端实现

目标：在右侧辅助工作区打开多个真实 Git Bash 终端。浏览器只负责显示和输入，进程始终运行在 Go 后端。

```text
xterm.js → WebSocket / JSON-RPC → appserver → machine-local → Git Bash + PTY
```

## 已确认方案

- 学习 Codex 的 `command/exec`，不让浏览器调用 Agent 的 `exec_command / write_stdin` Tool。
- Agent 进程与 UI 终端各管自己的生命周期，只共享 machine-local 的底层 PTY 和进程树实现。
- UI 终端属于当前 Client 连接；断线或关闭标签时终止，重启后不恢复。
- 终端输出是临时状态，不进 Session 账本，也不写入 `~/.harness`。
- 首版只启动当前工作区中的交互式 Bash，不提供 Shell 选择、分屏和终端恢复。

## 对外 RPC

沿用 Codex 命名：

| 方法 | 用途 |
|---|---|
| `command/exec` | 使用 Client 提供的 `processId`、工作目录和行列数启动 PTY |
| `command/exec/write` | 写入 Base64 编码的键盘字节，或关闭 stdin |
| `command/exec/resize` | 更新 PTY 的 `rows / cols` |
| `command/exec/terminate` | 终止整个进程树 |
| `command/exec/outputDelta` | 服务端实时推送 Base64 输出 |

`command/exec` 在进程退出后返回 `exitCode`；输出先通过通知持续发送。进程身份按 `ConnectionID + processId` 隔离。

首版不照搬 Codex 的 `sandboxPolicy`、`permissionProfile`、环境覆盖、输出捕获和超时配置；Harness 暂无对应需求。

## 第一步：补齐底层 PTY

- 保留现有 Agent `ProcessSystem`，不改 Tool 参数和行为。
- 在 `kernel/machine` 增加供富客户端使用的低层进程句柄契约：启动、输出、写入、Resize、Terminate、等待退出。
- machine-local 复用现有 Git Bash、xpty 和 Windows Job Object，实现可指定初始尺寸的独立 PTY。
- 进程句柄不进入 Agent 的进程表；由调用者负责生命周期。

## 第二步：实现 appserver CommandExec

- 新增连接级 `CommandExecManager`，登记上述 4 个 RPC 和 1 个通知。
- `command/exec` 启动输出转发；write、resize、terminate 通过同一控制通道串行处理。
- Client 断线、Server 关闭或命令请求取消时，终止进程并等待收尾。
- 慢 Client 沿用现有通知队列策略：断开连接，不能阻塞进程读取。
- Go 与 `clients/contracts` 手写契约同步；不进入 Product，也不进入 Host 服务表。

## 第三步：接入辅助工作区

- 使用 `@xterm/xterm` 和 `@xterm/addon-fit` 实现 `TerminalView`。
- 在现有辅助视图列表登记“终端”；支持多标签，新增时不修改编辑器和 Diff 组件。
- 键盘输入走 write；`ResizeObserver + FitAddon` 计算行列后调用 resize。
- 关闭终端标签时调用 terminate；隐藏整个辅助面板不关闭已有标签。
- 进程退出后保留终端内容并显示退出码，用户再手动关闭标签。

## 验收

- 能同时打开两个终端，目录均为创建时的当前工作区。
- `bash`、交互输入、ANSI 颜色、全屏程序和中文显示正常。
- 拖动辅助区后终端立即适配，不出现错行。
- 关闭标签、刷新页面和关闭 Harness 后没有残留进程树。
- Agent 的 `exec_command / write_stdin` 行为保持不变。
