# React Web 产品定义（待实现）

本篇作为正式迁移的产品基准，原型为 `prototypes/web`，不再另起一套设计；确认与交付事实见 STATUS.md。正式功能仍待迁移，示例数据和占位能力不算实现。唯一功能验收清单与施工顺序见 [Web迁移计划](Web迁移计划.md)。迁移完成后，将稳定规则收口到设计书与 WEB_UI.md。

## 1. 目标与视觉组织

- React + TypeScript + Vite 接替旧 Web；保留正式功能，不照搬旧 Templ、HTMX、SSE 或页面插件框架。
- 视觉与代码统一、好维护、可读性清晰。借鉴参考截图的留白、层级和按需展开，不照搬其全部功能。
- 设计 Token 统一颜色、字体、间距、圆角等，通过 Tailwind 映射供组件使用；页面不各自硬写一套视觉参数。
- 亮暗主题切换同一套语义 Token。公共组件统一样式和交互，页面组合组件表达业务；真实重复才提取，不做万能组件框架。
- 改视觉参数改 Token，改同类交互改组件；布局变化仍需修改布局，不承诺所有改动只动 Token。
- 采用 shadcn/ui 基础组件与 Stone 暖灰配色作为首稿基准，按需引入，不 clone 整套应用模板。配色接入统一语义 Token，不在业务页面另配颜色。
- 字体采用系统字体栈，兼顾中文；默认跟随系统亮暗主题。布局、留白与信息密度以原型验收，不把“使用组件库”等同于自动好看。
- 字号统一五档：辅助 caption 12、操作 label 13、正文/输入/工具详情 body 14、分区 heading 18、页面 title 24（默认像素等效值，实际使用 rem）。对应默认行高为 1.5 / 1.5 / 1.7 / 1.4 / 1.3；现有 shadcn 字号类也映射到这套 Token，不在页面另定字号。
- 图标统一使用 Lucide；React 使用 lucide-react，按需导入并通过受控图标入口使用。统一尺寸和描边，不混用多套图标、Emoji 或手画替代品；纯图标按钮提供可访问名称。

## 2. 页面与辅助工作区

```text
应用外壳
├── 左：项目／会话侧栏
├── 中：聊天页或设置页
└── 右：独立辅助工作区
```

- 辅助工作区本轮要设计和实现外壳，内容先空着，不填假文件、假终端或旧演示插件。
- 三个区域平级；辅助工作区从应用顶部贯穿到底，有自己的顶栏，不挂在聊天页或聊天标题栏下面。中间切换会话、聊天或设置，不影响辅助工作区的开关与宽度。
- 无标签时显示文件、浏览器、终端的选择入口；选择后创建并激活标签，顶栏“＋”可继续创建。标签可切换、单独关闭，全部关闭回到选择入口。收起工作区只隐藏，不清空标签；原型刷新不保留标签，内容仅标明尚未接入，不伪造真实能力。
- 外壳提供展开、收起与调宽；首次默认收起，本机记住开关与宽度。宽屏与聊天并排，窄屏打开为可关闭的覆盖层。
- 未来认真接入编辑器、浏览器、终端及其他功能；这些内容不因预留位置而自动纳入本轮迁移。
- 原型完整、真实能力分批。预留布局不等于预建通用插件框架或对应后台。
- 侧栏按项目分组，可折叠；顶部“打开项目”选择目录，每个项目旁“＋”新建会话，组内按创建时间倒序。历史项目目录已移动或删除时，“＋”要求用户重新定位真实目录，不静默猜测路径。
- 侧栏底部进入独立设置页，左侧栏目、右侧表单，包含外观与 Agent 设置；返回聊天保留草稿和运行状态。

## 3. 输入区

```text
┌──────────────────────────────────────────┐
│ 图片缩略图（有附件时出现）                │
│ 输入消息……                               │
│                                          │
│ ＋  Agent ▾           用量  模型 · 思考 ▾ │
│                                  发送操作│
└──────────────────────────────────────────┘
```

- 模型和思考档位合用一个菜单，不使用两个独立选择器；菜单展示所选模型支持的档位。
- 上下文用量放在模型／思考入口左边，不能放右边。
- 图片、Skill／命令候选按需展示；候选菜单与其他菜单共用视觉规则，不强行合成万能组件。
- Enter 提交，Shift＋Enter 换行；中文输入法选词时不触发提交。
- 不做等待队列：运行中输入不能在任务结束后自动发送或启动下一轮。
- 闲时 Enter 发送，运行中 Enter 直接 Steer，不做上方确认条。有内容时显示提交箭头，运行中提示“发送以调整当前任务”，独立保留停止按钮。
- “停止中”与后台确认结束后的“已停止”分开显示。
- 断线自动重连，保留草稿与当前画面，暂停发送、插话与停止操作；同步后台状态后恢复操作，不自动重发结果不明的请求。断线不等于后台任务停止。
- 草稿按会话保存在前端内存，切换会话或设置页不丢失；不承诺刷新、关闭页面后恢复。

## 4. 消息区：三级展开

**运行时展开工作过程，完成后自动收起；最终文本回答留在过程区域外。** 此决定替代旧文档中“工作过程始终默认收起”的设计，不沿用旧行为。

```text
⌄ 工作过程                           第一级：整轮过程
  我先检查相关代码……                 对用户的进展说明

  ▸ 已读取多个文件、运行命令          第二级：连续工具组

  找到问题了，接下来修改……           新的进展说明

  ⌄ 已编辑文件
    ▸ 已修改 server.go
    ⌄ 已修改 connection.go           第三级：单个动作详情
      ┌─────────────────────────┐
      │ 工具参数、结果或输出    │
      │ 限高，内部滚动          │
      └─────────────────────────┘

最终回答：不属于上述可折叠区域。
```

- 工具组默认收起，摘要说明正在做或已做的动作；展开后逐条查看工具调用，每个动作还能展开详情。
- 连续工具归为一组；出现真正对用户的进展说明时结束上一组，不跨说明合并，也不按 API 请求次数机械切组。
- 工具列表与单个详情限制高度，长内容内部滚动，不把完整输出铺满聊天区。高度与滚动体验通过原型确认。
- 正常完成统一自动收起最外层，即使用户正在查看详情也收起，之后可重新展开。折叠只是界面状态，不删除记录或改变账本。
- 失败和停止保留工作过程展开，显示明确状态，不能冒充成功回答；无最终正文时不把过程文字强当最终回答。
- 生成中的正文先在过程内展示，正常结束才移出最终正文，不重复显示。子任务回报、压缩摘要在过程内以具名折叠入口展示。
- 向上阅读历史或打开工具详情时暂停自动跟随；点“回到最新”或回到底部后恢复，不抢用户的阅读位置。

## 5. 推理、进展说明与工具必须区分

```text
推理／思考摘要   模型分析，不等同于对用户说话
进展说明        面向用户的文字，例如“找到问题，接下来修改”
工具调用        实际动作及其返回结果
```

- 工具之间出现推理内容，不应因此切断连续工具组；真正的进展说明才是工具组的分隔边界。
- 不能根据“文字在工具前面”就断定它是推理，也不能把所有文字都当进展说明；适配不同模型接口时保留内容类别。
- 接口提供的思考文本或摘要作为工具组内的折叠项，按顺序展示，点击才展开；无工具时独立显示该入口。不承诺取得接口未开放的原始推理，不伪造不存在的思考内容。
- 连续工具组可能跨越多次模型调用。自定义工具由应用执行并回传结果，模型可以继续调用工具、说明进展或给出最终回答。
- Responses API 可在工具调用之间保留推理上下文，但这不等于公开推理全文，也不决定前端如何折叠。此 UI 设计不以更换模型接口为前提。

依据：[OpenAI 推理模型说明](https://developers.openai.com/api/docs/guides/reasoning)、[工具调用说明](https://developers.openai.com/api/docs/guides/function-calling)。参考截图用于确认交互效果，不作为 Codex 内部实现的证据。

## 6. 原型交付与默认细节

- 先交付可交互 HTML 原型，使用示例数据与状态切换演示空会话、生成、完成、失败、停止和断线；不连接真实模型、不执行工具、不修改用户会话。
- 空页使用简短引导，错误就地提示，不叠加无意义弹窗。
- 尺寸、调宽范围、工具限高、断点及视觉细节由实现者提供统一 Token 默认值，通过原型查看后调整，不再逐像素提前拍板。
- 原型是视觉与交互基准，不是后台实现；正式 React 实现仍需验收可访问性、状态恢复与后端行为。
