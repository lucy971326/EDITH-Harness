# App-server 与多产品计划

2026-09-07 · 产品方向已定，尚未实施；技术细节另行验证。

## 1. 架构

**产品组织业务，插件组装服务，app-server 统一接入，Client 按需适配。**

```text
                各种 Client
                     ↕
                 app-server
          公共连接管理 + 对外功能登记处
              ↕              ↕
       HarnessProduct    WolfProduct（未来）
         通用 Agent         游戏业务
              ↘              ↙
          共用服务 + 产品专属服务
          由插件安装到同一个 Host
```

- 保留 Go 静态插件内核和产品扩展，不做动态加载或插件市场。
- 产品各管业务、数据和完整界面；共用 Runner、模型、工具等服务，不把游戏状态塞进聊天账本。
- 统一应用入口，取消页面内部 UI 插槽；app-server 传数据，不传页面组件。
- Host 属于整个后台，产品不另建小 Host；公共接口可直接接入所属服务，不必经过 HarnessProduct。
- Web 采用 React + TypeScript + Vite，不用 Next.js，替换 Templ／HTMX 页面方案。TS 写法直白、类型明确，少语法糖和类型技巧；普通 TS 管通信与状态，React 主要负责显示，保留必要的 JSX／Hooks。
- Vite 构建的静态文件用 Go embed 打进二进制；用户运行时不需要 Node.js。桌面用 Wails 承载同一套界面，版本待定。
- HarnessProduct 首版只迁移已有业务功能，不加新功能；不保留旧 UI 插槽和演示插件作为迁移目标。
- 不兼容、不迁移旧数据，允许从新数据开始；此决定不授权现在删除旧文件。
- 迁移期间允许不可用，不维持新旧双轨；以迁移后的结构清晰、已有功能完整为目标。

## 2. 一份契约，一个事实来源

```text
Go 契约：接口名、输入、输出、错误、事件、需要回答的交互
                         ↓
          登记时绑定处理函数，形成可用接口
                 ↙                  ↘
         运行时功能目录          生成 TS 类型／Schema
```

- 同一个事实只手写一次，其他地方引用或生成；不另外手写功能清单和客户端类型。
- Client 查询目录，只调用、订阅已适配的功能；可以只实现任务列表与查看。
- 后台服务按需共用；对外接口由代码登记，已登记默认可用，Client 需要什么拿什么。先靠开发规范约束，不加逐接口开放开关或复杂权限配置，也不自动暴露内部方法。
- 未知功能忽略，错误调用明确报错；适配范围不等于访问权限。
- 契约不自动生成完整 UI，类型生成也不代替运行时参数校验。
- 借鉴 Codex 的强类型契约、类型生成和双向请求，不照搬协议内容；运行时产品功能目录是我们的设计。Go → TS 方向已定，生成库未定。
- 消息采用标准 JSON-RPC 2.0：请求／响应、通知、服务端反向请求；保留 `jsonrpc` 字段，功能发现接口自己定义。
- Go 通过 HTTP 提供页面，WebSocket 承载 JSON-RPC；Wails 首版复用 WebSocket，不另做 IPC／Streams 适配。Client 逻辑与传输分离，未来有需要再扩展通道。

## 3. 接入与运行

- app-server 管连接、初始化、请求响应配对、事件订阅、提问回答中转和断线清理；业务实现与数据仍归所属服务。
- app-server 统一保存待回答请求，负责发送、回答配对与重发；业务服务负责为什么提问、回答是否合法、之后怎么继续。不让每个产品重复实现问答中转。
- 首版单用户、本机多 Client，仅监听本机回环地址；不做跨设备接入、多人账号、数据隔离或逐接口权限配置。本机连接校验方式由实施方案确定。
- 列表简要状态统一更新；任务详情、文字增量和待回答问题按查看需要订阅，离开任务取消详情订阅。不照搬 Codex 的新会话全端自动附着。
- 各端平等，可查看、发送、插话和停止，不设主客户端。后台统一协调操作并核对任务／轮次，旧操作不能误伤新一轮。
- 同一问题只接受一次有效回答，其他端收到已处理通知后收起问题；借鉴 Codex 的配对机制，但不省略业务校验。
- 发送按后台接收时的状态处理：闲时开始新一轮，忙时插话；明确点停止才取消。不做下一轮队列，保留启动与插话的独立边界，未来按真实需求增加排队。
- 产品登记对外接口；新增产品不修改公共核心的产品分支，也不直接暴露 Host 服务表。
- 通过本地应用启动入口自动启动后台或连接已有后台，不重复启动；Web 由本地启动程序打开，普通网页不承担拉起进程的职责。
- 后台独立常驻，退出界面不停止任务，另设明确的“关闭后台”操作；长期任务 context 由服务管理，不绑 HTTP 请求。
- 谁启动谁负责取消、收尾和等待退出。
- 无人回答默认继续等，不自动代答；只暂停依赖答案的执行，其他任务照常。业务可自行规定超时，停止任务则旧问题失效。
- Client 重连恢复历史、当前状态和待回答问题，再接续事件，不漏不重。
- 后台重启：未完成任务标记中断，不自动续跑；保留已落盘记录，旧问题失效，继续需用户明确发起。

## 4. 接下来的工程工作

**待研究：** Wails 版本、Go 类型生成工具、登记与版本规则、本机连接校验、后台启动与发现、重连同步、并发操作与有效回答的一次性交付、分步实施与测试方案。

**验收：** 新产品独立登记；契约一致；自动启动不重复；多端按需订阅、不串任务、不重复推进；断线继续、无人回答等待、重连恢复、停止收尾、重启中断；已有业务功能迁移完整。
