# Subagent 系统

尚未实现。Subagent 是平台的异步委派功能，Tool 只是模型调用它的入口。

## 职责与流程

```text
父 Run 的 Loop
    |
spawn / send / wait / stop 工具  接收参数、返回结果
    |
Subagents 服务              管理父子关系、结果、消息投递与等待唤醒
    |
同一个 Runner               启动、执行、取消与收尾
    |
子 Run --> Loop             独立工作，拥有自己的 Session
```

- `spawn` 启动孩子后立即返回任务 ID，不等孩子完成；父子可以同时工作。
- 父任务通过工具追加要求、查询或等待结果，也可以请求停止孩子。
- Subagents 不执行 Loop；所有父 Run、子 Run 都由同一个 Runner 管理。
- 子任务状态与待投递记录在对话账本之外；孩子的完整过程只进自己的 Session。父账本记录相关工具调用、结果及已接收的协作消息，明确标注来源，不冒充用户输入。
- 页面等其他入口也可调用 Subagents，不必经过 Tool。不新增通用 jobs 或第二套运行器。

## Agent 与会话设置

Agent 设置定义“怎么工作”，不是正在运行的 Agent。父子每次启动都使用各自的 SessionSettings，再读取选中的 Agent 设置。

```text
同一个 Runner
    +-- 父 Run <-- 父 SessionSettings --> 选中的 Agent 设置
    +-- 子 Run <-- 子 SessionSettings --> 选中的 Agent 设置
```

- `spawn` 可指定已有的 `agentID`；不指定时继承父 Run 使用的 Agent ID。
- 孩子使用选中 Agent 的 Kind、提示词和工具配置，不为每个孩子新建 Agent 设置。
- 模型、思考档位、工作区默认继承父 Run 的设置。
- 父 Agent 能查询已有 Agent 的 ID 和用途；指定不存在的 Agent 时明确报错，不偷偷替换。

## 多次交流与完成通知

借鉴 Codex V2 对“通知”和“触发工作”的区分，不照搬其整套实现。

- 父给孩子追加要求：复用同一个子 Session；忙时通过 Steer 在检查点接收，闲时启动新 Run。这是 Harness 的交互规则。
- 孩子完成：平台保存结果并向父投递通知，不要求每条通知单独启动一轮。

```text
孩子完成 --> 结果通知 --> 父会话
                           +-- 正在工作：按接收时机读到
                           +-- 正在等待孩子：唤醒继续
                           +-- 已经结束：保存通知，不强行开新轮
```

“等待孩子”与“已结束”必须明确区分；等待不等于保持模型请求运行。协作消息允许暂存，不因此为普通聊天增加通用排队功能。

## 停止与重启

- 用户停止父会话：父子都停止，待处理通知不得自动重启父。单独停止孩子不停止父。
- 应用重启：保留历史、结果和待投递记录；未完成运行标记“已中断”，不自动执行。
