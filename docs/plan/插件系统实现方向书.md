# 插件系统实现方向书

## 目标与顺序

让 Harness 成为插件的宿主：插件安装后，其能力由 Harness 发现、授权、启用和执行，而不只是把插件目录展示在页面上。

```text
第一阶段：扩展 Harness 的 Agents、Hooks、Commands → 能承载插件
第二阶段：接入 Composio → 提供网站连接器与账号授权
第三阶段：适配 Codex 插件 → 翻译、核对并报告兼容情况
```

严格按这个顺序推进。Composio 是连接器来源，不代替插件宿主；Codex 插件适配是最后的输入适配层，不倒过来规定 Harness 的内部运行模型。Skills 与 MCP 已有实现，第一阶段将它们接入插件来源，不重做一套平行系统。

## 当前起点

- Agent 由 `internal/agents` 管理用户设置，每轮 `Prepare` 形成运行快照；还没有插件提供的 Agent 来源。
- Hook 由 `internal/hooks` 管理全局／项目命令，目前只有 `PreToolUse`，在宿主执行，可拒绝本次工具调用。
- Command 由 `internal/commands` 在启动时登记，现有契约是按名称立即运行；`/` 菜单只是 Client 入口。
- Skills、MCP 已按作用域发现；MCP 工具进入统一 Tool 登记处，仍经过 Harness 的权限与审批。
- 设置分类的静态登记只负责页面组织，不等于运行时插件容器。

## 第一阶段：让现有能力接受插件

先用一个最小的 Harness 原生插件打通安装、启用、运行、禁用和卸载，再确定包格式与持久化字段。插件记录来源、版本、所含能力及启用状态；重复名称、缺文件、损坏包和升级失败必须有明确结果。插件文件与用户的授权／启用状态分别归属，不写进会话账本。不要预建通用服务容器或无法验证的扩展点。

### Agents

让插件提供的 Agent 与用户自建 Agent 一起出现在选择列表，但标明来源并保持各自的编辑、删除规则。每轮仍从确定的 Agent 与工具集生成快照；插件禁用、删除或升级不能悄悄改变已经开始的 Run。名称冲突与引用失效要能解释和恢复。

### Hooks

让 Hook 支持插件来源，并保留当前工具权限、审批、取消与工具结果配对规则。先接入已有的 `PreToolUse`；其他事件按真实需求逐个定义触发时机、输入、输出、失败处理与信任边界，不因外部插件声明了事件就假装支持。插件携带可执行脚本时，展示其权限与来源，按实际执行内容或固定版本建立信任；禁用插件后不再启动其 Hook。

### Commands

让插件命令参与名称登记和 `/` 发现，并处理来源、冲突、禁用与卸载。先区分“立即执行的平台命令”和“把提示词送入对话的命令”：现有 `Command.Run` 只表达前者，不能直接用它冒充后者。命令仍走相应的会话顺序、权限与取消路径，不让 Client 独自执行业务。

### 复用现有 Skills 与 MCP

插件中的 Skills 接入现有发现机制；插件中的 MCP Server 接入现有工具、信任和审批通道。插件禁用时移除其后续可见能力；已启动资源由创建者关闭并等待。插件所声明的工具不能绕过 Harness 的权限与审批或提升会话权限。

**阶段验收：**用一个 Harness 原生测试插件分别提供 Agent、`PreToolUse` Hook、立即执行命令、提示词命令及 Skill／MCP 中适用的内容。验证安装与禁用后的可见性、运行中禁用的边界、冲突／坏包／失败安装的恢复，以及 Hook 取消和审批不被绕过。只为真实故障路径补必要测试。

## 第二阶段：接入 Composio 连接器

Harness 的“连接器”页面负责展示服务、连接状态和可用工具；Composio 负责它所提供服务的账号授权与工具执行。Harness 后端保管调用 Composio 所需的密钥和会话引用，通过 MCP／服务 API 调用；第三方账号的 OAuth 凭据由 Composio 管理，前端不接触密钥。按用户身份隔离连接，明确授权、断开、过期、撤销和服务不可用时的状态。所有实际工具调用继续进入 Harness 的工具权限、审批与结果账本路径。

先挑一个需要 OAuth 的服务完成“展示 → 授权 → 调用 → 断开 → 重连”的闭环。实施前核对 Composio 当前 API、费用、授权页面品牌能力、数据处理边界与服务可用性；不把托管服务可用等同于 Harness 本地能力。连接器是插件可依赖的一种能力来源，但不与插件身份强行合并。

**阶段验收：**不同用户不能互用连接；未授权、令牌过期、用户撤销和 Composio 不可用时均有可恢复提示；Harness 的审批仍能拦截连接器工具调用。

## 第三阶段：Codex 插件适配

读取 Codex 市场与插件包，先生成兼容性报告，再允许安装。适配器将外部声明对应到 Harness 已实现的 Agents、Hooks、Commands、Skills、MCP 与连接器；保留来源、版本和许可信息。Codex 的 `.app.json` 引用 OpenAI 平台已注册连接的 ID，不能照搬为 Harness 授权；只有找到对应的 Harness 连接器并核对所需工具和参数，才能完成映射。

外部插件可能使用不同的命令语义、Agent 配置、Hook 事件、工具名或参数。对每项能力分别给出“可直接使用／需要转换或配置／暂不支持”，不默默丢弃，也不因清单解析成功就显示为可用。需要改写的内容生成明确的适配结果；无法安全等价执行的内容保持禁用。先以少量真实 Codex 插件校验，再扩大范围；Claude Code 可在同一宿主能力成熟后另做来源适配，不属于这一阶段的完成条件。

**阶段验收：**至少覆盖一个纯 Skills／MCP 插件和一个含连接器或 Hook 的插件；验证安装报告、实际调用、权限边界、更新与卸载。不能适配的条目在市场中说明具体原因。

## 暂不提前决定

- 插件包的最终文件格式、在线市场来源与发布流程：第一阶段用真实插件验证后确定。
- 插件提供自定义设置页面或任意前端代码：当前设置分类只是静态页面登记，先不开放动态 UI 执行。
- Codex／Claude 所有 Hook 事件的逐项兼容承诺：以 Harness 实际支持的事件和权限语义为准。
