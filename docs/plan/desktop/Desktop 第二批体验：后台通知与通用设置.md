# Desktop 第二批体验：后台通知与通用设置

状态：代码已实现；Windows／macOS 原生通知、页面视觉与首批关窗／托盘行为仍待实机验收。

## 目标

```text
新审批 / Run 成功或失败
          ↓ 开关开启，Harness 失焦
Web：浏览器通知     Desktop：Wails 系统通知
          ↓ 点击
     唤回并打开对应会话
```

- 设置导航新增「通用」，内部只有「外观」和「通知」；将现有独立「外观」入口并入。两端共用页面、控件与 Token。
- 通知默认关闭，Web 与 Desktop 各自保存开关；授权状态每次从浏览器或系统读取。用户在设置中开启时才请求权限；拒绝或不支持时说明原因，不自动反复请求。
- 仅在窗口隐藏、最小化或应用失焦时通知**新出现的人工审批**和 **Run 成功／失败**；主动取消不通知。初次订阅与重连不补发旧通知，同一审批或 Run 不重复提醒。
- 系统通知只显示通用文案，不展示会话标题、工具参数或正文。点击后打开对应会话，审批仍在 Harness 内回答；目标已失效时回到工作台并提示。切换页面遵守未保存草稿保护。

## 接入与边界

- Web 使用浏览器 `Notification` API。仅在标签仍打开、连接正常时提醒；关闭标签后不做 Service Worker 或后台推送。复用现有全局审批订阅，新增只推送所有会话 Run 终态的只读 RPC 订阅，响应含 `subscriptionID`，事件含 `subscriptionID`、`sessionID`、`runID`、`status`；Go／TS 契约同步。
- Desktop Go 接入层直接订阅后台的审批快照与 Run 事件，异步、有界地调用 Wails 通知服务，不依赖隐藏 WebView 的定时器。通知失败不能阻塞或改变 Run 结果；注销订阅、关闭队列和通知服务由创建者负责。点击回调通过现有平台桥唤回窗口并交给共用 UI 导航。
- 共用 UI 只负责设置与目标导航；`clients/web`、`clients/desktop` 分别实现通知能力。后台仅暴露只读事件，不引入浏览器或 Wails 依赖。两端的开关作为各自本地偏好保存；Desktop 启动时先禁用通知，待前端恢复偏好并同步给 Go 后再启用。
- Wails 通知服务初始化失败不能使应用无法启动。macOS 裸二进制或授权被拒时，设置页显示不可用状态，其他功能照常使用。

## Windows／macOS 交付与验收

- Windows 用正式 `.exe` 验证 Toast 送达、点击定位、关窗入托盘与单实例唤回。
- macOS 正式构建生成带固定 Bundle ID 的 `.app`，本机用临时签名供通知实机验收；开发模式裸二进制仍须能启动。分发签名、公证、安装包和自动更新不属于本批。
- 覆盖关闭开关、失焦判断、审批新增与撤销、Run 成功／失败／取消、初次订阅与重连去重、通知发送失败、点击已删除会话、授权拒绝与各端偏好独立。完成代码后统一运行一次 `make agent-check`；原生通知和页面视觉再用三端正式构建交互验收。
