# Desktop 首批体验：单实例、窗口恢复、后台驻留

## 目标

再次启动 Harness 时唤醒已有 Desktop 窗口；重启后恢复窗口布局；关闭窗口时保护运行任务、终端和未保存内容。共用 React UI 与现有业务 RPC 保持不变，原生行为由 Desktop 接入层负责。

## 关键改动

1. **单实例**：在 `backend.Open` 取得数据目录锁之前创建带 `SingleInstanceOptions` 的 Wails 应用。第二次启动只恢复并聚焦现有窗口；若窗口尚未就绪，记录唤醒请求并在就绪后执行。Web 已占用数据目录时仍显示现有启动冲突窗口。
2. **窗口恢复**：Desktop 在 `~/.harness/desktop/window.json` 保存位置、普通尺寸和最大化状态。移动、缩放后防抖写入；最大化不覆盖普通尺寸。启动时按当前显示器工作区校正位置与尺寸；文件缺失或损坏则居中使用现有默认尺寸。启动错误窗口不读写这份偏好。
3. **关闭与托盘**：Wails 关窗钩子向共用 UI 请求当下状态，Runner 提供只读的“是否有活 Run”判断。**有活 Run（含子任务），或有打开的终端标签时，点关闭直接隐藏到托盘**；任务结束后仍留在托盘，托盘提供“显示窗口”和“退出”。再次启动也能唤醒隐藏窗口。
4. **未保存内容**：没有上述活动时，汇总所有主会话与子任务聊天草稿、编辑器未保存文件、设置草稿及保存中状态。无内容则退出；有内容用现有确认弹窗提示“继续编辑／放弃并退出”，保存中暂不允许退出。托盘“退出”和系统退出入口走同一保护流程；若仍有活 Run，确认退出会先停止并等待收尾。
5. **故障退路**：前端未就绪或未响应关窗请求时，使用原生确认框提供退出路径，避免窗口无法关闭。Linux 托盘无法保证可见，首版不自动隐藏窗口，改为明确提示保持窗口或确认退出。新增简洁的 Harness 托盘图标，并同步 Desktop 使用说明、`DATA_MODEL` 与 `WEB_UI`。

## 验证

覆盖第二次启动及启动期唤醒、窗口偏好损坏与显示器变化、运行准备期和子任务运行时关窗、终端标签关窗、各类未保存内容、托盘恢复与显式退出。完成代码后只运行一次 `make agent-check`，再构建一次 Desktop 二进制；窗口和托盘交互由 Desktop 实机验收。

## 已定行为

- 运行中关窗：**直接后台**。
- 仅终端标签开着时关窗：**直接后台**。
- 无运行任务但有未保存内容：**退出前提示**。
- 不新增草稿持久化；此轮不做通知、安装包或自动更新。实现后先交付改动与验证结果，不自动提交。
