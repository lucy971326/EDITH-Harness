## 0. 一句话认识这个项目

用 Go 重写 DeepSeek 开源 agent 框架（dsh，TypeScript）的对应物：**一个小而稳的内核 + 一切能力靠插件**。module 名 `harness`，Go 1.25.5，纯标准库、零第三方依赖、单二进制、静态编译。

进度：**M1-M5 完工，M6 待做**。当前工作区 117 个测试 `go test -race -count=10 ./...` 全绿。

施工方式是里程碑制：每一节先读计划书 → 写代码 → `-race` 全绿 → 用户 review → 用户说"提交"才 commit。

## 2. 核心理念（五条命根子）

所有代码决定最终都回到这五条。遇到没写过的情况，拿这五条裁决。

### ① 内核做小，做完不改

内核一共就几个包：`core`（场地）、`chat`（词汇）、`session`（账本）、`llm`（插座排）、`tools`（流水线）、`loop`（搬运工），加上 M5 的 `files`/`process`/`shell` 和 M6 的 `cmd/dsh` 组装。**M6 做完 = 内核完工，之后一切新能力都是插件，内核不再为新能力改一行代码。**

### ② 账本是唯一事实源

`session` 包记的账（事件流）是整个系统唯一的事实：

- 模型看到的对话历史 = 从账本**算出来**的，不单独存；
- UI 显示 = 账本的另一种算法；
- 崩溃恢复 = 把账重放一遍；
- 上下文压缩 = 追加一笔摘要事件（带 `Replaces` 声明"我取代了哪几笔"），旧账不删；
- **验收红线：模型收到的每个字节都能从账本重建。**

账本规矩极硬：只增不改；编号从 1 连续；落盘要么整条要么没有；危险操作（调模型、执行工具）之前必须 `Flush`（把攒的账写穿到硬盘）。

### ③ 宁可说不知道，不可自动赌

工具执行到一半崩溃（账上有 `tool/start` 没有 `tool/result`）= 副作用可能已经发生（邮件可能已发出）。此时**绝不自动重跑**（赌错 = 双发），也**不卡死等人**——自动补一笔"结果不明"的账给模型，让模型自己决定重做还是问人。这条是用户亲自拍板的"路线 2"，详见 `失败边界与恢复状态机.md`。

### ④ 插件只依赖接口，不依赖实现

所有能力挂在公共能力表上，键是**能力名**不是插件名：`"llm"`、`"tools"`、`"agents"`、`"sessions"`、`"approval"`。谁提供实现随便换（本地换沙箱、DeepSeek 换 OpenAI），用的人无感。

### ⑤ 显式优于聪明

- llm 不设默认插座就报错，不猜；
- 工具要问人（ask）但没人挂 `"approval"` 能力 = 拒绝执行，不默默放行；
- 插件安装中途失败 = 逆序回滚已启动的，不留半装状态；
- `Resolve[T]` 查不到就报错，类型不对直接 panic（编程错误就该炸）。

## 3. 拍板过的重要决定（完整清单）

每条都定过了，**不要重新发明**。要翻案必须先问用户。

### 3.1 架构裁决

| # | 决定 | 理由 |
|---|---|---|
| 1 | **不做**：动态加载插件、热重载、AI 自我修改、Web 前后端分体 | 静态编译单二进制，可控可测 |
| 2 | 事件分发有四种，**各自失败语义不同**：`Broadcast` 崩溃隔离（观察者炸了只记日志）/ `RunChain` 错误上抛 / `RunSequentially` 出错中断 / `RunConcurrently` 聚合所有错误 | 不许一刀切 |
| 3 | `Broadcast` 是同步分发，不起 goroutine | 防流式输出触发 goroutine 风暴；要异步的监听器自己声明 |
| 4 | 服务表键 = 能力名，不是插件名 | 换实现不影响消费方 |
| 5 | 作用域 = 子 `App`：`ForAgent` 派生、同名遮蔽、`Restrict` 只能裁继承来的、子事件上浮到父的观察者（不下沉）、子 `Close` 后整批消失 | 给每个 agent 定制工具集和人格的方式 |
| 6 | `chat` 包是中立词汇表（Message/Attachment/ToolCall/ToolResult/Usage/Delta/ToolSchema），`session` 和 `llm` 都用它，**两个包互不依赖** | 谁也不借谁还没写出来的类型 |
| 7 | 多模态：`Message.Media []Attachment` 留了口子（图片/音频输入）；**生图/生视频是将来插件的事，不在内核** | 内核只管词汇，不管能力 |
| 8 | `llm.Adapter` 只有**一个**方法 `Stream`；非流式 = 不吐 delta 的特例；ctx 取消翻译成 `cancelled` 错误 | 适配器只需实现一种形状 |
| 9 | 统一错误七种 Kind：network / rate_limit / auth / bad_request / server / cancelled / unknown | 消费方可编程处理 |
| 10 | 工具执行是**九步流水线，顺序冻结**（见 §4.5），改顺序 = 破坏性变更 | 顺序本身就是契约 |
| 11 | 控制位（守卫/审批/重试）挂在 tools 的公共链上，**不是**各工具自己实现 | N 个工具 × M 种控制：挂公共路径写 M 次，挂工具里写 N×M 次 |
| 12 | 审批是**可选插件**（挂 `"approval"`，实现 `Approver` 接口），内核不内置问人 | 内核不该知道"人" |
| 13 | 工具表两层：全局 + 按 agent（同名遮蔽），`DropAgent` 清理防泄漏 | 见决定 5 |
| 14 | 每种账本事件**只归一家记**：`session` 提供 14 个专用 `Record*` 方法；公开的 `AppendEvent` 只许插件记自定义 Kind | 防记错格式 |
| 15 | 投递和领出是**两笔账**：消息先记 `inbox/deliver` 再入队，领出时再记 `inbox/claim`，**领出才变成进模型的 user 消息** | 崩溃恢复只重放未领出的，消息不双份不丢失 |
| 16 | 忙时碰撞：`Steer`（中途话）挤进当前轮下一步；`SubmitFollowup`（新话）排队，本轮收尾后才开新轮；`InjectMemo`（小抄）立刻入账但不唤醒、不占待办 | 用户终审过的语义 |
| 17 | 崩溃后"有 start 无 result"的工具调用 → **自动补 `tool/result{status:"unknown"}`**，正文写给模型的决策指引；不自动重跑、不卡死 | 路线 2，用户拍板 |
| 18 | `loop` 本身是插件，可整体替换；UI 只认 `"agents"` 能力（Roster），不知道 loop 内部长什么样 | 门面模式 |
| 19 | `session` 是**必装的第一个插件**：`session.Plugin` 用注入的 Journal 创建 Store 并登记 `"sessions"`，消费者统一用 `session.Get(app)` | 插件化不等于可选；账本是地基，但 Journal 实现可以替换 |
| 20 | 事件里 `SkipIfUnknown` 字段：true = 写这笔的插件将来没了就跳过；false = 整本账拒读 | 宁可过严 |

### 3.2 代码风格裁决（全部在 AGENTS.md，这里点重点）

- **err 的获取和判断不许写同一行**：先 `err := f()`，下一行 `if err != nil {`。用户反复强调，违者重写。
- 禁止花里胡哨的语法；**要全局可读性**，不是单个函数的可读性。
- 方法名自解释动词（`SubmitFollowup`/`ExecuteCall`/`AppendEvent`）；包名领域词；不发明概念名（Kernel/Ledger/Fiber/Realm 出现即毙）；避开标准库撞名。
- 一包一个公开构造；插件 = 结构体 + `Start(app)`，不用闭包式插件；闭包只做无状态包装。
- 注释：结构体一句话说组合了什么 + 核心字段标注角色（小能力/身份/长期配置）；函数 = 输入+输出+一句话干嘛+失败语义；内部注释纯中文；言简意赅不滥用。

### 3.3 流程裁决

- 每节动工前**先读对应计划书**。
- `go test -race` 全绿才算完工。
- **完成不自动提交**：用户 review 后说"提交"才 commit。
- commit 说明**双语**：第一行中文摘要（50 字内），空一行，正文英文（干了什么/为什么/怎么验的）。用 heredoc `git commit -F -` 防 shell 引号事故。
- 跟用户说话：**大白话，禁黑话**；问什么答什么，一句话答完不扩展。她看不懂就等于没说。

## 4. 代码地图（逐文件）

```
harness/
├── core/       场地：谁都能来的公共大厅
├── chat/       词汇：对话的数据形状
├── session/    账本：发生过的一切
├── llm/        插座排：调模型的统一口
├── tools/      流水线：模型的手
├── loop/       搬运工：不知疲倦的主循环
├── workspace/ 工作空间能力（这三个都不是插件）
│   ├── files/     Store 接口 + Get(app)
│   ├── process/   Spawner / Handle 接口 + Get(app)
│   └── shell/     借任意 process 跑完一条命令
├── localenv/  本地文件 + 本地进程实现，一次装上面三块
└── (M6 将加 cmd/dsh/)
```

工作空间这条依赖也是单向：`core ← workspace/files`、`core ← workspace/process ← workspace/shell`；`localenv` 只负责组装三者。

### 4.1 core/（零依赖，不懂任何 agent 知识）

| 文件 | 职责 | 关键符号 |
|---|---|---|
| `core/app.go` | `App` 结构：服务表/监听器表/中间件表/任务表/清理栈；`New()`；`Plugin` 接口（`Name()` + `Start(app)`）；`Install`（按序启动，失败逆序回滚）；`RegisterService`（重名 panic）；`Resolve[T]`（缺了报错、类型错 panic）；`OnCleanup`；`Close`（逆序清理、清表、幂等、崩溃隔离） | `App`, `Plugin`, `Install`, `Resolve[T]`, `Close` |
| `core/events.go` | 四种分发（`Broadcast`/`RunChain`/`RunSequentially`/`RunConcurrently`）；`Subscribe`/`Intercept`/`RegisterTask`；`RunChain` 是洋葱折叠，中间件拿 `next(P) R` 可改写载荷和结果 | `Listener`, `Middleware[P,R]`, `RunChain` |
| `core/scope.go` | `ForAgent(name)` 派生子作用域；`Restrict(names...)` 裁继承；`Parent()` 访问器 | `ForAgent`, `Restrict` |

`Message{Role, Text, Interrupted, Media []Attachment, Calls, Result}`、`Attachment{Kind, URL, Data, Mime}`、`ToolCall{ID, Name, Argument}`、`ToolResult{CallID, Output, Status}`、`Usage`、`Delta`（流式一小截）、`ToolSchema{Name, Description, Parameters []byte}`。

### 4.3 session/（账本）

| 文件 | 职责 |
|---|---|
| `session/types.go` | `Event{Kind, Seq, Time, Data json.RawMessage, Replaces []int, SkipIfUnknown bool}`；`Header{FormatVersion=1, ID}`；14 个内核 Kind 常量：`user/message`、`assistant/chunk`、`assistant/final`、`tool/call`、`tool/start`、`tool/result`、`turn/start`、`turn/end`、`step/start`、`step/end`、`inbox/deliver`（带 Target）、`inbox/claim`、`request/snapshot`（存当年真发的 `llm.Request` JSON）、`summary`；各 Data 结构；`ResultSuccess/Failed/Skipped` 常量 |
| `session/journal.go` | `Journal` 接口：`Create` / `Append(id, event, durable)` / `Flush(id)` / `ReadAll`。规矩：要么整条要么没有；durable=true 成功返回前必须真到硬盘；**真文件版（JSONL+fsync+烂尾修复）是 M6 的活**，现在只有 `MemoryJournal` |
| `session/codec.go` | 事件格式注册表：每种 Kind 登记 modelVisible（进不进模型历史）/ kernel（只许专用方法记）/ decode；`isDurable`：chunk 以外全部立刻落盘 |
| `session/session.go` | `Session`：14 个专用记账方法（`RecordUserMessage`/`RecordChunk`/`RecordAssistantFinal(final, replaces)`/`RecordToolCall`/`RecordToolStart`/`RecordToolResult`/`RecordTurnStart-End`/`RecordStepStart-End`/`RecordDeliver(id,text,target)`/`RecordClaim`/`RecordSnapshot(requestJSON)`/`RecordSummary(data,replaces)`）；广播：`EventAppended="session/appended"`，负载 `Appended{SessionID, Event}`；插件自定义事件在广播回调里走 `AppendEvent` 会被拒（`ErrInBroadcast`），要改用 `AppendLater`；内核专用记账碰上另一笔广播时会排队等待；`ModelHistory()` 给 loop 算出模型视角历史 |
| `session/plugin.go` | `Plugin`：必装的第一个插件；注入 Journal，创建并登记 `"sessions"`；`Get(app)` 统一取 Store |
| `session/history.go` | 历史缓存：有效名单（被 Replaces 收编的旧笔不再算数）+ 增量重算（只有收编发生才全量 rebuild）；chunk 攒缓冲、`assistant/final` 到达时收编 flush |
| `session/store.go` | `Store`：`NewStore(journal, broadcaster)`；`Create(id, seed...)`（seed 非空才触发恢复）；`Get`；`replay` 重放校验（seq 连续 + Replaces 合法 + 逐笔写盘） |

**`session` 是必装的第一个插件**。安装顺序是 `session.Plugin` → `llm.Plugin` → `tools.Plugin` → `loop.Plugin`；不能省略 session，但 Journal 实现可以替换。

### 4.5 tools/（九步流水线）

| 文件 | 职责 |
|---|---|
| `tools/types.go` | 四条链名：`PreExecute="tools/pre-execute"`、`Execute="tools/execute"`、`Guard="tools/guard"`、`PostExecute="tools/post-execute"`；`Tool{Schema, Execute}`；`Call{ID, Name, Argument, Agent}`；`Result{Output, Status}`；`ResultUnknown="unknown"`；`Decision{Kind, Reason}`（allow/deny/ask）；`Approver` 接口（挂 `"approval"`）；`Outcome{Output, Err}` |
| `tools/registry.go` | 两层表：`Register`（全局）/ `RegisterFor`（按 agent，遮蔽全局）/ `Lookup`（先 perAgent 后 global）/ `Schemas`（遮蔽时说明书也换）/ `DropAgent` |
| `tools/pipeline.go` | **九步，顺序冻结**：① `RecordToolCall`（记不上就不跑）② 前置链（allow/deny/ask）③ 问人（ask → `Resolve[Approver]`，没人挂 = 拒）④ 守卫链（只能拒，返回拒因字符串）⑤ `RecordToolStart`（执行边界，只记一次）⑥ 环绕链 + 本体（重试插件可重跑本体不重走流水线）⑦ 后置链可改结果 ⑧ panic 兜底成 failed（进程不倒）⑨ 终局入账。**唯一不记终局的出口 = 已开跑被取消**：返回 `ResultUnknown`，账上留 start 无 result，交给恢复流程。`runScopedChain` 递归折叠让链跨作用域聚合（父层在外） |
| `tools/recover.go` | `RecoverDangling(book, callID, status, note)`：恢复专用补账窄口，外部不许直接碰 session 记 tool/result——保持"每种事件只归一家记" |
| `tools/plugin.go` | `Plugin`（注册 `"tools"`）+ `Get` |

### 4.6 loop/（搬运工，Actor 形状：私有状态 + 收件箱 + 单 goroutine 串行）

| 文件 | 职责 |
|---|---|
| `loop/inbox.go` | 三条投递通道：`TargetNextTurn`（开新轮队列）/ `TargetNextStep`（中途话队列）/ `TargetMemo="context"`（小抄盒，不响铃不占待办）；**投递先 `RecordDeliver` 落账再入队**（崩溃不丢）；`takeNextTurn`/`takeNextStep`/`takeMemos`；`restore`（恢复时把未领投递放回队）；`pending` 只查前两条（小抄不算活） |
| `loop/agent.go` | `Agent` 门面：`SubmitFollowup`/`Steer`/`InjectMemo`/`WaitIdle`（sync.Cond，同时看 busy、working 和队列，搬运工已接活但还没开轮也不算空闲）/ `Cancel`/`State`/`Book`/`Close`（停搬运工 + `DropAgent` + 关作用域）；`AgentConfig{Model, SystemPrompt}` |
| `loop/driver.go` | 主循环：领消息 → `runTurn`（claim 变 user 消息 → turn/start）→ `runStep` 步循环：`step/start` → 领中途话和小抄 → 组装 `llm.Request`（系统提示 + 小抄 system + 账本投影历史）→ `RecordSnapshot`（存当年真发的请求 JSON）→ **`Flush`（问模型前的危险边界）** → `Stream` 边吐边 `RecordChunk` → `RecordAssistantFinal`（收编 chunk，seq 列表当 Replaces）→ 没工具调用就收步，有就逐个过九步流水线 → 直到没活。取消善后：已吐字固化 interrupted 定稿；`stepOpen` defer 兜底补 `step/end`。`Checkpoint="loop/pre-step"` 是预留位还没用 |
| `loop/recover.go` | `recoverFromLedger`：扫旧账一遍——未领投递回队并唤醒；有 start 无 result 的调用经 `tools.RecoverDangling` 补 unknown（正文：操作断在半路、结果不明、你自己判断要不要重做、拿不准先问我）；无 start 的补 skipped（断在开跑前，可以直接重试）；悬空 chunk 固化成 interrupted 定稿；缺的 step/end、turn/end 补上 |
| `loop/roster.go` | `Roster`：挂 `"agents"`；`Create(id, config, seed...)`（seed 非空 = 带旧账恢复）/ `Get` / `Drop` / `CloseAll` |
| `loop/plugin.go` | `Plugin`：Resolve `"sessions"`/`"llm"`/`"tools"` 三个依赖（缺谁报谁）→ `NewRoster` → 注册 `"agents"` + `OnCleanup(CloseAll)` |

### 4.7 workspace + localenv（工作空间能力 + 本地插件）

| 文件 | 职责 |
|---|---|
| `workspace/files/store.go` | 只放 `Store{Read, Write, List}` 接口、`Entry` 和 `Get(app)`；不碰本地磁盘 |
| `workspace/process/types.go` | 只放 `Spawner.Spawn/Close`、`Handle`、`Command`、`Exit` 和 `Get(app)`；不启本地进程 |
| `workspace/shell/runner.go` | `Runner.Run`：用 Spawner 起进程、立即关 stdin、同时排空 stdout/stderr、等退出；两路输出各自截断，不切出半个 UTF-8 字符 |
| `localenv/files.go` | 本地 `files.Store`：只接受根目录下的相对路径，写时创建父目录 |
| `localenv/process.go` | 本地 `process.Spawner`：每个进程单独建进程组，ctx 取消或 Spawner/App 关闭时杀整组；`Wait` 可重复读同一结果 |
| `localenv/plugin.go` | `Plugin{Root, OutputLimit}` 用同一个 Root 造出本地 files/process，再成对登记 `"files"` / `"process"` / `"shell"`；本地构造函数不对外公开 |

当前是为看清心智主干做的 macOS/Linux 本地直连版，根目录不是沙箱。

## 6. 与 dsh 参考源码的关系

`reference/deepseek-harness/` 是 DeepSeek 开源的 TypeScript 原版。**只许看、不许抄**（`reference/说明.md` 原话：不可直接使用）。我们已经对照它审查过一轮（M2 时），有价值的差异都已吸收。它和我们最大的不同：它是动态插件 + YAML 配置层叠 + agent 运行时可自写插件；我们是静态编译、手写组装、明确砍掉运行时自写插件。

## 8. 陷阱清单（我们踩过的坑，你别再踩）

| 坑 | 现象 | 规矩 |
|---|---|---|
| 广播回调里记插件自定义事件 | 直接 `AppendEvent` 会被 `ErrInBroadcast` 拒绝；曾因递归排水爆栈 | 改用 `AppendLater`；别把 `appendLocked`/`broadcastAndDrain` 的拆分合回去 |
| Go 方法不能带类型参数 | `func (a *App) foo[T]()` 编译不过 | 用包级泛型函数（`core.Intercept`、`tools.runScopedChain` 都因此是包级） |
| 空结构体指针全指向同一地址 | 测试里 `&fakeRegistry{}` 指针比较失真 | 假对象加个 tag 字段 |
| WaitIdle 早退 | 搬运工刚把队列领空、还没正式开轮时，外面误以为已经干完 | 除了 busy 和队列，还要看搬运工是否已经接活（`working`） |
| 按字节切汉字 | `Output[:100]` 切出烂字节，JSON 编码变 � 还多两字节 | 用 rune 切 |
| 同一 App 重复 RegisterService | 直接 panic（设计如此） | 第二个场景用子作用域遮蔽 |
| commit message 里的引号断 shell | `"outcome unknown"` 掐断命令 | 用 heredoc：`git commit -F -` |
| `docs/主要心智模型 ` 目录名尾随空格 | 路径写错找不到文件 | 复制路径时带上空格 |
| RecordDeliver 带 Target 参数 | 改签名后旧测试编译失败 | 改公开记账方法签名要全项目 grep 一遍调用点 |
