# 交接文档 —— edith-harness

> 最后更新：2026-08-25。Project → Session → Agent 模式重构、Web UI 第二版与“模式/模型分离”均已完成，尚未提交；TUI 暂停。

## 一句话认识项目

edith-harness 是一个 Go 写的静态插件化 Agent 框架：`core.App` 保管能力，插件把能力登记进去或领取别人的能力，账本是对话和恢复的唯一事实。

## 当前核心模型

```text
Project：一个工作目录
  └─ Session：一段独立对话
       ├─ 锁定一个 Preset 版本
       └─ Runtime Agent：真正运行对话，ID = Session ID
```

- Project 管工作目录和它的会话。
- Preset 是可复用的 Agent 模式：只保存人设和工具白名单；模型属于会话，可随空闲时切换。
- Preset 修改时只追加新版本。旧 Session 恢复时仍用创建时的版本。
- agents 不存档案，只负责组装、恢复和关闭运行中的会话。
- loop 是可替换 Runner，负责模型 → 工具 → 模型的主循环。

### 模式和模型：不要再混在一起

```text
Preset（Agent 模式）     = 人设 + 可用工具
llm.Selection（模型选择） = 服务商 + 模型 + 思考档位（空值表示服务商默认）
Session                  = 锁定的 Preset 版本 + 可变化的模型选择
```

- **任何模式都能用所有已安装模型**；创建或编辑模式时，绝不出现模型、服务商或思考档位字段。
- 第一条消息会锁定 Preset 版本，之后不能换模式。
- Session 空闲时可以换模型；下一轮生效。运行中拒绝切换，避免一轮对话前后混用模型。
- 每个 Project 记住自己上次选用的模型，新草稿优先沿用；从未选过时取已安装目录里的第一个模型。

## 能力表

`core.App` 内部的能力表本质是 `map[string]any`。字符串是抽屉名，值是实际服务。插件之间最终都是通过 Go 接口方法合作。

| 能力名 | 类型 | 用途 |
|---|---|---|
| `project-store` | `projects.Store` | 保存项目 |
| `preset-store` | `presets.Store` | 保存不可变模式版本 |
| `journal` | `session.Journal` | 保存会话事件 |
| `sessions` | `*session.Store` | 创建和打开账本 |
| `llm` | `*llm.Service` | 模型适配器插座与模型目录 |
| `tools` | `*tools.Registry` | 工具登记和执行流程 |
| `environment` | `environment.Provider` | 按 ProjectRoot 挂载会话环境 |
| `projects` | `projects.Service` | 项目管理入口 |
| `presets` | `presets.Service` | Agent 模式管理入口 |
| `agents` | `agents.Service` | 会话运行入口 |
| `ui` | `ui.Service` | 界面启动入口 |

`files`、`process`、`shell` 不再是全局能力。每次启动 Session 时，`environment.Provider` 会把一套新实例挂到该 Session 的子 App，因此多项目并行不会串目录。

## Session v4 封面与模型选择

```go
type Header struct {
    FormatVersion  int
    ID             string
    Title          string
    CreatedAt      time.Time
    ProjectID      string
    ProjectRoot    string
    PresetID       string
    PresetRevision int
}
```

ID 是自动生成的内部身份，Title 可重复。会话封面同时是它恢复时的组装说明书。

`model/selected` 是 v4 新增的追加事件，内容是 `Provider`、`Model`、`Thinking`。新会话首次发送前先记一笔；之后每次成功切换也记一笔。恢复时取最后一笔，所以重启不会忘记模型。旧 v3 会话仍可浏览；它没有这类事件时，Web 必须先让用户选模型才允许继续发送。

## 启动和组装

`compose.Open(home)` 读 `~/.harness/config.yaml`。当前格式是 version 2：

```yaml
version: 2
plugins:
  project_store: projectjson
  preset_store: presetjson
  journal: jsonl
  llm_adapters: [deepseek]
  environment: localenv
  tool_plugins: [files]
  runner: loop
  ui: web
```

安装顺序固定：

```text
项目存储 → 模式存储 → 账本 → session
→ llm / adapters → tools → environment / tool plugins
→ projects → presets → agents → runner → UI
```

YAML 只能选择已编进程序的大零件；不做动态插件、热更新或自动依赖排序。

## 账本和恢复红线

- 事件只追加，历史、模型上下文和 UI 都从账本计算；`model/selected` 记下每次模型切换。
- 危险操作前必须 Flush。
- 工具未开跑就取消：`skipped`。
- 工具已开跑却没有结果：恢复为 `unknown`，禁止自动重跑。
- 记账走同步 Journal；事件广播只通知观察者，永不落盘。

## 已锁定的取舍

- 静态编译，不做动态插件、AI 自改、热重载或通用 RPC 网关。
- 旧 `agents/` 档案与 v2 Session 不迁移，开发期直接干净升级。
- ProjectRoot 本轮不支持修改；目录移动视为新项目。
- 归档 Project 不删工作目录或历史账本。
- Web 的新会话草稿不创建 Session、不写账本；首次发送时才调 `agents.StartSession`。

## Web UI 第二版

- `uiplugins/web` 已是默认 UI：templ + HTMX + Tailwind，服务只监听 `127.0.0.1:8080`。
- 左侧是 Project → Session 树；`＋ 新会话` 与 `＋ 添加项目` 永远可用。聊天区从 `sessions.Read` 只读账本，不会为了查看历史启动 Agent。
- 左栏两个全局动作永不消失：`＋ 新会话` 只在当前 Project 建空草稿，`＋ 添加项目` 随时可打开系统目录选择框。项目名永远取所选工作目录名，用户不手填。
- 首次发送才调 `agents.StartSession` 并锁定 Preset；旧会话再次发送时调 `agents.OpenSession`，由 agents 决定是否交给 loop 恢复。**Web 不直接调用 loop。**
- `session/appended` 通过非阻塞 SSE 刷新当前会话；慢浏览器不会挡记账。
- 添加项目时 Go 后端弹 macOS 原生目录选择框，目录名自动成为项目名；已有模式创建/修改/归档、工具过程、排队消息、发送与取消。聊天页先预留“对话 / 轨迹”导航，但轨迹内容仍未实现；暂不做附件、分页和模型密钥编辑。
- 模式页只编辑提示词和工具。聊天输入框右侧提供“模型与推理等级”组合选择器：模型按服务商分组；推理档位严格跟随当前模型目录，只有该模型声明支持服务商默认时才显示 `Default`。草稿在发送时带入选择，已存在会话切换后立即写 `model/selected`。

## 给后续 Agent 的工作边界

- 当前工作区有一整批**未提交**改动；先看 `git status` 和 `git diff`，不要 `reset`、不要清理、不要覆盖未跟踪的 `uiplugins/web/`、`package.json` 或计划文档。
- 改动模型能力时，优先改 `llm.Selection` / `llm.Service`，不要把模型字段塞回 `presets.Revision`。
- 改动会话模型时，必须同时维护：`projects.LastModel`（新草稿默认值）、`model/selected` 账本事件（恢复事实）、Web 输入框（用户选择）。
- 改动 Web 后必须同步更新 `docs/Agent对接/harness-live-map.html`；这个约定是用户明确要求。
- UI 只用浅色、留白、弱边框的产品界面；参考 DSH 的信息层级，不复制其代码、素材或页面。TUI 已暂停，不要顺手继续修或扩展。
- 所有发送路径仍经 `agents`，由 `agents` 交给已登记的 Runner；不要为了页面方便让 Web 直接依赖 `loop`。

架构图在 `docs/AGent对接/harness-live-map.html`，每次增加真实模块后都要同步维护。
