# 架构与重要决策

当前能力见 [STATUS](AGENTS/STATUS.md)，开发约束见 [AGENTS](../AGENTS.md)，数据细节见 [DATA_MODEL](AGENTS/DATA_MODEL.md)，界面约定见 [WEB_UI](AGENTS/WEB_UI.md)。

## 主干与取舍

```text
cmd/harness / cmd/harness-desktop → backend：构造 → 登记 → 逆序关闭
                                        ↓
React → WebSocket / Wails Stream → appserver → conversations → Runner → Loop / Tools
                                      └→ 模型 / Agent / Skills / 审批 / Hooks
```

- 单一 Go module，后台按领域归 internal，具体实现放领域子包；contracts 不反向依赖实现，由入口接线。目录嵌套不增加运行层级。
- 删除 Host 服务表和 Product 层：当前只有一个产品，用明确依赖与会话操作入口代替运行时查服务；保留 Tools／Skills 等真实登记处。
- 状态按进程、会话、本轮、步骤归属。保留必要锁与快照，不重复存可推导值，不用万能容器或嵌套结构掩盖复杂度。
- 固定本机文件存储，领域负责格式与恢复，persist 负责可靠读写。不预留 SQLite，也不兼容旧架构数据。
- 资源创建者负责失败清理和取消／关闭／等待；先关接入层，再逆序关运行服务，单项错误不跳过其余清理。

## 接入与会话操作

Web 的 HTTP 提供静态资源，业务经 WebSocket；Desktop 在 Wails 窗口加载同一份 React 构建产物，通过 Wails v3 Stream 传业务消息，不开放业务 TCP 端口。两端传完整 JSON-RPC 2.0 消息，共用 appserver 的连接、初始化、方法表、订阅与断线清理，以及手写 TS 契约；Wails 不另建业务 API。桌面 Stream 每帧是一条完整消息，沿用 16 MiB 上限；发送受阻时限时关闭连接，不拖住后台收尾。

前端只有 `clients/main.tsx` 一个入口和 `clients/dist` 一份产物，由 `clients/assets.go` 嵌入供两端加载；npm 依赖与 Vite 配置统一在 `clients`。`clients/ui` 保存共用页面、RPC、草稿和投影；入口一次选择平台，注入 `openSocket()`、`openExternal(url)`，两端适配器不保存会话状态。

Go 传输对称放在 `clients/web` 与 `clients/desktop`；appserver 的 `connection.go` 只接收通用消息流，不拥有 HTTP 监听。Web 入口先关闭监听与升级后的连接、等待请求收尾，再关闭 appserver 和后台；Desktop 由 Wails 管窗口与流，appserver 统一清理 RPC。Web 保留回环／Origin 校验，HTTP 关闭同时取消已升级连接的读写，不能只关闭监听器。

Web 与 Desktop 分别启动后台，但共用 `~/.harness`。启动前取得跨进程文件锁，同一时间只允许运行一个后台；锁随服务关闭或进程退出释放。

appserver 管接入、类型校验、分发、订阅与连接清理；conversations 管会话操作；公共服务直接接入 appserver，不经 conversations 转发。Connection 不拥有业务事实。协议封套由 sourcegraph/jsonrpc2 处理，不另造 Batch 或边角兼容层。

- 方法显式登记，组装时编译 Schema，失败不开放监听；Go／TS 手写契约需同步审查。
- 本机仅监听回环地址、校验浏览器 Origin、先初始化协议版本；不加临时鉴权。远程接入另行设计身份认证。
- 同会话设置、发送、分叉与命令有序，不同会话并行；等待 Steer 落账前释放会话操作锁，Stop 独立执行。
- 发送统一通过 conversations.Send；闲时发送启动一轮，忙时直接 Steer，不建下一轮队列。expectedRunID 指定插入哪轮，不匹配返回冲突，不能退回启动新轮。
- 已接受的 Run 不继承连接 Context；关闭窗口只清理订阅。请求 ID 仅配对响应，没有业务防重 ID 时不自动重试副作用操作。
- 订阅先监听、再快照、响应后放行通知；按 updateSeq 排序，跨 seqEpoch 重建。缓冲有界，慢连接断开，不能反压 Runner。

协议字段与处理入口见 [appserver](../internal/appserver/README.md)，不在本篇复制接口目录。

## 一轮执行

```text
Start → 占 live → 读取本轮设置 / Prepare → Loop
                                           ↓
                         模型输出 + 全部工具结果
                                           ↓
                           检查点：Steer / 协作回报
结束 → 保存终态 → 完成资源收尾 → 释放 live → 完成句柄
```

准备期即占 live，可被停止；同一 Session 只有一个活 Run。执行固定为 ReAct，由 backend 构造并直接注入 Runner，不登记或选择执行类型。loops 只定义 Run、输入、事件与检查点契约。Loop 不访问 Runner／Session 内部状态。

一次模型步骤不可插入，检查点按到达顺序取尽输入，落账并发布后才确认 Steer。取消拒绝未落账 Steer；协作回报根据父账本 MessageID 确认，未落账由来源重试。工具调用必须配齐结果，停止后不启动剩余工具。

普通运行停止／失败保存已有正文与思考并标 incomplete；压缩必须正常完成且正文非空才追加 summary，失败不留下半截摘要。压缩复用 Runner 准入，不新增 Loop；完整账本仍可查看。

结束事实先可被 Snapshot 看见，live 保留到收尾完成；重启只把未完成轮次标为 interrupted，不自动续跑。事件只通知，不替代事实或有返回值的调用。

## Agent 与协作

Agent 拥有系统提示词与普通工具；SessionSettings 拥有 Agent、模型、思考档位、工作区和权限模式。每轮读取设置形成快照，Steer 不改配置。默认 Agent 可编辑不可删；新增普通工具不自动加入已有 Agent。

Runner 每轮只读取工作区根目录的 `AGENTS.md`，作为模型可见的项目上下文放在历史之前，不写入 Session 账本；子任务继承工作区并使用同一规则。文件缺失时跳过，读取失败、非 UTF-8 或超过 32 KiB 时拒绝启动该轮。子目录的 `AGENTS.md` 不自动加载。

Skills 与 MCP 按当前作用域发现，不复制进 Agent。Prepare 只提供 Skills 摘要和正文路径，模型按需用已启用工具读取，不暗中开工具。MCP 配置保存后，新 Run 在准备期读取新配置并固定工具定义、调用路由和连接版本；旧 Run 继续使用其已批准的旧版本，结束后释放连接。

Skill 设置只允许修改个人 Harness 目录；项目、`.agents` 和内置来源只读。关闭的个人 Skill 仍占同名发现位置，不回退到低优先级的个人 `.agents` 来源；项目同名 Skill 仍优先。新 Run 读取最新开关，已开始的 Run 不因开关停止。

Subagents 管协作，执行复用 Runner：

```text
父 Session (0) → 子 Session (1) → 孙 Session (2)
                    ↓
        子账本结果 → Runner.Receive → 直属父检查点
```

- 最大深度 2，服务端校验；不建任务队列或第二套执行器，不另限数量／并发。Task 只存关系与委派，状态和结果从子会话投影，投递确认取父账本。
- 孩子不复制父历史；继承父 Run 的 Agent／模型／档位快照，可分别显式覆盖并校验。工作区继承，父子共享文件，不自动创建 worktree。
- 身份来自可信 SessionID／RunID／ToolCallID，不从模型参数取得。接口按直属父 SessionID + TaskID 定位。
- Stop 递归取消目标及后代并覆盖在途派生；正常完成不停止孩子。父闲时不因回报自动启动；关闭视图不停止任务。

## 机器、工具与安全


`llm` 使用 OpenAI 与 Anthropic 官方 Go SDK，独立适配 Chat Completions、Responses 和 Messages，把流转换成 Harness 事件；SDK 类型不外泄。开发脚本从 models.dev 生成供应商／模型快照，显式补足协议和思考参数映射；普通构建与运行离线使用快照。供应商名单采用 Pi 的 OpenAI／Anthropic 入口，其他专用协议排除；混合网关在模型定义中记录协议差异。各家兼容供应商共用协议，不为每家建立适配包。用户配置只保存覆盖和隐藏项，已知模型自动提供上下文、最大输出、视觉与思考档位；不看图的模型由产品入口拒绝图片发送。内置账号通道仅保留 ChatGPT（PKCE、Codex Responses）和 xAI（设备码、Responses），端点固定；其他供应商使用 API Key。授权与协议分离，凭据先持久化再使用。思考签名和加密续接数据随助手消息保存，仅同供应商、模型和协议可重放。目录不保证账号权限，第三方订阅接口稳定性未获公开承诺。

`machine` 统一机器能力，契约在 `internal/machine`，本机实现位于 `internal/machine/local`，由入口显式构造。`AgentProcesses` 是 Agent 的长期进程能力视图，负责进程、PTY、增量输出、会话归属与关闭清理；`AgentFiles` 提供批量文件修改。Agent 入口必须接收可信 Policy，用户文件与终端使用直接操作入口。工作区是 SessionSettings 里从哪开始，不是另一种机器。

长期进程只存在 machine-local 内存，使用 JSON 安全的大空间随机 ID；最多保留 64 个，单进程未取输出采用 1 MiB 头尾缓冲。进程交付 ID 后跨 Turn 存活，Harness 关闭时按进程树终止并等待收尾。`exec_command` / `write_stdin` 只是 Agent 入口，负责 Bash 参数、等待范围、输出预算和文本呈现，不保存第二份进程状态；`process_id` 与聊天 SessionID 分开，内部仍用 SessionID 校验归属。

同一份 `machine` 通过 `FileSystem` 能力视图供 Tool 与富 Client 共用。appserver 提供 `fs/readFile / writeFile / readDirectory / getMetadata / watch`；内容使用 Base64，编辑器单文件上限 2 MiB，保存必须携带读取时的 SHA-256。监听由 machine-local 使用 fsnotify 实现，按 200ms 合并路径，通过 `fs/changed` 推送并由 `server/unsubscribe` 解除。

`fs/searchPaths({workspace, query})` 复用这份文件能力，只读返回 `{entries: [{path, kind}], truncated}`；路径相对工作区，类型为 `file / directory`。空查询仅列根目录，非空按名称或部分路径做不区分大小写的包含搜索，最多 50 项；从工作区根逐层应用 `.gitignore`，跳过 `.git` 和符号链接，不维护索引或搜索会话。查询受请求 Context 与 5 秒期限限制，失败返回错误而非空成功；普通目录读取不受搜索忽略规则影响。

同一份 `machine` 还通过 `TerminalSystem` 向富 Client 提供低层 PTY 句柄。appserver 的连接级 `command/exec / write / resize / terminate` 负责协议、输出通知和断线清理；UI 终端使用 Client 自定的 `processId`，按 `ConnectionID + processId` 隔离。它与 Agent 的长期进程只复用 Git Bash、xpty 和进程树清理，不共用进程表、Tool 或 Session 生命周期；终端输出不落账也不持久化。

`tools` 是登记处。核心普通 Tool 为 `exec_command` / `write_stdin` / `apply_patch`，都走 machine；不做 grep / find / ls。工具是否开放看 `Allow`，不靠 schema 名单；执行权限另由 permissions 计算。MCP 转成普通 Tool 再填进来，名字 `mcp__<server>__<tool>`；Loop 看不见 MCP。工具用法写在 schema 描述里，不另设工具提示词段。

MCP Server 属于宿主侧进程或远端服务，不进入 Agent 命令沙箱。全局 MCP 配置由用户主动安装；项目 `.mcp.json` 和 `.harness/mcp.json` 在连接前按真实项目路径与解析后的有效配置摘要请求用户确认，批准记录存 `~/.harness/approvals/mcp-trust.json`。项目配置及其引用的环境变量变化后，新 Run 依新摘要重新请求信任；旧 Run 继续使用其已批准的旧连接。项目同名项先覆盖全局项，关闭、连接失败或审批拒绝时均不回退到全局同名项。单个 Server 连接失败只影响自身；设置页读取配置不连接项目 Server，也不触发信任审批。只读模式不发现项目 MCP、不给模型 MCP Tool，调用入口仍拒绝；请求批准和智能审批逐次审核实际 Server、Tool、参数，智能审核不确定时转人工；完全访问直接调用。MCP 审批不扩大文件或网络 Policy，也不把 Server 放进沙箱。

Streamable HTTP MCP 支持本机 Web／Desktop OAuth。普通 Run 只用已有凭据，401 提示登录，403 仅在 `insufficient_scope` 时提示增权；用户在设置页显式启动独立的授权任务，经本机回环回调完成授权码、state、issuer 与 PKCE 校验。预注册客户端优先，其次用户提供的 CIMD，服务不支持 CIMD 时回退 DCR；CIMD 文档需由用户提供可访问的 HTTPS 地址，Harness 不托管，DCR 注册声明刷新授权。授权发现要求 PRM、授权服务元数据与 S256，不接受旧端点猜测。MCP 领域拥有登录任务、私有凭据文件与刷新；Windows 文件内容由当前用户 DPAPI 加密，Unix 限制文件权限。令牌绑定资源、issuer 与已验证的授权／令牌端点；新 Run 固定连接版本，配置撤下时旧 Run 可继续使用原连接，退出登录才阻止旧连接继续调用。项目登录复用整个项目配置摘要信任，确认页列出该摘要涵盖的 Server，但不伪造 Run 身份。

Runner 以本轮设置快照、工作区和可信临时目录调用 `BuildPolicy`，经 Invocation / tools.Call 传递权限，不允许模型参数指定 Policy。命令工作目录不产生额外授权。平台启动方案由本机实现准备；Linux 使用系统 bwrap 的文件视图、namespace 与 seccomp，macOS 使用 Seatbelt，Windows 受限执行尚未实现。缺依赖或无法安全表达策略时明确失败，Full Access 才直接执行。

补丁 Tool 负责解析与计算，实际修改交给 AgentFiles；所有 Agent 写入由同一可执行文件的内部助手完成；受限模式复用命令沙箱，Full Access 直接启动助手。父进程按固定的规范化 key 获取与编辑器共享的路径锁，等待支持取消；文件 I/O 不占用 machine 服务锁。助手做版本检查，返回完成前缀与准确性。已有进程沿用启动时权限，后续交互不接收新 Policy。临时挂载占位按引用与文件身份清理，不删除原有或已填入内容的目录。

`internal/permissions` 是纯规则包。会话模式与实际文件、网络权限分开：`模式 + 工作区 + 可信临时目录 → 基础权限`，明确批准后生成仅属于本次操作的有效权限。前三档允许读取宿主当前用户可读文件；Read Only 默认无写入且禁网，Ask for approval 与 Approve for me 默认工作区和临时目录可写且禁网，仅审核者不同；Full Access 不添加 Agent 文件与网络限制。可写根下的 `.git`、`.agents`、`.harness` 默认受保护，只有明确授权内部路径才能放开，宽泛的父目录授权不能解除保护。规则不解析 Shell 副作用、不替代操作系统隔离。

权限模式归 SessionSettings，默认 `full_access`（完全访问）；新设置保存时确定默认值，读取时缺字段或未知值报错。设置更新省略模式则保留原值，仍只允许闲时修改。分叉复制模式，子会话继承父 Run 的模式快照。人和模型共用 Reviewer 契约，审批服务独立负责请求归属、等待与取消。首版 `PreToolUse` Hook 在工具参数校验后、执行前运行宿主命令；只能拒绝本次工具调用，未表态或故障时继续原有审批与沙箱流程。项目 Hook 按配置文件版本信任，不跟踪脚本内容。审批 Hook 尚未实现；将来若接入，它只能对当前请求作决定，未作决定时继续内置审批。审批故障或取消不能当作批准，批准不修改会话模式。实际隔离由 Agent 执行通道落实，用户编辑器与终端保留原有机器通道。

`internal/approvals` 是独立审批服务。Tool 直接调用 Authorize，统一比较、审核并生成本次权限；人和模型审核沿用 Reviewer 契约，等待复用工具 Context，不创建后台执行队列。命令以 `extra_permissions` 和 `justification` 主动申请；补丁从准备好的目标计算已有父目录权限，审批展示真实开放目录，批准后仍校验预读版本。批准不会关闭沙箱，也不修改会话设置；已有进程保持启动权限。

智能审批由全局设置选择常规 LLM 或 Jev，单次申请取设置快照。常规 LLM 复用公共模型服务；Jev 是独立 HTTP 适配，不混入聊天模型目录。两者使用真实用户授权与完整操作，信息不足或故障转人工，停止直接取消；Jev 的自动批准置信度门槛按已定选择为 0.5。审核无调查工具与独立对话历史，模型分类不替代沙箱。审批服务拥有设置与生命周期，不为两种适配建立插件登记处。

待审批表只在服务内存中，回答与取消原子取走请求。`approval/subscribe` 原子返回快照并转发后续完整列表，`approval/respond` 只接受请求 ID 与决定；断线不取消 Run，重连恢复待审批，重复回答返回冲突。网页属于同一本机用户，订阅全部会话与子 Agent 的请求并显示来源。订阅容量 1 合并为最新列表，传输层沿用有界通知队列与慢连接断开。服务关闭拒绝未完成申请，重启不续跑。

Runner 将权限与审核者传给 Tool；同时把每轮权限说明保存在运行记录，按历史中首次出现的 Run 插入模型输入，相同说明不重复。说明使用明确标注的运行环境 user 消息，兼容忽略历史 system 消息的 Provider；不添加到 Session 账本，不改写旧提示前缀。分叉复制运行记录；压缩后从保留的历史重建权限基线。模型输入的说明不产生授权，真正权限始终来自本轮设置和本次审批。

`exec_command` / `write_stdin` 的单次输出受预算限制。`apply_patch` 使用 Codex 补丁语法，先解析并计算全部目标内容，再按预读版本依次提交新增、修改和删除；上下文失败或文件并发变化时不覆盖，I/O 中途失败则准确返回已提交前缀。更新保留原文件换行风格；相对路径从工作区解析，绝对路径和 `..` 不受限制。普通工具错误回给模型；取消 Run 才终止。

`apply_patch` 将真实落盘变化作为结构化 Delta 交给 Runner。Runner 按 Run 聚合“首次内容 → 最新内容”的净变化，保存 `runs.json` 摘要与 `diffs/<run-id>.json.gz` 完整前后内容，并在每次变化后推送同一份投影。Diff 不进入对话账本，也不追踪编辑器保存或 Shell 副作用。Run 结束后可按文件撤销；revision 与 machine 原子版本检查共同阻止覆盖后续修改。
