# 架构与重要决策

运行约束见 [AGENTS](../AGENTS.md)，当前能力与限制见 [STATUS](AGENTS/STATUS.md)，数据归属见 [DATA_MODEL](AGENTS/DATA_MODEL.md)，界面约定见 [WEB_UI](AGENTS/WEB_UI.md)。这里只记录代码边界背后的长期取舍。

## 主干

```text
cmd/harness 或 cmd/harness-desktop
  → backend 显式装配、登记、逆序关闭
  → clients/web 或 clients/desktop → appserver → conversations
  → Runner → 固定的 ReAct Loop → LLM / Tools → machine 与领域服务
```

单一 Go module；`internal` 按领域组织，不恢复 Host、Product、万能服务容器或旧数据兼容层。`appserver` 负责连接、协议校验、方法登记和通知；`conversations` 负责会话操作；Runner 独占活 Run；Session 只记对话。公共模型、Agent、Skill 等服务直接接到 appserver，不经会话服务转发。资源由创建者负责失败清理和关闭等待。

## 接入与执行

Web 使用回环地址上的 HTTP／WebSocket，校验 Origin；Desktop 用 Wails Stream。两端发送完整 JSON-RPC 2.0 消息，共用 appserver、手写 TS 契约和同一份 `clients/dist`，不为 Wails 再造业务 API。`clients/main.tsx` 选择平台并注入传输、打开网址等能力；`clients/ui` 不感知 Wails。Web 与 Desktop 各自启动后台，但同一份 `~/.harness` 同时只允许一个后台。

同一 Session 的写请求有序，不同 Session 并行；Stop 独立取消。闲时发送启动 Run，忙时按 expectedRunID 插话，不建立下一轮队列。请求连接断开只清连接资源，不取消已接受的 Run；副作用请求不自动重试。订阅先登记、再取快照、响应后释放通知；慢连接断开，不能反压 Runner。Web 关闭时先收传输，再关 appserver。

Runner 在准备期就占有唯一活 Run，完成资源收尾后才释放。一次模型输出及整批工具结果不可插入；检查点按到达顺序落账 Steer 与协作回报。已发出的工具调用必须配齐结果；停止后不启动剩余工具。完整事实先持久化再发布，重启只标记未完成轮次中断。压缩复用 Runner 准入，只有完整非空结果才追加 summary。

每轮读取工作区根目录 `AGENTS.md` 作为模型上下文，不写入 Session 账本；缺失则跳过，读取失败、非 UTF-8 或超过 32 KiB 则拒绝启动。子目录 `AGENTS.md` 不自动加载。Agent 只配置系统提示词和普通工具；固定使用 ReAct，不保留执行类型开关。Subagent 复用 Runner，最多父→子→孙两级；只持久化关系和委派，不复制父历史、不另建任务队列或 worktree。子结果经直属父 Run 检查点落账，Stop 递归取消后代。

## 模型与工具

LLM 适配 OpenAI Chat Completions／Responses 与 Anthropic Messages 官方 Go SDK，统一转换成 Harness 流事件；SDK 类型不外泄。开发脚本从 models.dev 生成内置快照，显式补足协议与思考参数；普通构建和运行离线读取。只纳入 Pi 的 OpenAI／Anthropic 协议入口；兼容供应商共用协议适配，混合网关按模型选协议。用户文件只保存覆盖和隐藏，不把模型目录当账号权限。内置账号仅 ChatGPT（PKCE／Codex Responses）与 xAI（设备码／Responses）；认证与协议分离，凭据先保存再使用。模型思考续接只在同供应商、模型和协议下重放。

`machine` 定义执行与文件契约，`machine/local` 持有本机进程、PTY、沙箱和路径锁。Agent 的持续进程与 UI 终端不共用进程表或生命周期；交付后的进程沿用启动权限。Tool 注册处只开放 Agent 允许的工具；`exec_command`、`write_stdin`、`apply_patch` 通过 machine 执行，MCP 工具也进入统一 Tool／审批路径。`apply_patch` 先解析和预读，再按版本提交；中途 I/O 失败返回已提交前缀，真实文件 Delta 由 Runner 聚合为 Run Diff。编辑器、终端与 Agent 工具共用机器能力，但前两者不经 Agent 权限审批。

权限由可信的本轮设置、工作区和临时目录计算，不接受模型参数指定 Policy。真实用户授权只从可信的 `userAuthored` 消息及其来源追溯；委派文本、模型摘要和未标记消息不能提升授权。Read Only 禁写禁网，Ask for approval 与 Approve for me 默认只写工作区和临时目录且禁网，Full Access 不加 Agent 文件／网络限制；受保护的 `.git`、`.agents`、`.harness` 不能靠批准父目录绕过。Linux 用 bwrap／seccomp，macOS 用 Seatbelt；Windows 受限执行未实现，缺安全实现时明确失败。批准只对当前操作有效，不改变会话模式或已有进程权限。

审批服务独立持有待办与取消；人工、LLM、Jev 审核信息不足或故障时转人工，不用模型判断替代沙箱。`PreToolUse` Hook 在参数校验后、执行前运行宿主命令，可拒绝本次工具调用；配置故障不能当批准。MCP Server 在宿主或远端运行，不进入 Agent 命令沙箱。项目 MCP 连接前以真实路径和有效配置摘要取得信任；项目同名项覆盖全局，失败不回退。旧 Run 固定已批准的连接版本，新 Run 使用新配置。设置页只读查看项目 MCP 不触发连接或信任。

HTTP MCP OAuth 仅在用户显式发起时登录，普通 Run 只用已有凭据；授权核对资源、issuer、端点、state 与 PKCE。凭据由 MCP 领域保护并刷新，不经前端。批准 MCP Tool 不扩大文件或网络 Policy；只读模式不发现项目 MCP 工具。
