# 设计书

本篇只写产品形状和不能改的决策。铁律与写法见根目录 `AGENTS.md`，进度见 `STATUS.md`，数据放哪见 `DATA_MODEL.md`，画面见 `WEB_UI.md`，未做事项见 `docs/plan/future_plan.md`。

参考 DSH / pi，**不照抄**。Go，静态编译，无热加载。

## 1. 根是宿主

进程是一张服务表。聊天是桌上的一摊，不是根。

```text
Host
  整份 A     persist（三把键） / sessions / sessionSettings / agentStore
             llm / machine / agents / runner / chatService
  登记处 B   tools / loops / skills / commands / events / web
```

能换的做成登记处，等人来填。不能换的做成一整份服务。电影只填 `web.products`，不必再占 Host 键。狼人杀、多机器人是验架构的例子，v1 不做。

`RegisterService` / `Resolve`。定义者出契约，提供者装上，消费者 import 定义者，彼此不 import。Host 不叫 `App`。

启动顺序写在 `cmd/harness`，yaml 只选这次启不启动，不能发明还没编译的插件，也不能改顺序。内核每次都 Start，不进 `enable`。persist 包一次挂 `sessionPersistence`、`sessionSettings`、`agentStore`；jsonl / sqlite 是包内选文件。machine 按 yaml 必装一个提供者。v1 改配置后重启。

动手前先问：这是桌上新的一摊，还是聊天里的一份数据、一种画法？工作区、轨迹页、自定义模式都是聊天产品，不改内核形状。

## 2. 一轮对话

```text
闲着再问     ChatService.Start → Runner.Start → agents.Prepare → 用户消息落账 → Loop.Run →（LLM 类）llm.Stream
跑着插一句   ChatService.Steer → Runner.Steer：立刻落账，Loop 在检查点取走
停止         ChatService.Stop → Runner.Stop：取消本轮并收尾
压缩         Runner.Compact：占空闲 live，不是 Loop，不换 Kind
平台命令     commands.Call：按名调用，不经 Agent
```

不要 `Chat.Followup`，不要 Inbox，不要等待队列。`Run(sessionID)`，不加 `appName` / `user_id`。用户拦在 HTTP。

Loop 是一种程序，要编译。登记 Kind 的条件：`Run` 必须取尽 Steer。Loop 启动时自己 Resolve 依赖；`Run` 不碰 Host、Session、Runner。Invocation 只带本轮数据。

活着的 Run 只在 `Runner.live`。同一 Session 同时只能占一次：Start / Compact 互斥。账本只有 Runner 能写。屏幕只听这一轮 `Emit`（浏览器走 SSE），不听账本。耐久事件先 `Append` 再给屏幕，失败则终止 Run。

`Runner.Start` 返回运行句柄，提供稳定 RunID、本轮配置快照、完成信号与最终状态/错误；Chat 对 Web 仍只返回启动错误。先释放 live，再完成句柄，关闭 Runner 会等待后台收尾。运行中的配置查询按 SessionID、RunID 匹配快照，不重新读可变设置，不缓存已结束运行。

Steer 的输入信号只唤醒、不消费消息；待处理输入持续可观察，检查点取走后才换信号代次。ReAct 每次工具调用获取当前信号，随可信 SessionID、RunID 与协议 ToolCallID 传入 tools.Call，不从 Arguments 取身份。初始化不能重复消费 Steer；Compact、已取消或正在关闭的运行不接收 Steer。

`Runner.Receive` 接收带稳定消息 ID 和来源的协作消息，与 Steer 共用检查点和输入广播，按实际父账本去重。启动事件期间接收的消息由 Runner 放入初始 History，进入 Loop 前只消费一次。协作输入先落账再发布现有 Message 事件；落账或发布失败终止本轮，并保留真实错误。运行收尾等待在途协作消息发布结束。

`events` 只通知、不存、不代替有返回值的调用。`RunEvent` 只由 Runner 发布；Loop 内部事件不露出表面。换 Loop 不能迫使 UI 改事件名。

## 3. 谁管什么

```text
Agent            Kind / 人设 / 普通 Tool 勾选（设置页默认折在「高级配置」）
SessionSettings  AgentID / 模型 / 思考档位 / 工作区
Skills           系统 + 个人 + 当前项目，自动可用，不写进 Agent
MCP              个人全局自动加入，项目只在当前工作区自动加入；Agent 不选 Server，也不选小工具
```

`agents.Prepare` 现取 Agent、当前作用域 Skills 摘要、已启用 MCP 说明和工作区，拼成最终 System Prompt。Runner 只拿成品。`Prepare` 与 `/`、`$` 候选共用 `AvailableSkills(workspace)`。

没有 `prompts` 登记处。Skills 正文仍在各目录的 `SKILL.md`，不强制加载，不暗中补开 `read` / `bash`；提示词不得宣称未启用的工具可调用。项目 Skill / 项目 MCP 换工作区才换，不串别的项目。MCP 按现有加载时机生效，改配置重启，不热加载。

Agent 和 SessionSettings 都是实时事实；Runner 每轮读一次，改动影响下一轮，不打断当前 Run。Steer 不改 Agent。`default` Agent 可编辑、不可删除；首次生成时勾上当时全部普通 Tool，之后新增普通 Tool 要人勾。

模型键和思考档位键来自 `kernel/llm/models.json`；API key 在 `~/.harness/config.yaml`。两项都是独立选择，首次发送前必选。`off` 是明确选择，空值是还没选。

## 4. 账本

Session **只记对话**，可以分叉。todo、审批、棋盘、Dock、面板宽度都不进账本。

```text
Entries()   完整账本；聊天区画这份
History()   发给模型。若有 summary，从最近一条摘要起：摘要收成普通文本，其后原样保留
```

块：`text` / `reasoning` / `tool-call` / `tool-result` / `image` / `summary`。字级 Delta 不落盘；进程崩了只丢尚未 Append 的半截。

压缩不是新 Loop。成功条件：正常结束且正文非空，才追加 `Kind=summary`。摘要指令只在内存里，不进账本，为的是保住模型前缀缓存。用户必须仍能看见压缩前的对话。

本轮 System Prompt、时长、token **不写进账本**。用量球听 `usage` 事件，刷新后从 0 开始。

`SessionMeta` 只有 `ID / Title / CreatedAt`。新会话标题「新对话」，首条用户消息落账后自动命名。标题不是消息，不进 `SessionSettings`。

项目 = 按 Workspace 分组的 Session，不是独立数据。

## 5. llm / machine / tools

`llm` 直接调 goai，不自写各家协议。`models.json` 手写 `contextWindow`、`vision`、思考档位的 ProviderOptions。不看图的模型：发给它的 image 块换成文字占位，账本和屏幕仍留原图。

`machine` 是一台机器一把键，不要拆成 shell / fs / subprocess。契约在 `kernel/machine`，提供者挂上之后表上才有这把键。`Run` 只执行 argv；bash Tool 自己变成 `bash -c`。工作区是 SessionSettings 里从哪开始，不是另一种机器。不限制路径。

`tools` 是登记处。v1 普通 Tool：`read` / `write` / `edit` / `bash`，都走 machine。不做 grep / find / ls。权限看 `Allow`，不靠 schema 名单。MCP 转成普通 Tool 再填进来，名字 `mcp__<server>__<tool>`；Loop 看不见 MCP。工具用法写在 schema 描述里，不另设工具提示词段。

`read` / `bash` 回模型最多 2000 行、50 KiB。`edit` 的 `oldText` 必须恰好一次。普通工具错误回给模型；取消 Run 才终止。

## 6. Web

内核一份。Web 和 webview 同一套 templ；TUI 另画；ACP 是管子不是画面。v1 请求 POST，通知 SSE，不用 WebSocket。

`surface/web` 只提供产品、路由、公共设置插槽。**Web 不认识 Chat、Runner、Session。** Chat 是 `plugins/web/chat` 填进去的产品。Chat Web 与其分叉、输入候选、Agent 设置填充物都通过 `chatService` 使用聊天业务；`chat` 键仍只提供页面插槽登记处。

```text
产品     进入哪一摊（Chat / 以后的电影）
页面插槽 只扩展某个产品内部，不在 Host 上另占键
```

Chat 固定：项目/会话、发送/停止、模型与档位。插槽：

```text
message.actions     list   复制、分叉；不内置点赞点踩
dock                list   持续状态，不进 Session
composer.actions    list   只改变输入产生方式
composer.suggestions list  `/` 命令立刻 Call；`$` / `/` 插入 Skill
sidepanel           keyed  Chat 画壳，插件画内容；状态在浏览器
settings.section    Web 公共 Master-Detail
```

分叉：从已完成助手回答复制耐久历史和 SessionSettings，开独立新会话；原会话不动。

消息区走 `surface/web/runview`：ChatService 提供的 History Snapshot 和 SSE 进同一个 `paint()`。JS 不写账本。一张会话一条长期 SSE；`run-ended` 不拆连接。关页面只断 SSE，任务继续；`Stop` / `Runner.Close` 才取消。慢客户端断开，不准卡住 Runner。重连再读 History；未落账的半截 Delta 允许丢。

HTTP 的 Context 管这次请求，不能当 Run 的 Context。

轨迹页是同一份账本的另一种画法，不改 Runner；v1 先做对话气泡。

## 7. 以后做也不改的边界

Subagent：孩子自己一本 Session、自己的 Run；`subagents` 是管理委派关系与协作状态的整份服务，使用 Runner，不直接执行 Loop 或写对话账本。关系、逐轮结果位置与通知由它独立保存，子会话不进入普通聊天列表。重启只恢复记录，不自动执行。

委派工具插件向现有 `tools` 登记处填入 `subagent_options / spawn / send / list / wait / stop` 六个工具（均带 `subagent_` 前缀）。使用 Subagents，不另挂服务、不直接调用 Loop，也不保存自己的运行状态。调用身份来自程序提供的 SessionID / RunID / ToolCallID；模型只填写委派说明、可选设置和目标任务 ID。沿用普通 Tool 权限，安装不会自动给已有 Agent 勾选新工具。

spawn 启动后马上返回；send 忙时 Steer、闲时在原有子会话开启新轮，发生可能已经接收的错误时不盲目重发。list 通过服务读取逐轮最终正文，任务 JSON 仍只存结果位置。

wait 使用 `taskIDs` 等任一指定孩子当前或后续轮次的新完成结果，`seenNotificationIDs` 跳过已见通知；默认 60 秒、允许 0～60 秒。返回 `reason`、当前任务状态 `tasks` 和新完成通知 `notifications`（状态、轮次、通知 ID），不返回正文。等待不保持模型请求；用户 Steer 提前唤醒，取消 Context 结束等待，超时不停止孩子。当前任务进入新轮，也不覆盖此前等待的完成通知。

Subagents 保存完成状态、最终正文位置与稳定通知 ID 后才投递；失败、取消、中断明确标注。父运行中通过 Runner 在检查点接收；最终检查点已关闭则保留待投递，父闲置时不自动启动。下一次用户主动启动父会话时，现有 RunStarted 通知触发投递，首次模型请求前接收。投递确认写盘失败可重试，账本已存在消息 ID 就不再次注入正文。服务拥有通知重试后台与事件订阅，Close 解除订阅、取消并等待退出。

父账本保存平台工具结果及 `role=collaboration` 的带来源消息，不把任务状态当通用记录塞进账本。模型侧按带来源说明的普通输入处理，不冒充用户或系统指令。不新增 `subagent-*` 事件或前端 JS，Loop 里不分叉。Chat 用户停止时父子一起停止的完整接线仍留在第 5 步。

命令是平台能力的门，不是外部能力进来。新命令若需要新内部行为，先改 Runner / Session，插件保持很薄。

扩展开关（个人 Skill / 个人 MCP Server）若以后做：对所有 Agent 生效，不存进 Agent 或 SessionSettings；关 MCP 是不建立连接。现在没有开关 = 已发现的个人来源默认全开。项目来源不受个人开关控制。
