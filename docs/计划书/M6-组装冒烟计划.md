## 职责（一句话）

**把 M1-M5 的零件组装成一个能跑的真程序，并用真实世界完成最终验收。**

> 进度：终端交互闭环、第一轮真实崩溃恢复测试和 `--dump-config` 已实现；真实 API 冒烟仍待人工带密钥验收。

## 文件

```
cmd/dsh/main.go     从用户目录和当前工作目录调用组装
compose/config.go   严格读取 YAML 装机清单
compose/plugins.go 按名字选择已编进程序的大零件，并排好固定顺序
compose/compose.go  检查目录 + 安装完整插件清单
ui/                 UI 的极小启动口：只规定 Run(ctx)
uiplugins/terminal/ 终端 UI：选 Agent / 选会话 / 发消息 / 显示账本过程
persistence/jsonl/  JSONL Journal 插件：登记 "journal"，同步写盘和烂尾修复
persistence/profilejson/  Agent 档案插件：登记 "agent-profiles"，保存模型、人设、工具名和归档状态
```

用户目录固定为 `~/.harness`：`config.yaml`、`agents/`、`sessions/`。新建目录是 0700，新建配置、档案和账本是 0600；密钥不写进日志或错误。首次缺 `config.yaml` 时只写无密钥模板并退出。YAML 选择档案存储、账本、模型适配器、执行环境、工具插件、Runner 和 UI；`session`、`llm`、`tools`、`agents` 四个固定插座自动安装。配置只能选择已经编进程序的插件，不做动态加载、配置叠加或热更新。工作目录永远由调用方显式传入，不能误用 `~/.harness`。

默认 YAML 选择 `profilejson`、`jsonl`、`deepseek`、`localenv`、`files`、`loop` 和 `terminal`。安装顺序固定为：档案存储 → 账本 → `session.Plugin` → `llm.Plugin` → 模型适配器 → `tools.Plugin` → 成套执行环境 → 工具插件 → `agents.Plugin` → Runner → UI。`main` 组装完成后只领取 `ui` 并调用 `Run`；终端 UI 其余时候只用 `agents` 管会话、订阅 `session/appended` 显示过程，不认识 loop。将来 SQLite 编进程序后可把 `plugins.journal` 改成 `sqlite`；`session` 不能省略，执行环境不能拆开换。

## 真实闭环清单（缺一不算完工）

1. **一个真实模型 adapter**（DeepSeek 或 OpenAI 兼容），走真实 API——不接受只跑 fake；
2. **一个有副作用的工具**（`toolplugins/files` 插件提供 `write_file`，领取 `files` 后登记进 `tools`；std 工具集整体挪到内核完工后，终审修正）；
3. **最小持久化**：`persistence/jsonl.Plugin` 实现 M2 的 **Journal 原子提交接口**（不是挂 Broadcast，禁止事后挂钩；SQLite 是将来的同级插件）；
4. **重启恢复（红队升级）**：`session.Store.Open` 读回指定会话的整本账，`agents.Service.ResumeSession` 从账本封面的 AgentID 领取当前档案后交给 loop 恢复；不只 kill——在**每个提交点前后**强杀 + Journal 故障注入（短写/坏尾）；恢复后：待办找回、坏尾只修未提交的那条、有 start 无 result 的调用进入待裁决而非自动重跑。当前 `loop/crash_recovery_test.go` 已用真实 JSONL + 子进程 `SIGKILL` 覆盖未领消息、模型请求窗口、工具未开跑、工具已开跑和坏尾；`persistence/jsonl` 另有短写故障注入。新增提交点时必须补相应强杀场景；
5. **取消**：流式中断、已收前缀入账、未跑工具补 skipped；
6. **完整关闭**：Ctrl-C / Close() → 落盘 flush、清理子进程、幂等可重入；
7. **终端 UI（已实现）**：菜单选或新建 Agent，手动输入全局唯一会话名，发消息 / 取消 / 看历史；逐字和工具过程从账本事件显示，慢输出不能堵住记账；
8. **--dump-config（已实现）** 只读并校验当前 YAML 后输出；导出 → 再导入可得到等价组装。
