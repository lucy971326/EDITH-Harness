# M6 计划书 —— cmd/dsh：组装 + 真实闭环冒烟

> 状态：已定稿（补齐于外部审核——此前此里程碑缺失计划书）。

## 职责（一句话）

**把 M1-M5 的零件组装成一个能跑的真程序，并用真实世界完成最终验收。**

## 文件

```
cmd/dsh/main.go     装配：建 App → 按序装插件 → 中途失败逆序回滚 → 跑
compose/config.go   配置结构 + 按 id 整体替换 + --dump-config
persistence/jsonl/  JSONL Journal 插件：登记 "journal"，同步写盘和烂尾修复
persistence/profilejson/  Agent 档案插件：登记 "agent-profiles"，保存模型、人设、工具名和归档状态
```

安装顺序先固定为：`profilejson.Plugin`（登记 `"agent-profiles"`）→ `jsonl.Plugin`（登记 `"journal"`）→ `session.Plugin`（必装，领取 Journal）→ `llm.Plugin` → `tools.Plugin` → `loop.Plugin`。将来 SQLite 可以分别替换两种持久化插件；session 不能省略。

## 真实闭环清单（缺一不算完工）

1. **一个真实模型 adapter**（DeepSeek 或 OpenAI 兼容），走真实 API——不接受只跑 fake；
2. **一个有副作用的工具**（写文件——一次性烟测工具；std 工具集整体挪到内核完工后，终审修正）；
3. **最小持久化**：`persistence/jsonl.Plugin` 实现 M2 的 **Journal 原子提交接口**（不是挂 Broadcast，禁止事后挂钩；SQLite 是将来的同级插件）；
4. **重启恢复（红队升级）**：`session.Store.Open` 读回指定会话的整本账，`loop.Roster.ResumeSession` 从账本封面的 AgentID 领取当前档案后恢复；不只 kill——在**每个提交点前后**强杀 + Journal 故障注入（短写/坏尾）；恢复后：待办找回、坏尾只修未提交的那条、有 start 无 result 的调用进入待裁决而非自动重跑；
5. **取消**：流式中断、已收前缀入账、未跑工具补 skipped；
6. **完整关闭**：Ctrl-C / Close() → 落盘 flush、清理子进程、幂等可重入；
7. **--dump-config** 输出可 roundtrip（导出 → 再导入 → 等价组装）。

## 全程纪律（六里程碑共用）

`go test -race` 常开；每包一个公开构造；无包级全局变量；文件按 module/capability/types/state 四类分；插件不持有整个 App；**组装禁止拆开换执行环境**（files/process 必须同源，终审修正）。
