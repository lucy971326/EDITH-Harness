# M5 计划书 —— 三个执行接口（大白话版）

> 定型"工具的手和脚"。规矩：**接口 + 本地实现一起交付，被真实进程敲打过才算数**——纸上设计的接口不算数。
>
> 状态：**已完成**。

## 三个接口，一句话一个

```
files.Store      读 / 写 / 列文件

process.Spawner  长工：起一个进程，跟它持续对话、发信号、管它的子进程
                 （LSP、终端、编辑器协议都要这种）

shell.Runner     小时工：跑一条命令 → 等它完 → 拿输出
                 （站在 process 肩上，只是个便利封装）
```

为什么分三个不合一：LSP 要的是"雇住家保姆"（长期对话），bash 要的是"打车"（一次一结）——用打车软件雇保姆必返工。

**成对交付（终审）**：一个执行环境插件必须同时登记 files + process（+shell）——禁止 files 用本地、process 用沙箱的拆开换法，否则 write_file 写完 bash 读不到。

**Close 收进程树（终审）**：Spawner 跟踪活进程，App 关闭时杀整个进程组。

## M5 交付什么

```
接口定义 × 3        files / process / shell
本地实现 × 3        真进程、真文件，不是假的
行为测试            用取消、超时、输出截断、子进程退出、关 stdin 敲打接口
```

## 实际落地

```
workspace/files/store.go      Store 接口 + Get(app)
workspace/process/types.go    Spawner / Handle / Command 接口 + Get(app)
workspace/shell/runner.go     站在任意 Spawner 上的通用一次性命令
localenv/files.go             files.Store 的本地实现
localenv/process.go           process.Spawner 的本地实现 + 进程组收摊
localenv/plugin.go            一次登记 files + process + shell
```

`localenv.Plugin` 只收两个配置：共用根目录和 shell 输出上限。files 写完的文件，shell 必须在同一个目录看得见。

**目录规矩**：`workspace/files` / `workspace/process` / `workspace/shell` 是一组工作空间能力；凡是直接碰本地磁盘和本地进程的代码，全放在顶层插件 `localenv`。本地构造不对外公开，官方本地环境只能成套安装。

## 这一版故意很简单

- files 只有读、写、列；写入时顺手创建父目录。
- process 只有启动、三条标准管道、信号、等待和关闭。
- shell 不发明新执行器；就是 `Spawn → 关 stdin → 收输出 → Wait`。
- 取消和超时都用 `context.Context`，不再造一套计时器。
- stdout/stderr 默认各保留 64 KiB；超出后继续排空管道，但不再占内存。
- 本地根目录是工作范围，**不是安全沙箱**；当前进程组实现面向 macOS/Linux。
- 不做 PTY、进程池、远程执行、资源配额、虚拟文件系统；这些等真的第二执行后端来了再说。

## 一句话立场

真实实现参与过、测试敲打过，接口才算**定型**；但在第二个执行后端（沙箱或 ACP）接入之前，**不承诺永不变**——真世界会反向修改接口。
