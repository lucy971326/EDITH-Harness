# M2 计划书 —— session 包（账本）

> 状态：已定稿（经第一性原理评审：砍掉 Fork、合并有效名单、明确记账判据；黑话已清理）。
> 本文是施工依据，改本文 = 改设计。

## 职责（一句话）

**记住发生过的一切，并让所有人从同一份记录里各取所需。**

M2 不懂 agent 知识——不知道"模型"是什么、不知道谁在记账。它是一本规矩很硬的账本。

## 不做什么（边界）

- ❌ 不管谁记账——**每种事件只归一家记**：tools 的事（tool/call、tool/start、tool/result）只有 tools 能记，loop 的事（投递/领出/消息/流式片段/快照/轮/步）只有 loop 能记。别人想代笔？API 根本不给口子
- ❌ 不管压缩策略——何时压、摘要写什么，是将来的压缩插件的事；M2 只认识 `Replaces` 标记
- ❌ 不管存到哪——一行一条 JSON 的文本文件、SQLite 是将来的插件；M2 只保证"存进去什么样，读出来还什么样"
- ❌ 不管人看的排版——那是 UI 的事；本包的翻译是机器对机器
- ❌ **不做 Fork**（评审砍掉）——`Create(seed)` 这个底子保留，Fork 只是它的组合用法，需要时再加（纯增量）
- ❌ 不允许省略 session 插件——它紧跟 Journal 插件安装；插件化不等于可选，"模型看到的每个字必须账上有"这条命根由它扛。Journal 实现可以替换

## 核心判据：什么才记账

> **要"复活"的才记：模型看到的一切（铁律）+ 重启后还要在的东西。**
> 过眼云烟不记：缓存的视频帧、解析树、UI 刷新、中间变量。

## 四个功能

### ① 记账（规矩极硬）

```go
type Event struct {
    Kind          string          // 事的种类："user/message" / "tool/call" ...
    Seq           int             // 第几笔，= 账的长度，必须连续（1,2,3...不许跳）
    Time          int64
    Data          json.RawMessage // 记账时校验 + 深拷贝（记完就锁死，改原结构不影响账）
    Replaces      []int           // 摘要专用："我取代了这几笔"——压缩全靠它
    SkipIfUnknown bool            // 写这笔的插件将来没了：true=读到我就跳过
                                  // false=整本账拒读（宁严勿猜）
}

func (s *Session) AppendEvent(kind, data) Event   // 插件自定义种类走这里
```

三条铁律：**只增不改、编号连续、记账时验**（非法 JSON 当场报错，不留给硬盘）。

记账流程（一步不成功就当没记过）：

```
拿编号 → 验内容 → 写进文件 → 写进内存 → 通知大家
```

一本账同一时刻只有一笔在写，排队来，不许两笔同时。

**写文件（Journal）的规矩——"要么整条，要么没有"：**

- 记账成功 = 这笔账真到硬盘了（关键事件写完立刻 fsync，不是躺在系统缓存里装死）；
- 记账失败 = 文件里**不许留半行**。实现：写之前记下位置，认认真真写完整条，失败就退回写之前的位置；
- 重启读账：每笔都带编号，挨个检查连续性；**只允许扔掉"确定没写完"的最后一行烂尾**，中间坏了就拒绝读这本账；
- 什么时候必须立刻落盘：用户消息、收件箱、tool/start、tool/result。流式片段（chunk，模型吐的字）可以攒一批再写，但取消时已收到的前缀必须在盘上；崩溃丢了当前批没写的尾巴可接受（关键事件没有这个宽限）；
- **留了"把攒着的立刻写完"的按钮（Flush）**：调模型、执行工具这些危险动作之前必须先按它——万一断电，账上至少知道刚才断在哪（对照 dsh 补的缺口）。

**内核事件的专用记账方法**：tool/call、tool/result、消息、chunk、轮/步这些**不走**上面那个公开的 `AppendEvent`——session 给 tools 和 loop 各发一套**专用方法**（参数是具体类型，比如 `记工具调用(调用单)`，塞不进乱七八糟的东西）。插件自定义的事件种类才走 `AppendEvent`。"每种事件只归一家记"靠 API 形状强制，不靠文档自觉。

**压缩藏在 `Replaces` 里**：摘要事件声明"我取代了第几笔到第几笔"，旧账一字不动；摘要里顺手记下**哪个模型写的、花了多少 token**——将来排查"这份摘要谁写的"有答案。

### ② 算历史（同一本账，两种读法）

```go
func (s *Session) ModelHistory() []Message  // 模型视角：被摘要收编的不算
func (s *Session) Events() []Event          // 全量视角：人 / 审计 / 回放
```

内部一张**有效名单**（哪些编号还没被摘要取代）+ 算过的存着不重算（有新的取代才全部重算）。

**哪些事件会变成模型的消息（默认：不会）**：

- 每种事件在自己的格式说明里声明"我变成一条消息 / 我不进模型历史"，**默认不进**；
- 模型一段话说完记一笔**定稿（assistant/final）**：收编它引用的那些 chunk，带上用量和是否被打断——"这轮花了多少钱""这句话是不是半句"账上有据可查；没来得及定稿的（崩溃、打断异常），chunk 前缀照样折叠成一条兜底；
- 连续的 chunk 折叠成一条完整的助手消息；
- 收件箱投递、请求快照、轮/步标记只进 `Events()`，模型看不见它们；
- **被打断的回复只留一条**：打断消息就是那批 chunk 的折叠结果，不许既折叠又另写一条（模型会看见两段重复的话）；
- 请求快照是"当年发给模型的那份"的存档，单独看，不算模型历史。

### ③ 翻译与版本（祖传账本的规矩）

- 每种事件一份**格式说明**（结构体 ↔ JSON 互相怎么转，存进去什么样读出来还什么样）；
- **不认识的事件种类**：默认整本账拒读（宁严勿猜）；带 `SkipIfUnknown` 标记的 → 保留并跳过；
- 账本封面带**格式版本**和所属 Agent：账本号只代表一段会话，`AgentID` 代表长期 Agent；会话创建时还记下档案版本作历史标记。当前格式为 v2，旧 v1 没有 AgentID，明确拒绝打开并提示迁移；
- 事件种类对插件开放：插件注册自家种类 + 格式说明即可记账（todo、goal、视频摘要……）。

### ④ 名册（管家）

```go
type Plugin struct{}

func (Plugin) Start(app *core.App) error  // 领取 "journal"，登记 "sessions"
func Get(app *core.App) (*Store, error)   // 从 App 取账本管家

func (st *Store) Create(sessionID, agentID string, profileRevision int, seed ...Event) *Session
func (st *Store) Open(id string) *Session                   // 打开已有账；只重建内存，不重写旧账
func (st *Store) Get(id string) *Session
func (st *Store) Release(id string) error                   // 写穿并忘掉内存态，之后可再次 Open
```

持久化插件先把 Journal 登记为 `"journal"`，`session.Plugin` 再领取它、建 Store 并登记 `"sessions"`。JSONL / SQLite 是二选一的同级持久化插件；session 不能因为插件化就被省略。

## 文件与体量

```
session/
  journal.go   落盘接口（"要么整条要么没有"+ Flush 立刻写完；内存假实现给单测，真文件版 M6 接）
  store.go     管家：Create/Open/Get + 旧账重放；NewStore(journal, broadcaster) 两个都从外面注入
  session.go   账本体：AppendEvent / ModelHistory / Events
  plugin.go    必装插件：领取 Journal、创建并登记 Store，提供 Get
  codec.go     格式说明：结构体 ↔ JSON + 不认识的事件怎么办 + 版本
  history.go   算历史 + 有效名单 + 结果缓存（名单是算历史的内部状态，不独立成文件）
  types.go     数据格式：Event / 封面 / 各事件的字段
```

七个文件，估计 ~400 行。

## 裁决记录（为什么是这样）

| 问题 | 裁决 | 理由 |
|---|---|---|
| 记什么 | 要复活的才记 | "模型看到的每个字必须账上有"是铁律；内部状态记账是浪费 |
| session 是插件吗 | 是必装插件，不能省略 | 规矩的载体；它紧跟唯一的 Journal 插件安装。Journal 可以替换，拔掉整个 session 则崩溃恢复/回放全塌 |
| 翻译给谁服务 | 机器对机器 | 人看的排版是 UI 的事；格式说明的职责是存取无损 + 版本 |
| Fork 要不要 | 砍 | Create(seed) 已覆盖其本质；Fork 是便利函数，需要时纯增量加 |
| 有效名单独立吗 | 并入算历史 | 它是算历史的内部状态，不是独立能力（评审质疑成立） |
| 为什么必须 JSON | 无损 + 可版本化 | 结构体直接存绑死了内存布局；JSON 让旧账永远可读 |
| Session 依赖 core 吗 | 账本对象只依赖 Broadcaster；`session.Plugin` 依赖 `core.App` | 账本本体仍可独立测试；插件统一从 App 登记 "sessions"，消费者通过 `session.Get` 取 |
| Message 属于谁 | 中立词汇包 chat | session 与 llm 共用公共词汇，避免 M2 借用 M3 的类型 |

## 验收测试（写代码前先写这些）

1. 记账规矩：非法 JSON / 编号跳了 / Replaces 指向不存在的编号 → 当场报错；
2. **重放一模一样**：`Create(seed)` 重建 → `ModelHistory()` 与原账逐字节一致（做成可复用测试工具）；
3. 压缩：写入带 Replaces 的摘要后，`ModelHistory` 跳过被收编的段、`Events` 全量不变；
4. 不认识的事件：必需的 → 拒绝重建；带 SkipIfUnknown 的 → 保留且跳过；
5. 记一笔播一次：每次 Append 后 M1 的 Broadcast 收到一条，**且广播里带着账本号**（开多本账时界面分得清哪笔来自哪本）；
6. 缓存正确：有取代 → 重算；没取代 → 直接追加不重算；
7. 深拷贝验证：记账后改传入的原结构体，账内容不变；
8. **破坏实验六种**：只写进半行、磁盘满、失败后再试一次、写一半断电留烂尾行、两边同时记账、坏了重开——任何失败后文件里无半行污染，重开只扔"确定没写完"的最后一行；
9. 声明不进模型历史的种类，`ModelHistory` 里没有；连续 chunk 折叠成一条；定稿收编素材后只剩定稿文本、被打断的半句只落一条；
10. 全程 `go test -race` 通过。

## 给 M3/M4 的接口预留

- M3（tools）：拿专用记账方法记 tool/call、tool/start、tool/result（格式说明归 session，tools 不自己注册）；
- M4（loop）：拿专用记账方法记轮/步/消息/chunk/投递/领出/快照，读 `ModelHistory` 用；
- 未来插件：注册自家事件种类记账；压缩插件只写带 `Replaces` 的摘要事件。
