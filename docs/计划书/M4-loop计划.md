# M4 计划书 —— loop（大白话版）

> 搬运工：不知疲倦地重复"领消息 → 问模型 → 调工具 → 再问"，直到没活。
> 它自己没有主见——拿什么、调什么、准不准，全是别人决定的。

## 核心裁决：UI 跟 Agent 说话，不跟 loop 说话

```
UI 插件 → 能力表["agents"] 名册 → 按 id 领一个 Agent 门面
                                        │ 门面背后（外人看不见）
                                        ▼
                                   Driver（loop 造的）
                                   ├ 收件箱（私有）
                                   ├ 一个 goroutine
                                   └ 状态：闲/忙
```

换掉整个 loop，UI 毫无感知——就像客人按门铃，不用关心门后是人是狗 😄

## 全景图

```
   SubmitFollowup（开新轮）/ Steering（中途捎话）/ Inject（塞小抄不吵醒）
        ↓
   收件箱：两条待办队列（开新轮 / 中途话）+ 一个小抄盒
   （三条都是投递先落账再收下——崩溃不丢消息；
     小抄盒不算待办：不响铃、不唤醒、不变用户消息）
        ↓ 唤醒
   ┌──────────── 一个循环 ────────────┐
   │  领消息 → 检查站 → 拍请求快照 → 问模型     │
   │                        ↓（逐字记账）       │
   │  没活了 ← 还有工具要跑？→ 调工具（过 M3 流水线）│
   └──────────────────────────────────┘
        ↓
   等待空闲（WaitIdle）
```

## 三条规矩

- **消息进上下文必过账本**：领出 → 记账 → 投影，绝不直接塞给模型；
- **边发生边记账**：模型每吐一字记一笔（UI 逐字显示白送）；
- **被拒的尝试也留痕**：检查站拒了这批消息，也关一个空轮记账。

名词解释（两个就够）：
- **轮**：把一批输入从头干到尾；
- **步**：问一次模型 + 它要的工具调用（一轮含多步）；
- **请求快照**：每次问模型前，把"最终发了什么（消息/系统提示词/工具清单/参数）"记一笔——将来重放才是当年真发出去的东西（快照不进模型历史，是独立投影）。

**忙时碰撞规则（终审）**：忙时 Steering 进当前轮下一步；Followup 排队，本轮正常结束后才开新轮；Inject 立即入账、不唤醒、不占待办队列。

**投递与领出是两条账（五轮缺件B）**：入队事件与领出事件分开落账；**领出才变成进模型的 user/message**；恢复只重放未领出的投递（否则崩溃在消费标记落盘前 → 用户消息双份）。Inject 同理：入队不投影，被某步领出后才进上下文。

**裁决出口（五轮缺件A）**：待裁决态的出路只有一条——追加裁决事件并经 tools 窄写入口落成 `tool/result`（成功/失败/跳过），loop 才准继续；禁止"无 result 继续"（否则模型看见无结果调用会再调一次 → 邮件双发）。

**已裁决（路线 2）：重启后碰到"工具干到一半断了"，自动补一条"结果不明"的账**。恢复时发现有 start 无 result 的调用，loop 自动经 tools 记一笔 tool/result{status:"unknown"，正文写给模型："刚才这个操作断在半路，结果不明，你自己决定要不要重做"}——模型自己判断重试还是问人。不赌（不自动重跑），也不卡死等人。高危工具（删库/转账类）要强制人工 = 可选审批插件（前置链说 ask），不是内核行为。

## 验收（最硬的四条）

1. 三种塞消息方式语义正确（小抄不吵醒、中途话下一步生效）；
2. 崩溃重启后：按《失败边界与恢复状态机》重放重建——待办找回、轮次状态还原；**存在"有 start 无 result"的调用时，自动补 tool/result{status:unknown}（正文=写给模型的决策指引）后正常待命**；有 chunk 无定稿的，自动补被打断的定稿；
3. 取消：模型已吐的字固化成被打断的定稿入账；**没开跑的**经 tools 落 `tool/result{status:skipped}`，**已开跑的**保持无结果（结果不明，恢复时自动补账）；
4. **模型收到的每个字节都能从账本重建**。
