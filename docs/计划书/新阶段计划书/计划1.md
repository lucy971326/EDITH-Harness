# Project → Session → Agent 模式：内核重构计划

> 完成状态：已实现。新代码通过 `go test -race ./...`、`go vet ./...` 和 `git diff --check`。本机配置已升到 v2，旧 Agent 档案和 v2 Session 已移出运行目录。

## 核心模型

```text
Project：一个工作目录
  └─ Session：一段独立对话
       ├─ 锁定 Agent 模式版本
       └─ Runtime Agent：负责实际运行，ID = Session ID
```

借鉴 DSH：

- Project 使用稳定 ID 和规范化目录。
- Agent 模式与运行中的 Agent 分离。
- 每个 Session 拥有自己的运行环境。
- Session 锁定模式版本，历史行为不会随模式修改而变化。

不照搬 DSH 的动态挂载、热切换、复杂 KV 事务和空会话状态机。

## 关键改动

### 1. 新增 Projects 与 Presets

新增 `projects` 插件：

- `Create / Get / List / Rename / Archive / Restore`
- 保存项目 ID、名称、根目录、上次使用的模式。
- `ListSessions(projectID)` 从 Session 封面筛选。
- 同一个规范化目录只能登记一次。
- 不自动把启动目录加入项目。

新增 `presets` 插件：

- 接管现在的 `AgentProfile`。
- 对外称“Agent 模式”。
- 每次修改产生不可变的新版本。
- 旧 Session 继续读取指定旧版本。
- 已归档模式不能开新会话，但旧会话仍能恢复。

### 2. Session 改为真正的归属中心

账本封面升级为 v3：

```go
type Header struct {
    FormatVersion  int
    ID             string // 自动生成，界面不展示
    Title          string // 可重复的会话标题
    CreatedAt      time.Time
    ProjectID      string
    ProjectRoot    string
    PresetID       string
    PresetRevision int
}
```

- 删除 `AgentID` 和旧 `ProfileRevision` 语义。
- 不同项目允许出现同名会话。
- 项目根目录本轮保持不可修改；移动目录视为新项目。
- 新会话页面只是 UI 草稿，第一次发送消息时才创建真正 Session。
- 草稿可切换模式；发送后模式锁定。
- 新项目没有历史选择时必须手动选模式；之后默认显示该项目上次成功发送时使用的模式。

### 3. Agents 只管理运行时

`agents` 不再保存档案，也不再让一个长期 Agent 拥有多段会话。

```go
type RunInput struct {
    SessionID string
    Project   projects.Project
    Preset    presets.Revision
    Scope     *core.App
    Book      *session.Session
}
```

`agents.Service` 只保留：

- 新开、恢复、获取、关闭运行中会话。
- 登记可替换的 `Runner`。
- 管理 Session 专属作用域和清理过程。

`loop` 继续实现 `Runner`，但改为读取 Session 锁定的模式版本。运行时 Agent ID 统一等于 Session ID。

### 4. 每个 Session 拥有独立执行环境

把 `localenv` 从“启动时绑定一个目录”改成环境提供者：

```go
type Provider interface {
    Mount(scope *core.App, root string) error
}
```

启动 Session 时：

```text
读取 ProjectRoot
→ 创建 Session 子作用域
→ localenv 把 files/process/shell 挂到该作用域
→ 按 Preset 工具白名单启动 loop
```

工具执行接口增加当前作用域参数；文件工具执行时从该作用域领取 `files.Store`，不再在插件启动时捕获全局目录。

这样同时运行项目 A、B 时，两个 `write_file` 只会写入各自项目。

## 持久化与组装

- 新增 `projectjson` 和 `presetjson` 存储插件。
- 模式旧版本永久保留，供历史 Session 恢复。
- YAML 升级为 version 2：

```yaml
plugins:
  project_store: projectjson
  preset_store: presetjson
  journal: jsonl
  environment: localenv
```

- `compose.Open` 改为只接收 `home`，不再接收启动工作目录。
- 组装顺序固定为：

```text
项目存储 → 模式存储 → 账本 → session
→ llm / adapters → tools → environment / tool plugins
→ projects → presets → agents → runner → UI
```

- 旧 Bubble Tea TUI 源码移入 `reference/terminal-v1`，不再参与编译。
- 保留一个明确提示“TUI 已暂停，下一阶段接 Web”的终端入口。
- 不触碰用户已有 `.gitignore` 修改。

## 验收测试

- 两个项目可以拥有同名 Session，内部 ID 不同。
- Session 恢复后仍使用创建时锁定的模式版本。
- 修改或归档模式不会改变旧 Session。
- 两个项目并行调用文件工具，文件不会写错目录。
- 工具白名单按 Session 隔离。
- 环境挂载失败时，Session 不发布且作用域完整关闭。
- 假 Runner 测试证明 `agents` 不依赖具体 `loop`。
- Project 归档不删除目录和历史账本。
- 更新架构 HTML、交接文档和 `0825mission.md`，画清 Project、Preset、Session、Runtime Agent 的关系。
