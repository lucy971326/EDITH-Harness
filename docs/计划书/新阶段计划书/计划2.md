# 计划2：Web UI 实现

> 状态：第二版已实现并通过 `go test -race ./...` 与 `go vet ./...`。下面保留它的产品边界，后续功能仍按此收敛。

## 总体方案

新增 `uiplugins/web`，使用 templ + HTMX + Tailwind 构建本地网页工作台：

```text
左侧：Project → Session 树
中间：聊天、工具过程、输入框
左下：设置、主题
```

新会话直接进入空白草稿，不弹窗；第一次发送时自动用首句话生成标题、创建 Session 并锁定 Preset。模式锁定后不可换；模型在输入框独立选择，可在空闲时切换。

## 关键实现

- Web 插件领取 `projects`、`presets`、`sessions`、`agents`、`llm`、`tools`，不调用 loop。
- 给 `session.Store` 增加只读历史入口；点开旧会话只读账本，再次发送时才恢复 Agent 运行环境。
- 给 `agents.Service` 增加“获取或恢复会话”的统一入口，避免 Web 自己判断运行状态。
- 首屏从账本生成聊天视图；运行中监听 `session/appended`，通过 SSE 通知 HTMX 局部刷新。事件通知不得阻塞记账。
- 聊天投影展示用户消息、流式回复、最终回复和工具状态；投递但尚未处理的消息显示“已排队”。
- 首次消息成功入队后调用 `projects.RememberPreset` 与 `projects.RememberModel`；记忆失败只提示，不撤销已经发送的消息。
- `model/selected` 是账本内核事件：首次发送与每次模型切换都写入；恢复会话取最后一笔。
- Agent 模式管理使用现有版本机制：创建、修改、归档；它只保存提示词和工具清单。`llm` 给聊天输入框提供“已安装服务商 → 模型 → 思考档位”。
- 添加项目时，Web 请求本机 Go 后端弹 macOS 原生目录选择框；选中的目录名自动成为项目名。
- 服务只监听 `127.0.0.1:8080`，静态资源嵌入二进制；启动后打印访问地址。POST 请求校验同源。
- `compose` 支持 `ui: web` 并设为新模板默认值；保留暂停中的 `terminal` 选项。

## 页面范围

第一版完成：

- 添加和选择项目；侧栏永久保留“新会话”和“添加项目”。
- 查看、新建和恢复会话。
- 创建、修改和归档 Agent 模式。
- 首次发送前选择模式与模型，发送后锁定模式；模型仍可在空闲时切换。
- 发送、排队和取消消息。
- Markdown 回复和可展开的工具过程。
- 浅色主界面与本地保存的主题选择。

暂不实现附件、轨迹页、会话分页、复杂统计、模型密钥编辑和通用 UI 扩展系统。

## 测试

- 空草稿不产生账本；首次发送创建并锁定正确的 Preset 版本。
- 浏览旧会话不会启动 Agent；再次发送才恢复。
- 历史账本正确生成聊天、排队消息、流式内容和工具状态。
- SSE 只刷新对应 Session，慢客户端不会阻塞 `session/appended`。
- 项目与 Agent 模式页面覆盖正常创建、修改及错误提示。
- 选择项目会登记所选目录及其目录名；取消选择不创建项目。
- Web 只能从本机访问，跨源写请求被拒绝，关闭程序时 HTTP 与运行中会话正常收摊。
- 执行 `go test -race ./...`、`go vet ./...`、`git diff --check`，再手工完成一次真实 DeepSeek 对话冒烟测试。
