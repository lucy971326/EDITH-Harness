# Commands V1 —— 拍板用

同意从第 1 条开始。它是第一个「人直接调用」的插座，不碰 Prompt、不碰孩子、不碰配置。Settings / Credentials 是另一条，这次不做。

## 它是什么

Command 是人喊的。Tool 是模型喊的。聊天是人跟模型说话。

```text
人打 /xxx
    │
    ▼
commands 插座     登记、解析、分发
    │
    ├─ 认识 → 那个插件自己干活
    └─ 不认识 → 报错，绝不进模型
```

三条路永远分开：

```text
/plan              → commands      不耗 token
ls 这个目录        → 聊天 / loop   耗 token
模型调 files.read  → tools 流水线  耗 token
```

## 三层（照抄我们自己的 tools 形状）

```text
commands 插件        提供空登记处
能力插件             Start 里 Register 自己的命令
Web                  只 List + Execute，不写 if /movie
```

`commands` 不认识网页、不认识 templ、不跑模型。需要模型时，填插座的人自己去找 `agents`。

## 铁律

1. 提交行去掉首尾空白后以 `/` 开头 = 命令平面。格式错、名字不认识，都报错，不准变成聊天。
2. 名字：小写 ASCII `a-z` 开头，后接 `a-z0-9_-`。参数整段留给那条命令自己解析。
3. 结果只给人看，不进账本，不进模型历史。命令要改领域状态，走那个领域自己的 API 记账。
4. 草稿也能跑（不必先有 Session）。命令自己需要会话时，自己去 `agents` 拿；没有就它自己报错。
5. 取消跟模型取消不是一回事：HTTP 请求停了就停等；命令自己配合 `ctx`。
6. 全部用 `/`。用元数据分组区分核心/插件，不另造 `$`。

## 抄竞品什么，不抄什么

抄：独立插座、插件登记、未知 `/` 不进模型、handler 显式调 Agent、结果不进模型历史。

不抄：

- 按 Agent 遮蔽的两层命令表（我们没有热重载）
- `command/run` / `command/done` 记账（轨迹阶段再说）
- 客户端目录缓存、模糊搜索引擎、弹窗框架
- 图片附件、参数 schema、表单

我们是静态编译 + 服务端画页：每次 `/` 现问 List 就够。

## V1 做什么

```text
commands 包
  Register / List / Find / Execute
  返回 unregister

compose 固定装上它（在 UI 之前）

Web
  发送以 / 开头 → Execute，绝不 SubmitFollowup
  输入框打 / → 弹出名单（一个菜单，不是每条命令自己做 UI）
  结果用一次性提示，刷新可以消失
```

V1 **没有**业务命令。插座的第一个真实消费方是 Web 拦截。测试里登记假命令证明能跑。`/help` 不是必须的：名单就是 help。

V1 不做：作用域命令、账本事件、参数表单、命令生命周期表、每条命令的网页伙伴。

## 请拍这三板

1. **结果不进账本。** 刷新后提示消失。以后轨迹要看见命令，再加 log-only 事件。
2. **V1 就做 `/` 菜单。** 这是命令消费方自己的界面，不是第 3 条的通用挖洞。
3. **V1 不发明第一条业务命令。** `/plan` `/compact` 等它们的领域插座先出现。

这三板你点头，下一刀就是按这个形状开工。
